## Finding 1 — `s155-D1`: the shape is ruled, the values are not, and the gap is deliberate

Dave settled the question three sessions of record had carried as unanswered, in one sentence:
*"green is the same as red, this is decided already, dark and light in exactly the same contexts."*

What that rules is a **structure**: green/success ink takes a background-keyed fork identical to
`s151-D1`'s two-red law — one dark value on white for text and atoms, one light value everywhere
else, with the same riders (coloured text only on monetary values carrying a symbol; labels always
default ink; the governing standard is *"colour alone must not carry meaning"*, not a blanket 4.5:1).

What it does **not** rule is the two hex values, and this is the part most likely to be got wrong by
a later reader. No green pair has ever been named by anyone. The red pair (`#DA1A00` / `#F6604C`) is
sitting right there and looks like a derivation waiting to happen — lighten it, rotate the hue, done.
That would be exactly the laundering [[feedback-dont-launder-a-premise-into-a-ruling]] names: a
premise (*"green mirrors red structurally"*) turned into a value Dave never uttered, inscribed with
the authority of a ruling. The values are his, and the agreed delivery shape is a live picker he can
rule off in one message [[feedback-live-controller]].

Mechanically: `knowledge/_rulings.json` reached **116 entries** by a 19-line **textual splice**. The
file carries mixed `\u` escaping, so a load-and-dump round-trip is not byte-identical and a serializer
would silently reformat the whole file [[serializer-defaults-reformat-the-file]]. Priors were asserted
parse-equal before and after. `_FUTURE-STATE.md`'s floated entry was marked **PROMOTED #155 by
addition** — the floated text stands as provenance, closed by promotion, never rewritten.

## Finding 3 — the proof finally has a runner, and half of it is deliberately advisory

#153 measured the sharp version of [[instrument-without-a-consumer]]: the MARK-leg **fix** had a
consumer (`_build_all.py` runs the gate), but the **proof** — the browser-driven selftest arms —
had none, in the sandbox or in CI. #153-A knocked out the sandbox half. Dave ruled the CI half here:
*"keep the ubuntu solution."*

`.github/workflows/gates.yml` gains a second job, `render`, on `ubuntu-latest` — which has root, so
`playwright install --with-deps chromium` needs none of the sandbox lib-farm choreography that cost
#153 an entire session. Two steps, deliberately different tiers:

- `--selftest` is **BLOCKING**. It is the proof; a proof that cannot fail a build is documentation.
- the full sweep is **ADVISORY** (`continue-on-error`), because its exit is **1 today** on the
  known-open Banner 8. Blocking on a declared-open item would paint every unrelated push red, and a
  permanently-red gate is a gate everyone learns to ignore. **When it flips is Dave's**, and the flip
  condition is Banner landing — recorded in the residual so the advisory does not become permanent
  by forgetting.

And the honest residue: `knowledge/_tests/test_gates.py:23`–`:25` still reads *"their un-testedness
in CI is a known gap, not a green light."* That is now false. It was left alone on scope, and named —
a corrected claim with an uncorrected duplicate is precisely [[assertion-propagation-gap]]: the
sentence was true when written, quietly went stale, and nothing chases a claim that never flips a
gate. Declaring it costs a line; not declaring it is how these survive for sixteen months.

## Finding 4 — the session was not the session the record said it was

The window booted on a chain whose NEXT-TITLE read `#154`. `git log` said otherwise: commit
`156d926` is a **#154 that already wrapped** (`s154-D1`, the M8 banner-block roll-legality fix).

The explanation is structural, not clerical. **#154 committed without running the ritual** — no
banner, no `_LIVE-STATE.md` delta, no stratum, no title bump. So its work landed in git while the
record's forward pointer stayed exactly where #153 left it. Anyone reading the chain would have
opened this session as #154 and written a second #154 banner over the top of a live #153 one.

Two consequences, both taken here:

1. the banner/delta/title chain resumes at **#155**, and the wrap's subject was verified against
   `git log` **after** the commit, not assumed [[a skipped wrap makes the chain certify the wrong
   session]];
2. `notes/_GAUGE-LOG.md` gets **`HOLE #154 — …`**, not `ABSENT`. The distinction is #34's and it
   matters: `ABSENT` means *no block was found and whether one ever existed is unknown*; `HOLE` is a
   positive, evidenced claim — that session wrote no stratum, and here is why. We can name the
   session, the commit and the reason, so `HOLE` is the honest marker and `ABSENT` would understate
   what is known.

★ The general form, and it is the one worth carrying: **a fix-only session that skips the ritual does
not merely fail to record itself — it leaves the record actively pointing at a session number that
has already been used.** Repo-state claims get verified against `git log`, never against a banner
[[ritual-output-is-not-evidence]].
