## 1. Why a mutation test that goes RED is a narrowing, not a pass

`s262-D5` says three things about option 3 of the designer opener: the goal is stated once and
**held** for the session, the shape is **confirmed** before building, and progress is **reported
against the goal** rather than against a list of tasks. Nothing tested any of it — the sixth
recorded venue of the fail-open class, carried since #262.

The instrument built here (`knowledge/_bite_goal.py`) does the only honest thing available: it
**cuts the clause out and sees what changes**. `--emit DIR` writes the intact
`apollo-spider/cold-start/COPILOT-BOOT.md`; `--emit DIR --mutate` writes a copy with option 3's
five-line `/goal` span removed and **asserts** the span is gone rather than trusting the edit.
Two Opus lanes, blind to each other and to the repo, each played the assistant from ONE boot
through the same 4-turn scenario. Grading: **INTACT GREEN 2/2 · MUTATED RED 1/2.**

The interesting part is not the RED. It is **which arm went red**, and what the other two proved
about themselves.

- **G2 — hold the goal against a drift — is the clause's, and it is the whole of it.** With the
  clause, T2's *"just build me a transactions list"* was checked against *make rent* **by name**
  and re-shaped into two priced options. Without it, the list was built and the drift was
  absorbed — never named as a drift. That is the mechanism the ruling describes, and it moved
  when the text moved.
- **G1 — confirm before build — is NOT the clause's.** Both T1s end *"Dashboard bento — is that
  right?"*. Rule 7a's bento question fires whether the `/goal` span is present or absent, so the
  arm passes in both directions and **discriminates nothing**. It stays counted because `s262-D5`
  says so; recording that it does not discriminate is what stops a future reader treating a 2/2
  as two pieces of evidence.
- **G3 — report against the goal — cannot be told apart by regex, and the transcripts show why.**
  Intact T4 opens *"Against the goal — … The answer reads at a glance — not yet"*; mutated T4
  opens *"Where we are: 1. Goal stated 2. Page built …"*. Both name the goal. A reader separates
  them in one glance; `GOAL_TERMS` cannot. This is [[no-gate-parses-the-artefact]] arriving in a
  venue we thought was safe — a transcript is text, and we still could not parse the thing that
  matters.

Dave ruled both open questions in two words each. `s265-D1` — *"1. okay make it stand alone"* —
keeps the instrument **out** of `test_gates.py`'s CASES, because the sandbox has no scriptable
driver (`claude -p` returns `terminal_reason: api_error`) and a case that cannot run in one
environment is refused as a gate [[gate-cannot-pass-in-one-environment]]. `s265-D2` — *"2. okay
yes"* — grades G3 **rubric-only**: a reader grades T4, and the regex arm is advisory and never
counted. **Two rulings that both make the instrument smaller and truer.**

What is still open, and is carried: the verdict rests on **one drive per arm**. The two T2s read
like different rules rather than different dice, but that is a reading, and a second pair costs
≈100K sub tokens. And the boot is written for Copilot while both drivers were Opus lanes.

## 2. Why three of four reds were repairable without a single authored word

Four gates were red on a pristine tree at the session's open. Three of the repairs that landed
share one property: **the correct value was already in the repository**, and the lane's job was
to find it rather than to choose it.

- Footer's `provenance.source: "redesign"` was **restored** from `git show 6e6271f`, where the
  file's own pre-#261 value (`gap-report`) still stands.
- Legend's five UNKNOWN "icons" were never icons — they are bar-chart canvases — and the
  `data-bespoke=` reason string that fixes them was **copied byte-for-byte** from the fourteen
  chart snippets that already carry it.
- Lane E's seven missing KG nodes came out of a **clean scratch regeneration's own output**,
  entry for entry, sort order and serialisation verified against the generator's writer by a
  round-trip byte-compare before anything was edited.

The one place a lane refused to repair is the tell. Legend's `context:small-multiples` could not
be registered, because nothing in the corpus derives that id: registering it would have meant
**writing a label and a `sources` list by hand for a node the machinery does not know**. The ref
was moved to the id the repo does derive instead. *The repo determines the id; the lane moves the
pointer.* That refusal is the same instinct as the fourteen integrity errors left standing — each
is a schema decision, and a lane that widens a schema to make a gate green has ruled.

One finding along the way is worth keeping: `footer.meta.json`'s `edges.composes` was an
**invented edge type with no consumer anywhere** — `grep -rn "composes\b" knowledge --include=*.py`
returns only the `$composes` template convention and prose. It was not merely non-validating; it
was **silently invisible to the knowledge graph**. A schema violation announced itself; the
missing edge did not.

## 3. Why the KG generator is now fenced by a measurement rather than by caution

`_validate_kg.py`'s last remaining structural item is the generator freshness arm, and the
obvious repair is "re-run `gen_kg_edges.py`". Lane E priced that instead of assuming it, on a
scratch mirror: a clean regeneration **rewrites eight metas** and **deletes** Filter-toolbar-bar's
`composedOf` / `delegatesTo` / `drivesConsumer` / `$contract` blocks in full (the `s258-D1`
event-and-attribute contract, ~40 lines), Legend's `containedBy` and `governedBy` edges — which
cite `ruling:s151-D1`, `s248-D3`, `s258-D1` — and the tail of Footer's `$note`. The diff is 441
lines and is filed as an asset.

`s245-D7` is the ruled mechanism that exists to stop exactly this, and its carry list reads
`DECLARED_EDGE_TYPES = ("groupsWith",)`. **One name.** Everything else authored into `edges` since
is unprotected by construction.

So the fence in the record is not "be careful with the generator". It is a measured statement
with a receipt: **do not run `gen_kg_edges.py` before Dave rules what carries.** The registries
were advanced by **addition only** for the same reason — a regeneration would remove
`context:page-above-a-table-or-list-items-region`, which `filter-toolbar-bar.meta.json:151`
live-references, so a "tidy" pass would have opened a new red while closing an old one.

There is also a smaller lesson underneath the freshness red itself. The join key that binds a
ruled PROMOTE verdict to its edge is an **exact `$note` prose string**, and #258 rewrote the prose
that note is derived from. The verdict never changed and is still correct; only the key rotted.
A review artefact was made to carry mutable prose as a primary key, and re-keying it would fix
today and guarantee recurrence — the conflated-fix shape [[conflated-fix-guarantees-recurrence]].

## 5. The lock that was never stale

Two sessions of record described a "stale `.git/index.lock`" that could only be moved, never
deleted, with Dave clearing it Mac-side. That diagnosis was wrong about the cause. The Cowork
sandbox was refusing **every unlink on the mount** until `allow_cowork_file_delete` was granted;
git's own lockfiles and its `tmp_obj_*` objects survived each commit not because a process had
died holding one, but because nothing running here could remove any file at all. The permission
was granted mid-session and the condition cleared.

★ The general shape: **a symptom that only ever appears next to one tool gets attributed to that
tool.** The lock was attributed to git for two sessions because git is where it was noticed.
