RULE (Dave 2026-07-17): **every `GOOD-MORNING.md` carries a standing orientation section**, not just the session
handoff. His words: *"add references and pointers to the general context of the entire project … just as we would
orientate a new starter to a project, wider context helps."*

**Structure now in force:**
- **§A · Orientation** — DURABLE, carried forward every session; update only when the project's *shape* changes:
  what Apollo is (retrieval-not-recall; verification=enforcement; "lovable on rails" + the 4 phases) · the three
  libraries as ONE skeleton + modes (mono/UI/SC, and *pro-forma == Apollo mono*) · where things live (repo map with
  what each dir IS) · the one command (`_build_all.py`, 26 gates) · the rules that bite (survey-before-build, type
  composites, real-icons-only + filenames-not-trustworthy, 4px, sentence case, square/roundel, red-once, ATOMISE,
  derivation governance = Dave promotes) · how we work (clean+REVIEW pair, Dave commits via GitHub Desktop,
  exec-summary comms, sandbox renders = layout not brand type, webfont blocker).
- **§B · This session** — what landed.
- **§C · Queue** — numbered, actionable, with an explicit UNCOMMITTED list + the opener line.

**Why:** cold-start context loss caused real waste — T8 rebuilt Tab-bar and Stepper because the session started
from a queue item without the wider picture (see [[feedback-survey-before-build]]). The handoff was tuned for
"what changed", which assumes continuity that a fresh session doesn't have. Orientation is the cheap fix; the
component index + gates are the enforced fix.

**⚠️ §A ERODES — it is the section most at risk, because it's the only one that doesn't change each session.**
On 2026-07-18 a from-scratch rewrite of `GOOD-MORNING.md` cut §A's standing-instruction note down to the two
words "Standing section", dropping both the carry-forward rule and Dave's reason for it. Caught only because
Dave asked *"just double checking the standing instruction for wider project orientation is in there too."*
The instruction had been surviving *only* by being copied forward inside the file it governs — which isn't
survival, it's luck. **A rule that lives only in the artefact it governs dies the first time that artefact is
rewritten.** Now also written into `_RUNBOOK-capture-ritual.md` step 2, so it survives independently of the
file. Same failure family as the `#1A1A1A` rationale (value survived, reason lost) — see [[capture-ritual]].

*(Detail drift: the §A "one command" line above says 26 gates; it is **27** as of 2026-07-18, with the advisory
edge-extremity check. Verify counts against `_build_all.py`, not against this note.)*

Keep §A tight — one page, pointers not prose. It complements [[comms-style-exec-summary]] (front-load) and the
cold-start spine (`GOOG-MORNING → _LIVE-STATE → decision files`).
