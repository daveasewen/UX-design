**Graphify** (OSS `github.com/safishamsi/graphify`, MIT; commercial `graphifylabs.ai`, YC S26, v2.1.0). Turns a folder of code/SQL/docs/PDFs/images into a queryable knowledge graph. Local AST extraction (tree-sitter, ~20–28 langs) + semantic extraction; confidence-tagged edges (`EXTRACTED`/`INFERRED`/`AMBIGUOUS`); Leiden clustering + "god-nodes" (betweenness centrality / blast-radius); **incremental — patches only changed nodes on file change, no re-embed/rebuild** (`graphify watch` → `graph.json` + `GRAPH_REPORT.md`); on-device/air-gapped, optional on-prem Neo4j/Postgres; MCP server exposes `query_graph`, `get_node`, `get_neighbors`, `shortest_path`, `get_pr_impact`. Installs as a Claude Code/Cursor/etc. skill (`/graphify`).

**Verdict for Promenaut:** strong candidate for the **runtime-query + code-ingestion + persistent-memory** layer — best when the **Sutherland React repo** lands. Pilot LOCALLY (`--backend ollama` or on-prem Neo4j) so HSBC proprietary code never leaves the machine (resolves data-residency). It is an *extraction/inference* engine → **complements, does not replace** our hand-curated, schema'd canon (DTCG tokens, compliance rules w/ severity+EN301549, authored anti-patterns — you don't want those inferred). Cautions: early-stage (waitlist, "SOC2-ready" ≠ certified → real security/maturity DD before any HSBC prod dependency); disable the browser-history/meeting-capture features (irrelevant/unwanted for HSBC) — use only the code+docs graph, on-prem.
