# Platform — Web (desktop & responsive)

> Source: create.hsbc — `platforms-and-channels/web.html`. Captured 2026-06-18 for RAG. Summarised. Landing/pointer page; deeper detail on the sub-pages below.

## Purpose

Guidelines to **design and build consistent, HSBC-branded desktop and responsive web experiences**.

## Structure

- **Web foundations** — the overarching aspects of the web experience: **type scale, dark mode, elevation and more**. (Same foundations as `tokens/typography.json`, `guidelines/dark-mode.md`, `guidelines/elevation.md`, applied to web; aligns with the breakpoint/grid work in `tokens/layout.json`.)
- **Campaign landing pages (CLPs)** — pages that sit **between advertising/aggregator pages and existing HSBC product pages, to drive customer conversion**. A web-specific conversion pattern (pairs with the CTA framework in `calls-to-action.md` — prime vs convert-led).
- **Design toolkits** — the **building blocks** for accessible, on-brand web design (the browser side of the HSBC Common Toolkit Figma library already ingested — e.g. Masthead, Pagination, Tooltip, Data tables, the browser-only components).
- **SharePoint accessibility** — techniques so staff creating/maintaining SharePoint content do so accessibly (niche, staff-facing).
- **Legacy standards**.

## How this maps to the system

- Confirms the **browser-only** scoping recorded on several component metas (Pagination, Tooltip, Masthead, Data tables, Links "Text links (browser)").
- Anchors web design to the shared foundations + breakpoint/grid tokens — consistent single token store across app and web.
- Accessibility for web follows the same **WCAG 2.2 AA** bar (see `digital-accessibility-standards.md`).
