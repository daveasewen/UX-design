01

What this is

A governed design-system engine: judgment encoded as data, enforced by executables, operated by whatever agent hosts it.

The repo's one-line self-description holds up against the code. Generation is treated as a commodity; the product is the layer around any generator, in four kinds of asset: canon (DTCG token stores, 38 human-reviewed reference snippets, a generated canon.css composition layer), criteria (per-component meta.json judgment, rubrics, the fixed/flex charter), gates (Python validators run as an 18-step build where a11y, contrast, token fidelity, icon provenance, coverage and integrity block), and runbooks (the method written down for a cold-start agent).

Around the engine sits a second, quieter invention: a project-memory state machine — _LIVE-STATE.md as a supersession ledger (LIVE / DEAD / OPEN / PLANNED), ADRs with a correctness-audit that separates recorded from vouched, tombstone discipline, and an end-of-session capture ritual. This is how a solo, nights-and-weekends project survives its own context loss — and it is your first named spin-off candidate for good reason.

The governing idea that makes this more than "AI + component library" is charter §9: register is not a look, it is a licensed level of inference — sober = retrieve, balanced = extend, expressive = invent — with cardinal curbs (brand colour, type, square corners, a11y floor, safety patterns) that never lift and foundational curbs that release as the ramp climbs. No commercial tool surveyed has an equivalent; the market's ceiling is a binary "strict mode" toggle.

The operating flow, as designed — and where reality currently stops

brief → criteria contract (definition of done, written first) → retrieve + generate N variants across registers in isolated cold passes → blocking gates kill the broken → advisory signals annotate → render + visual QA → one human taste call → winner promoted to canon.

As-built, the chain is real up to the gates. Isolated generation was used for real in the July spreads; the divergence probe ran once as a grep, not the specced tooling; render + visual QA is not owned by the pipeline at all (no Chromium in the loop; every quality verdict in the spreads was a text description); and promotion has run end-to-end only for components, not screens. The conveyor exists; two of its stations are drawn on the floor in chalk.

Architecture — as built, from code

Four asset layers and a build spine. The strength is real; so are the four structural gaps the code exposes.

This section was mapped from the executables, not the prose docs — the repo's ~60 status files disagree with the code often enough that the code is the more reliable record (the build's own docstring still describes 8 steps; the STEPS list has 18).

The as-built engine. Solid black = the enforced spine. Dashed red = governance that exists but sits outside the one-command build, or is named in the charter and not yet built. The layout layer is absent from every box — that absence is the crux of section 04.

What each blocking gate really checks — and what slips through

Snippet gate · the deepest — 7 checksstrongdeclaration-scoped

Token fidelity light+dark against the store, ARIA presence, contrast pairs, all-caps ban, focus-visible, typography rules, copy-lint. The catch: checks 1–3 validate only what the author declared in the snippet's own token-manifest (_validate_snippets.py:120–161). A genuinely low-contrast pairing that was simply never listed in contrastPairs is never computed. The gate verifies stated obligations, not actual accessibility — an honesty system, not an inspection system. (The gate-blindspot lesson on state contrast was exactly this failure shape.)

a11y gate · the shallowest linkweak

Two checks only. Reduced-motion is a substring presence test — a prefers-reduced-motion block that does nothing still passes (_validate_a11y.py:47). Target-size fires only when a rule declares BOTH width and height in px on a selector matching a hardcoded class-name regex (:35, :53–55) — the overwhelmingly common padding-sized button is never checked, and any control class outside the regex is invisible. Context from the field: even axe-core's full ruleset finds ~57% of issues by volume; this gate is far below that. It should not carry the name "a11y gate" with its current scope.

Icon-source gate · byte-level provenancenovel

Every inline SVG path byte-matched (whitespace-normalised) against the 746-glyph library; UNKNOWN fails the build; shape-only icons flagged (_validate_icons.py:34–84). No commercial tool surveyed does this. Two holes: data-bespoke is self-attestation (a hand-drawn icon so marked passes unexamined), and byte-matching can't see a right glyph used at a wrong meaning.

Coverage · integrity · contrast audits · dark-surface · the bookkeeping gatessound

Coverage is name-existence only — every meta has a snippet and vice versa; it does not verify the snippet implements the meta's declared props/states (_validate_coverage.py:52–64, whose docstring still says "32/32"). The contrast audits compute real WCAG ratios from token data — genuinely ahead of tools that only check rendered current-state. Dark-surface catches one defect class (flat-white-in-dark) by category name-matching. Integrity lints the cross-file joins.

The four structural gaps · what the code itself exposesload-bearing

1 · Screen-level governance is out-of-band. _validate_compose.py and _validate_screen.py are not in STEPS; they scan only a hand-curated _fitness-test/*.canon.html glob. An agent's arbitrary generated output is gated only if a human remembers to drop it in the right folder with the right filename — the July restyle proved exactly this (no gate ran until Dave asked "did you put this through the gates?", and the file's name meant the default glob would have missed it anyway).

2 · There is no layout/composition layer to retrieve. Zero .cn-page/.cn-grid/.cn-layout; the charter says so itself at line 34. Canon governs the vocabulary below the component line and is silent above it — the charter's own §1 risk table even names this ("strong below the component line, silent above it").

3 · The KG is an inverted index, not a graph. Self-asserted relatedSC arrays flipped into two lookup tables (_build_compliance_kg.py:61–78); no SC→SC or component→component edges; meta relationships never compiled; nothing verifies a component actually satisfies an SC. Meanwhile retrieval (query.py) is one-hop dict joins with substring name-matching. "Knowledge graph" currently overstates both.

4 · Enforcement covers 12% of the register. 54 of 462 rules block; the advisory tier never blocks by construction (_validate_advisory.py:243); and metas can cite dead tokens forever because meta token refs are prose (19 of 38 components still carry deprecated bindings per the xref index).

Portability — what the GOV.UK second system actually proved · 2-day probegeneraliseswith coupling

The differentiated logic — contrast enforcement, ARIA, focus, retrieval-not-recall — transferred to GOV.UK components with no edits and immediately bit two real issues (GOV.UK's known 1.35:1 yellow-focus failure, and the operator's own v4/v5 recall drift). But the probe also enumerated real single-tenant coupling: HSBC hardcoded in the icon gate, KG builder, token generator and typography; a light/dark mode assumption; Figma-node-shaped identity; no DTCG alias resolution in gates. Portability is proven for the per-component gates, unproven for the system-completeness gates. The hardcoded constants list (RED_HEXES, ACRONYMS, CTRL regex, GOD_BLAST=7, a duplicated 32-name ORDER list in two generators) is the tax to pay when a second tenant arrives for real.

Where the trace itself needs a health warning — five nuances the writeups miss

1 · "Zero cardinal violations" is overstated on two cardinals. The dossier's own rule layer flags square-corner violations in two governed files (partly a heuristic false-positive on the sanctioned round-dot exemption — but that proves square-corners can't be self-certified mechanically), and 2.4.7 focus-visible reads not-honoured in four governed files. Given E0 found the KB has no focus-ring spec at all, that may be a real cardinal a11y gap hiding under a celebratory summary.

2 · Flag-where-silent counts are syntactic. Candidate markers are comment-string matches; E1 already proved a self-report can claim flags that don't exist. Don't read candidate counts as evidence of reasoned derivation.

3 · Two trace outputs at different fidelity coexist (07-07 TRACE.md vs 07-10 entities/dossier). Same files, different instruments — cite the dated one, or a future session will "find" a discrepancy that is just version skew.

4 · Rule-adherence verdicts are heuristics, not the gates. "Retrieve-don't-recall" collapses to one boolean; the "20 rules violated" total includes false positives. Fine for direction, not for a scoreboard.

5 · The tool cannot answer its own framing question. It measures provenance; the complaint is gestalt. "PURE-RETRIEVAL yet flat → points at architecture" is an inference the instrument supports but cannot verify — only the controlled two-pass comparison (never run) can.

Evidence-quality ledger — what is proven vs suggestive

Proven (mechanical, reproducible): colour cardinal holds under governance (0 live hex ×8 files); rigour-tier rule changed retrieval behaviour; layout divergence is real and monotonic; two independent Opus passes caught a genuine contract-data ambiguity; a cold run's self-report can be false.

Suggestive only: "Opus expressive reads bolder" (never rendered); "diagnostic layouts are better" (one human eyeball, no blind comparison, no scoring); "two-pass beats one-pass" (one hand-made artifact, no controlled pair); everything is n=1 screen — payments, explicitly a narrow-road screen. The §9 framing survives; its proven status is rightly still deferred in the audit ledger.

Constrained generation — what the literature says about your architecture · the crux research

Three findings bear directly on the §9 question. (1) Post-hoc rejection is the weakest configuration. The field's hierarchy: constrain during decoding > repair after > reject after. Blocking gates with no repair loop are rejection sampling at N=1. (2) Repair works when feedback is ground truth (Olausson, ICLR 2024: self-repair is often not worth it — except when the critic is a stronger signal such as tests). Your validators are deterministic ground truth; they are the exact ingredient that makes repair loops pay. (3) Rendered-feedback multi-pass beats single-pass on UI specifically (UI2Code^N: 66→74% across 5 rounds). Best-of-N with weak-verifier filtering (Weaver) is the cheap middle path: sample 3–5 expressive candidates, keep what passes most gates, repair the rest.

And the flatness itself has a literature: RLHF measurably reduces output diversity; format constraints degrade some tasks on some models. "Governance tax on creativity" is a documented phenomenon, not an Apollo bug — which is why the answer is architectural (spend the constraint budget in a second pass) rather than motivational (ask the model harder to be exciting).

Layout generation — H3 has published precedent on all three claims · RALF · LayoutRAG · UI grammars · SDUI · A2UI

Decomposed, "a retrievable layout layer (page archetypes as graph nodes)" makes three claims, each separately validated: layout should be an explicit serialized object (LayoutGPT/LayoutNUWA treat layout as code; Stanford's Generative Interfaces pipeline inserts a structured plan stage and wins 84% over chat UI); layouts should be retrieved, not invented (RALF, CVPR 2024 oral: retrieval-conditioning beats pure generation — trained on 3k samples it beat a baseline trained on 7.7k; LayoutRAG halves FID); and the unit should be a semantic archetype (GOV.UK "patterns" and USWDS templates prove the granularity for humans; Airbnb's Ghost SDUI schema — screen = named layout × typed section slots — proves it as a production schema; Google's A2UI ships "agent may only render from a client-owned catalog" as an open protocol).

What does not exist anywhere: semantic page archetypes as graph nodes linked to a governed component canon, retrieved and instantiated under blocking validation. Academia retrieves geometry; industry governs component vocabularies and leaves composition to the model. The synthesis is open ground — with one caution: retrieval helps fidelity, not creativity, so a small archetype library trades flat for repetitive. Seed wide (GOV.UK/USWDS are free and pre-vetted) and let the promote loop grow it.

Knowledge graphs & the compliance KG — import the middle layer · ACT Rules · axe-core · GraphRAG · overlay indexes

The W3C ACT Rules Format 1.1 became a Recommendation in February 2026: every ACT rule carries a machine-readable mapping to WCAG success criteria, atomic/composite typing, and — crucially — "partial testing" semantics that prevent the false claim "passed rule = conformant SC". axe-core publishes rule metadata mapping rules→SC→ACT IDs. This is the SC↔rule half of your compliance KG, standardized and community-maintained: import it rather than hand-typing the 31-entry table. The component↔SC leg — components as first-class nodes with applicable SCs and executable checks — exists nowhere else and is your genuine novelty.

On graph infrastructure: extraction-based GraphRAG is overkill and cost-critiqued at this corpus size; the overlay-index pattern (graph derived from artifacts, disposable, regenerable — exactly your _blast-radius/graph-index instinct and ADR-0003's leading hypothesis) has clearly won over ontology-first for code corpora. Your Phase-3 plan is pointing the right way; the trap to avoid is building a monolith.

Agent memory — the state machine, benchmarked · Graphiti/Zep · AGENTS.md · spec-kit · A-MEM

Your _LIVE-STATE + ADR-0007 + decision-audit stack is a hybrid nobody ships as one product: Graphiti's edge-invalidation semantics + classic ADR supersession + spec-kit's constitution-as-memory, applied to design decisions. As a spin-off thesis, that's defensible. As infrastructure, be honest about scale: at single-designer scale, plain ADR files with supersession front-matter + the _LIVE-STATE index gets ~80% of the value, and Graphiti (Apache-2.0, 27.8k stars, custom entity types) exists if queryability ever matters. Borrow two cheap upgrades: bi-temporality (record when a decision became true in the design AND when the ledger learned it — makes audits reconstructable) and A-MEM-style backlink refresh (when superseding a node, also refresh the summaries of its neighbours — your propagation-gap failures are exactly what this prevents). The industry lesson that validates your whole approach: prose instruction files don't enforce; enforcement belongs in gates. You knew that on day one.

Tokens & a11y tooling — what to adopt, what to keep · DTCG 2025.10 · Style Dictionary v5 · axe · EAA

Tokens: DTCG shipped its first stable version (2025.10) with a Resolver Module draft for modes/theming — check the store against the stable spec, and evaluate Style Dictionary v5 / Terrazzo as the token→CSS transform layer with your Python gates validating their output. The bet on DTCG was right; hand-maintaining the transform now carries drift risk against a stabilized spec. Your token-fidelity blocking gate has no commercial equivalent (Omlet/Luro are analytics, not gates) — that stays bespoke.

A11y: the declared-pairs contrast approach is ahead of shelf tools in one way (it checks hover/pressed from token data at all) and behind in the decisive way (axe-family tools check the rendered DOM, catching undeclared pairs, inheritance, overlays). No mature product automates a full forced-state sweep — but the mechanism exists: Playwright + CDP CSS.forcePseudoState + axe's contrast rule per state is a few hundred lines and would close both the declared-pairs hole and the state blind spot at once. Don't adopt APCA (removed from the WCAG 3 draft; WCAG 3 is 2030+); stay on 2.x ratios. EAA: in force since June 2025, banking explicitly in scope, enforcement so far "guidance first, fines later"; UK domestic law unaffected but EU-facing services in scope — the ADR-0004 follow-up to re-verify the legal position stands, direction unchanged.

What's wrong — the six findings

F1 — The rules under-govern layout — the real gap isn't the pass count · rev 2, reframedcritical

(Rev 1 titled this "the generation shape is the architecture error" and argued single-pass should be considered superseded. Dave's ruling corrects it: single-pass is not the fault — for the factory/floor end it is exactly right, and provenance-perfect. The real gap is what the rules govern.)

The engine's rules govern the vocabulary below the component line thoroughly and are silent above it — layout, composition, page structure. So the generator, single-pass or not, has nothing to retrieve for the dimension that most carries a design; it must invent layout every time, and governed inventions come out flat. The evidence is convergent: the trace measures zero layout retrieval; the library stops at the organism tier (0 templates/shells); the charter admits it at line 34. The fix is to widen what the rules encode — a retrievable layout/library tier, sharper tier definitions, composition licence per band — not to abandon the single pass. A normalise/repair stage (the two-pass) is one option to trial on the ceiling/novel end, where it may help; it is not the headline. What survives untouched and is the moat: the canon, criteria, curbs, gates, and the register vocabulary.

F2 — The engine cannot see. Every real defect was visual; every gate is staticcritical

AGENTS.md principle 8 states it; the July session proved it four times in one sitting (invisible hero number, ungated restyle, 4 real contrast failures behind a green check, a modal keyboard trap). The failure mode lives in the one channel the gates don't measure. Rendering exists in the sandbox (Playwright was proven for snippet PNGs); it has simply never been wired into the loop as an owned stage. Until the pipeline renders and looks, "gates green" will keep manufacturing false confidence — the state-contrast blind spot generalised.

F3 — Declaration-scoped gates verify honesty, not realitystructural

Contrast checks cover only author-declared pairs; ARIA checks only declared strings; coverage checks only name existence; the a11y gate's target-size check fires only on a hardcoded class regex with literal px pairs; screen/compose gates aren't even in the build and scan only a hand-curated glob. The system audits what authors claim, exhaustively — and inspects what artifacts are, barely. The rendered-DOM state sweep (R5) and putting screen gates in the build close most of this.

F4 — "Knowledge graph" oversells two lookup tables; retrieval is grepstructural

The compliance KG is a bipartite index over self-asserted arrays — no verification edges, no component relationships compiled, nothing beyond WCAG. query.py is one-hop joins with substring matching. This matters because the project's next big bets (unified overlay KG, archetype nodes, PM-KG MVP) all assume a graph substrate that doesn't exist yet. The good news: the overlay-index instinct is the industry-validated pattern, the component↔SC leg is real novelty, and the SC↔rule layer can be imported wholesale from W3C ACT/axe-core instead of maintained by hand.

F5 — The self-analysis ratio is becoming its own risktrajectory

The top-churn files are all governance machinery; 56 rewrites of two handoff files; the July-05 session produced an audit of the audit method. Each piece is individually excellent — collectively, the project increasingly reasons about itself instead of shipping screens, and the audit's own recurring finding was "foundations set ahead of completed work." The state machine is also your best spin-off, so this isn't wasted — but cap it: the PM-KG MVP should be the last infra build before D2, and new governance docs should need a kill-something-first rule. The deepest mitigation is external: one colleague using the engine converts self-analysis into feedback.

F6 — Green gates sit on an incomplete, mis-tracked corpus — and the entry points still drifthygiene

Ingestion was never completed (three siloed strands, one narrow graph, 147 deprecated tokens un-retired, 21 legacy files, metas citing purged tokens); the Sutherland manifest sat stale for 18 days saying "blocked" after the blocker cleared; today knowledge/README.md tells a cold start "32 metas / four gates / Sutherland parked" and GOOD-MORNING.md presents the built trace tool as future work. The supersession discipline exists and works when run — the gap is that it isn't yet mechanical (_build_live_state.py and the staleness gate remain unbuilt). Until then the ledger's accuracy is a function of end-of-session willpower, which the burst working pattern regularly exhausts.

The one-sentence critique rev 2: you built a world-class verification layer and an honest memory system, but the rules they enforce under-govern the thing that carries a design — layout — so tune what the rules ask for, give layout a retrievable tier, and trial (don't assume) a normalise/repair stage, and the same assets become the product you set out to build.
