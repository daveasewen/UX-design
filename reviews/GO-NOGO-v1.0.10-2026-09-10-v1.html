The mechanism, fixed

01
A string call is not a node

local_imports() read only ast.Import and ast.ImportFrom nodes. The gate reaches its helper by string, deliberately — so that gate and generator have no import cycle:

knowledge/_validate_receipt.py:635
gen = __import__("gen_provenance_receipt")          # lazy: no cycle at import time

The scan saw nothing, so helper_closure() in build_manifest() never claimed the file, and it never shipped.

Before — _gen_pack_manifest.py:851 (at fee2572~1)

local = {m for m in mods if (m + ".py") in knowledge_files or m in HELPER_HOMES}

After — _gen_pack_manifest.py:870, :913

def string_call_imports(tree):
    """Module names named as a string LITERAL to __import__() / importlib.import_module()."""
    …

local |= {m for m in string_call_imports(t)
          if (m + ".py") in knowledge_files or m in HELPER_HOMES}

Why here and not in HELPER_HOMES. That table is a typed seed whose own comment says it must stay small: a name typed there is a claim that ages, and the next lazily-imported helper would be missing again. This seat is the measurement — the closure now claims whatever the source actually reaches for.

Why only the local side moves. A string call naming something that is not ours stays out of third_party on purpose: _validate_dataviz.py:277 does __import__("hashlib"), _validate_type_composites.py:323 does __import__('datetime'), and importlib.import_module("tiktoken") is a guarded soft probe. Folding those in would invent NEEDS-DEP verdicts out of optional code paths.
