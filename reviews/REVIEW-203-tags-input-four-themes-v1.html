Tags input

Itinerary row 23, newly built at #203. A field you type your own values into, each committed as a removable chip. The gated Tags component is the display half of this — same chip, no field — so the chip is copied rather than drawn again.

Every pane is live. Type a reference and press Enter or comma. Try adding one that is already there, and try filling past eight: both are refused out loud rather than silently dropped.

PROPOSED #203, your eye owed — Backspace takes two presses. The first press on an empty field arms the last chip (an inset outline, announced to screen readers); the second removes it. One press would be faster and would also lose data silently for anyone typing quickly. Watch it in the Console panes, where the outline is easiest to see.

Approaching the limit is said in words, not in weight or colour. The counter changes from “3 of 8 tags” to “1 more tag allowed”. A weight change would need a raw font declaration the type gate forbids, and there is no component-composite emphasis hook — that gap is written up as a design-system improvement.

PROPOSED — no suggestions. A tags input that also suggests known values would be this composed with Multi-select. Deliberately not built; say the word and it becomes a variant.

Refusals stay ink. A duplicate or an over-limit value gets a message with a symbol and words; the red is on the field stroke only. Check the refusal panes in all four themes — the words should be perfectly readable, and the field should still obviously be the one at fault.
