Why scatter's filter never worked (proven, gate now fixed)

Scatter's legend is the dead static model (ul.dv-legend); the registry subscribes scatter to dv-behaviour only; and the migration gate read the static legend as "no legend", certifying the gap green. The gate is fixed tonight — it now says, loudly: "static legend present but not migrated and not subscribed" — and it will stay red until D3 below is ruled and enacted. That red is deliberate.

The four rulings

D1 — Ratify ADR-0015-A2 (the consumes-manifest), TENTATIVE since 07-28?

It has earned it: the narrow path is live (scatter's own declaration), refusal proven in four directions, and one unpredicted safety property observed — a declaration cannot be silently deleted without the file going non-conforming. Absent key = consumes everything (universal default), which is what makes sparkline's dead weight possible (D2).

D2 — Sparkline sheds its inert payload?

Sparkline has no legend and no behaviours that need one, yet carries 16,661 B of injected dv-legend (universal default; the record's "15.6KB" remeasured today). Declaring "consumes": ["dv-behaviour"] sheds it — the exact move the ADR predicted "when ruled". This is that ruling.

D3 — Scatter's legend: migrate, or delete?

Migrate: static ul becomes .dv-legrow rows (the molecule's markup parameters) and scatter adds dv-legend to its consumes list. Budgets hold, measured: scatter page would carry 13,346 + 16,661 = 30,007 B against the 32,768 group cap; dv-legend.js itself needs zero new bytes if discovery-at-init covers scatter's markers (they already carry data-series-group) — that zero is asserted by reading the init loop, and will be proven by the build gate at enact, not assumed. Delete: call scatter legendless-by-design (segments are already shape+letter-keyed on the points themselves — colour is never the only channel).

D4 — The control lockup becomes a named partial (the genuinely new molecule)

Title + View-as-table + (theme/contrast/replay where present) repeats across bar, donut, line, combo, scatter with drift between copies. Proposal: extract as an ADR-0013 partial (dv-lockup), parameterised by data-attributes (title text, which controls, alignment), registry-gated like every partial.
