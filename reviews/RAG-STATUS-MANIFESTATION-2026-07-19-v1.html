How is a RAG status drawn?

Colours are settled (R-D10). This decides the manifestation — which components carry status, and when. Canon already answers most of it: the Status-indicator (dot + label) is the existing RAG-coded form; tags and pills are explicitly not for status. The open question is whether we also canonise a filled cell (dense tables) and a bar (cards) — and how they map to surfaces.

The decision — which forms are canon, and their surface map

A · Status-indicator (dot+label): confirm as canon, rebind to R-D10 tokens. (existing component)

B · Filled cell/badge: canonise for tables/dashboards? This is where the ramp + fill rules apply.

C · Bar/edge: canonise for cards / grouped objects?

My steer: all three, context-scoped — A for inline / lists / anywhere a single status sits in text; B for status columns in dense tables (scan speed); C for cards. Tags/pills stay excluded. If you'd rather ship only the existing dot+label (A) and treat B/C as later, that's the minimal path.

Pick the canon set (A / A+B / A+B+C) and confirm the surface map. Then it's a Sonnet build: rebind Status-indicator + spec the cell/bar as gated components.
