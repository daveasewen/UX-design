Combobox

Itinerary row 21, newly built at #203 and shown here for the first time. A text field that narrows a list as you type, for option sets too long to scroll. The field anatomy is the gated Input-fields box and the popup is the gated Dropdown menu — both copied, neither re-drawn. Only the typing half is new.

Every pane is live. Type two or three letters into any field: the list narrows, the matched run underlines, arrow keys move the highlight without taking focus out of the field, Enter commits, Escape closes. Each pane runs independently.

The matched run is underlined, not bolded and not coloured. Bolding would need a raw font-weight declaration, which the type gate forbids — there is no component-composite equivalent of the editorial emphasis class. Colour alone is barred by 1.4.1 and by red and yellow being problem hues for you. Check the underline reads clearly in Console and Supercharge dark, where the ink is warmest.

PROPOSED #203, your eye owed — the highlighted row carries two signals. The active option has both the hover fill and a 3px inset rule on its leading edge, so the highlight never rests on colour alone. In Mono light the rule is nearly invisible against the fill; in Console it is obvious. Keep both, or drop the rule and rely on the fill?

PROPOSED — no free text. The value must come from the list. A combobox that also accepts typed values is a different contract and is not built here. If payee-name entry needs it, say so and it becomes a variant.

No canon block exists yet. These panes bind the snippet's variables straight to the canon DNA tier by hand, because the generator that normally writes the per-component block is another lane's exclusive surface this session. When it runs, the styling arrives the ordinary way and this page can be rebuilt unchanged.
