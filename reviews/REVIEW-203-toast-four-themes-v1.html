Toast / snackbar

The transient member of the feedback family: it appears on an event, confirms it, and leaves. Every pane below is the real gated markup rendered through the generated canon.css — not a copy, not a redraw.

Read this first — the brief's premise did not hold. Wave 3 was briefed from the itinerary of 2026-07-14, which marks this component Gap. It is not a gap: the gated snippet, the meta, the showroom page and the MIGRATED_SNIPPETS entry all landed on 2026-07-22, eight days after that snapshot. Nothing was re-built here. This page is an audit surface: the existing approved artefact, rendered through the real generated canon.css across all four themes, so your eye can rule on what is actually there. Everything below is PROPOSED #203, Dave's eye owed — nothing on this page is a ruling.

How Toast differs from its gated siblings

  • vs Alert Alert is the persistent, in-flow callout that stays until answered. Toast is transient: it appears on an event, confirms, and leaves on a 6s timer (paused while you hover or focus it). Toast therefore has no error variant by design — an error must persist, so errors route to Alert (role="alert"). Toast is always role="status", polite, never assertive.
  • vs Banner Banner is page-level and sits in the document flow. Toast is viewport-fixed, stacked bottom-left, and overlays.
  • vs Notifications This one is not clean — see below.

Finding — Apollo has two snackbars, with two different chromes. The gated Notifications component already carries a Snackbar placement (Notifications.reference.html:190–193): tinted ground plus elevation shadow, warning / success / information, error omitted, role="status". Toast is the same object with the opposite chrome: an elevated neutral raised surface, no tint, the status glyph sitting directly on it. Same job, same statuses, same ARIA, two visual answers. The third strip in every pane above puts them side by side so you can rule by eye.
PROPOSED #203, Dave's eye owed: either Toast supersedes the Notifications Snackbar placement and that placement retires, or the two are given a stated reason to differ. This is a duplicate-surface question and a promotion question — both yours, not a sub's.

The rest of the audit — all PROPOSED, all yours

  • Dark-mode roundel — open since 2026-07-22, never answered. The snippet's own manifest note says the dark coloured roundel on the elevated neutral ground was "flagged in the worker receipt for confirmation": the tint-surface white-shape ruling targets tinted grounds, not elevated neutral ones. It was flagged and then nothing happened. Look at the four dark panes.
  • The stack sits bottom-left (left:24px; bottom:24px). MD3 agrees; Ant puts it top-right. Never ruled either way.
  • 44px hit area — checked by hand, passes. The action is a real 44px-tall button; the dismiss × is a 24px visual with a 44×44 ::before hit target. No gate enforces this — it was measured in the source, not assumed.
  • Type-composite debt: 3 violations, all in demo chrome (body font-family, the demo h2's font-size:14px and font-weight:500) — none in the component itself. The gate already keeps a demo-chrome advisory bucket; these are not in it.
  • Colour is never the only carrier. Every status toast carries data-carries="symbol label" — a glyph and a sentence. Correct for the problem hues.

Measured finding, all four themes — in Supercharge dark the only thing holding this overlay off the page is a hairline at 1.96:1. These overlays are lifted by the elevation recipe: a shadow in light, a 1px border in dark. In light the panel is exactly the page colour in every theme (1.00:1) and the shadow does all the work — that is the canon recipe and it reads fine. In dark the border takes over, and it is not equal across themes: mono's hairline is #808080 on #1A1A1A = 4.41:1, comfortable; Supercharge's is #524842 on #1A1A1A = 1.96:1, under the 3:1 non-text floor. Compare the mono-dark and supercharge-dark panes below. Pre-existing and theme-level, not this component's — but it is the component that shows it. PROPOSED #203, Dave's eye owed.
