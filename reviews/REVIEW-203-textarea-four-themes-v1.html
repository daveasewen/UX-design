Textarea

Itinerary row 20. Already built and gated — landed 2026-07-22, after the 2026-07-14 itinerary that still lists it as a Gap. Every pane is the approved Textarea.reference.html markup through canon.css; nothing re-drawn.

First four-theme spread for this component. Each pane is live: type into the counter field at the top of any pane and the count, the weight change at 90%, and the polite announcement all run in that pane independently.

Error message stays ink, on purpose. The error state colours the border with rag/error and the message text with ordinary text/default, not red. Red text on the page background fails contrast in several themes, and you are astigmatic with red as a problem hue, so meaning is carried by the icon, the border and the words. Check the error pane in all four themes: the message should be perfectly readable and the field should still obviously be the broken one.

PROPOSED #203, your eye owed — no explicit hit-target rule. Unlike Alert and Form layout, this snippet declares no 44px minimum anywhere. In practice its only control is the textarea itself, which at rows="3" is far taller than 44px, so the requirement is met by geometry rather than by a rule. That is fine today and fragile tomorrow: a future one-row variant would silently drop under the floor. Worth a rule, but that is a decision, not a fix.

PROPOSED — type debt. Contributes 7 of the 1,097 type-composite violations, including a full font: 500 16px/1.3 shorthand on the demo headings. Shrink-only ratchet, so safe to pay down; left to the conductor because it edits an existing shared artefact.
