Tier-map proposal — atoms → molecules → organs → templates, shells as the slot mechanism

Two words, defined (s135):
Lexicon — the recipe book the build mode cooks from. Each entry = a named pattern declaring what it composes (tiers), what holes it opens (shells/slots), and what it emits (molecule/organ/template). The 209 folded patterns become recipes, not nodes.
Mutation key — the context name that switches a built-in variant of ONE component: in:card → tighter padding. The key unlocks the mutation; it never forks a second component. The 134 context nodes become these keys.
Judging rows: every underlined node id opens the component's actual rendered reference — judge with your eyes, flip the select if the tier is wrong, export when done.

Decision you're making: for every node the library has today, does the PROPOSED TIER look right, and is SHELL? ticked on the right things? Flip any select or checkbox, then hit Export at the bottom — that JSON is the ruling on this proposal.

Scope, per s135-D3 (ruled, not re-opened here): atoms/molecules/organs/templates hold their own variants EMBEDDED, keyed by context. A shell is not a 5th tier — it's a component AT ANY TIER that carries a slot for injected content (Dave: "patterns with injected contents... Figma calls them slots"). Contexts stop being nodes and become MUTATION KEYS on the component they modify. Per s135-D2 (ruled), 5 near-exact context nodes (card, header, link, navigation, tab) already merge into their matching component — those 5 are excluded below; the other 134 context nodes remain live but become keys, not nodes, under this proposal.

Counts: 14 atom · 35 molecule · 31 organ · 0 template · 209 lexicon-fold · 134 mutation-key · 1 n/a (scaffold) — 29 of the tiered nodes carry shell=true. Zero nodes propose to TEMPLATE today — no existing node is a full page assembly; templates are what the build mode GENERATES by composing organs+shells, which is the gap s135-D3 exists to close.

Mutation-key grammar

Today a component's edges.usedInContext points at a separate CONTEXT NODE (e.g. context:card). Under s135-D3 that edge becomes a mutation record embedded in the component's own meta, keyed by a plain string — the context NODE disappears (either because s135-D2 merged it into a component, or because it was never more than a placement label). One component, many keys, never a second node.

Shape: component.mutations[<context-key>] = {{ note, overrides: {{ prop/token deltas }} }}. The key is just the old context id with its context: prefix stripped — merged or not makes no difference to the KEY, only to whether a second node used to exist behind it.

Example 1 — Accordion in a Card

Today, knowledge/components/accordion.meta.json → edges.usedInContext:

[{ "ref": "context:page" }, { "ref": "context:form" }, { "ref": "context:card" }, { "ref": "context:tab-panel" }]

Proposed — folded into accordion's own mutation map. context:card is one of the 5 that MERGE per s135-D2, so the key survives as a string even though the node it pointed at is gone:

accordion.mutations = {
  "page":      { "note": "Page" },
  "form":      { "note": "Form", "overrides": { "header-padding-top": "padding/responsive/xxxsmall" } },
  "card":      { "note": "Card", "overrides": { "background": "inherit-from-card" } },
  "tab-panel": { "note": "Tab panel" }
}

Example 2 — Button in a Card / Dialog-modal / Page-header

Today, knowledge/components/button.meta.json → 5 usedInContext refs: context:form, context:card, context:dialog-modal, context:page-header, context:toolbar. One atom, five contexts — exactly the case s135-D3 names ("button-in-card is a mutation of the one button, never a second node").

button.mutations = {
  "card":         { "note": "Card",         "overrides": { "size": "compact" } },
  "dialog-modal": { "note": "Dialog/Modal", "overrides": { "variant": "primary", "fullWidth": true } },
  "page-header":  { "note": "Page header" },
  "form":         { "note": "Form" },
  "toolbar":      { "note": "Toolbar" }
}

Example 3 — Badge in a Tab / Link (both merge per s135-D2)

Today, knowledge/components/badge.meta.json → context:icon, context:navigation-item, context:tab, context:link. Two of these (tab, link) are in the 5 that merge away — this is the direct link between the s135-D2 cleanup and the s135-D3 mechanism: a merged context doesn't vanish, it becomes the mutation key.

badge.mutations = {
  "icon":            { "note": "Icon" },
  "navigation-item": { "note": "Navigation item" },
  "tab":              { "note": "Tab",  "overrides": { "labelled": false, "shape": "dot" } },
  "link":             { "note": "Link", "overrides": { "shape": "inline-pill" } }
}

Pattern lexicon — shape only, not built

Of the 214 pattern nodes today, 209 name exactly ONE source component (e.g. pattern:button-processing-state → button) — these are mutations in disguise and fold straight into that component's own mutations map above; they don't need a lexicon entry at all. The remaining 5 name 2–3 source components (budget-composition, portfolio-mix, list-grid-view-toggle, segmented-presentation-switch, spend-by-category) — these are real compositions and are the first candidates for an actual lexicon entry, because the build mode needs a recipe, not a mutation key, when the output spans more than one component.

Proposed shape (a new file, e.g. knowledge/components/_pattern-lexicon.json) — a generative grammar the build mode reads, never hand-assembled per instance:

{ "id": "lexicon:spend-by-category", "composes": ["chart-bar", "chart-donut", "chart-pie"], "slotsOpen": ["title", "legend-position"], "mutationKeysUsed": ["card", "dashboard-tile"], "emitsTier": "organ", "shell": true, "note": "recipe: instantiate one of the composed charts, wire its 'card' mutation key, leave title/legend open for the caller" }

Build-mode generation loop this implies: pick a lexicon entry (or author one by hand) → resolve composes to concrete nodes at their current tier → resolve each node's mutations map for the target context → assemble → the result is tagged shell:true only if a slot in slotsOpen is left for caller-supplied content. This is the mechanism Dave asked for ("create new molecules, organs, templates, shells, all patterns from a logical pattern lexicon") — sketched, not implemented.
