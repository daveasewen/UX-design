Data grid

The gated Data-grid component — sort, row selection, filter chips, pagination and inline edit — rendered through the generated canon.css in all four themes, light and dark. Each pane is live and independent. Sort a column, tick rows, page through, press F2 in a reference cell: it works in every pane, and you can compare two themes mid-interaction.

Why these are iframes and the other two review pages are not. The grid carries a real demo script bound to document-level ids. Eight copies on one page would fight over those ids and you would be reviewing a broken thing. Each pane is therefore its own document, styled by the same canon.css and the same theme attributes — the cascade is identical, the isolation is not a fudge.

Use the Live / Loading / Empty switch at the top of every pane. The three states are worth comparing across themes: Loading shows the skeleton bones, Empty shows the grid’s own no-results register — which is a different thing from the Empty-state component on its own review page, and whether those two should look the same is a question for you.

PROPOSED #203, your eye owed — the responsive divergence. This grid does not collapse to cards on narrow screens the way the passive Table does; it scrolls horizontally under a sticky header. The recorded reason is that collapsing orphans the columnheader-to-cell relationships a screen reader needs in a grid. Narrow this window and judge it — peers (Carbon, Ant, AG-Grid) do the same, but it is a visible inconsistency with Table and it should be a decision, not a leftover.

PROPOSED #203 — the Wave-3 brief scoped inline edit OUT of this component. It is already IN, and already built. The reference column edits with Enter or F2. Nothing was removed; the brief’s cut was written against a stale inventory. Keep it or cut it — but it is working code today, and cutting it would be a deletion, not a deferral.
