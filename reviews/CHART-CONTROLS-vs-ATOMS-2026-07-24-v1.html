Chart controls vs existing atoms — do we mint new? · 2026-07-24 v1

The chart-line exemplar's controls are all hand-rolled .dv-* classes. Before the wave fans out (three lanes port this pattern), the question is whether they should consume an existing atom or justify a new quiet-utility family. Below, each chart control sits beside the nearest thing we already have — drawn from the real snippet CSS, so what you see is what's in canon. The bordered cell is the chart's control; the muted cell is the existing atom.

01Segmented switch — exclusive, one active reuse candidate

The chart's view switch (Monthly ⇄ Year to date) and our View-options atom are the same semantics — pick exactly one. But they're different weight classes: the chart's is 24px, instant, joined-border, filled-active; the atom is 40px with an animated sliding indicator. Click both.

Chart · .dv-seg

Transparent, 1px --line, ink text, 24px. Active = instant ink fill. No motion, no press physics (Q5 quiet-utility posture).

Exists · View-options .seg

40px, one framing border, sliding fill that animates between segments (mirrors Tabs). Inverting secondary/background fill. A more prominent control.

Exists · Tab / Table .seg.pill

Same sliding mechanism, rounded pill. Used in Tab-bar / Table view-switches. Also 32–40px, animated.

02Additive toggle + action buttons no existing home

The chart's overlay toggles (Target line, Last year) are outline aria-pressed buttons; Copy CSV is the same shape as a momentary action. Nothing in the library is a quiet outline button — the only button atom is the Button press family, which is loud (filled tiers, scale/darken press physics) and was deliberately ruled out for charts (Q5). Compare the postures:

Chart · .dv-vt toggle + .dv-csv

Outline, 24px, ink border darkens on hover / when pressed. Quiet — reads as chrome, not a call-to-action. No scale, no fill motion.

Exists · Button .btn (B-D7 press family)

40px, min-width 96, filled tiers, press physics (scale + darken — press one). Built to be the loud action on a screen. Wrong register for chart chrome.

03Legend-as-filter chart-specific, new

Legend rows are filter buttons carrying the series' swatch shape + letter key, with the AA hollow off-state (grey that passes contrast, never dim-only). This is data-bound to the chart's own non-colour channels — there is no general atom for it, and arguably shouldn't be; it belongs to dataviz. Click a row to toggle.

Chart · .dv-legbtn (swatch + key + hollow off-state)

"Margin" is toggled OFF — note the hollow swatch + grey text/letter (the data/axis role, AA-passing), so state never rides colour or dimming alone.

Option A — mint a small "quiet-utility control" family (recommended)

Register a second control family (ADR-0013 group #2): a base quiet button (.dv-vt: transparent, 1px line, ink, 24px, no press) + a compact segmented variant + the legend-filter variant. This formalises the observed duplication into reusable atoms with a proper registry entry, contrast gate, and states — the same way the button family was minted. Any future quiet toolbar (table controls, filters) reuses it.

Cost: one registry group + a gate. Upside: the wave lanes port canon atoms, not copies.

Option B — extend the segmented atom + mint only the outliers

Give View-options/.seg a compact/quiet variant (24px, no-slide, ink-outline) and have the chart consume it for the view switch; mint the quiet button + legend-filter as chart-specific. Fewer new atoms, but bends a prominent, animated atom toward a posture it wasn't designed for — the two may fight as either evolves.

Paste-ready ruling (edit before I inscribe):
"Chart controls = Option A: mint a quiet-utility control family (base .dv-vt + compact segmented + legend-filter) as registry group #2. The view switch does NOT consume View-options as-is (weight class differs). Legend-filter stays dataviz-scoped." — or pick B, or split it differently.
