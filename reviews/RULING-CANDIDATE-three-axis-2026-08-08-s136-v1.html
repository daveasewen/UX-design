Ruling candidate — the three-axis model

CANDIDATE, not a ruling — nothing enters _rulings.json until you say ruled, per clause or whole. Drafted s136 from your words this morning ("shells… content variants… inject new variant molecules… all parametrized to a certain extent — this logic needs to be cohesive and flexible") + the #135 research lane. It subsumes the three items FLOATED at #135. Grounded in the existing meta.json schema — only slots is a new key; props, variants, tokens already exist.

Every node — atom, molecule, organ, shell — flexes on exactly three orthogonal axes: parameters for values · variants for switches · slots for content. A variant always travels with the node that owns it. A slot constrains by contract, never by list. A parameter draws only from the spine. No axis ever does another axis's job.
Clause AParameters — values, spine-bound, DTCG on the wire

If it's a value, it's a parameter. Spacing, labels, counts, colour roles. Lives in the existing props key. The bound ("to a certain extent"): every visual prop declares which spine token it binds — free hex/px values are forbidden. This is what lets four themes re-skin everything by re-binding tokens.

Wire format for the token spine itself: W3C DTCG (stable Oct 2025) — the industry format the research lane confirmed. Values stay in tokens/*.json (the spine); DTCG is how they're encoded, not a new home.

"props": [{ "name": "gap", "type": "token",
  "binds": "space/stack-md",        // ← spine path, MANDATORY for visual props
  "default": "space/stack-md" }]

Clause BVariants — switches, owned by their node, travelling with it

If it's a switch, it's a variant. Compact vs comfortable, with-icon vs without. Lives in the existing variants key as mutation-keys — a variant is never a new node (s135-D3, already ruled: "variants embedded as contextual mutations"). This clause adds the travel rule:

A variant belongs to the node that owns it and travels with it through any slot. Your "content variants which are their own molecules" — same molecule, wearing a mutation-key, injected anywhere. A shell never enumerates the variants of its contents.

Extends s135-D3 (ruled) — adds the travel rule only.
Clause CSlots — content, contract-typed, any scale

If it's content, it's a slot. A shell = any node with ≥1 slot; slots work at any scale (your s135-D3 readback, ≈ Figma Slots). The slot declares a contract — what it accepts, by tier or capability — never a list of children. New molecules ruled next year inject without touching the shell.

New meta.json key (the only schema addition in this ruling):

"slots": [{ "name": "content",
  "accepts": { "tiers": ["atom","molecule"] },  // or "capability": "chart"
  "min": 0, "max": null }]                       // null = unbounded

Shells made of variant-bearing molecules/atoms: the frame's parts flex on their own axes; injected content flexes on its own. Both at once, neither enumerating the other — that is what prevents the combinatorial explosion.

Clause DThe fork ban — the three axes are the ONLY sanctioned variation

Any variation not expressible on the three axes is a fork, and forks are gate failures. A one-off restyled copy in a snippet, a hand-tuned hex, a near-duplicate component — the gate names the axis the variation should have used. Enforcement lands as a validator addition (enact lane, priced separately) — this clause rules the principle, so the gate has authority to be built against.
