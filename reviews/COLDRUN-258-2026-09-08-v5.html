05 · Findings — one fact each, with the file that proves it

  1. data-theme on the same element as the .cn-* scope class silently kills the dark theme.

    canon.css generates every theme leg as a descendant selector — [data-theme="dark"] :where(.cn-template-dashboard-bento){…} (canon.css:16672) and [data-theme="dark"] :where(.cn-template-dashboard-bento) .sh-mark[data-mode="light"]{display:none} (canon.css:17082). Skill step 3 says "Root element (or <body>) gets class="canon" plus two attributes", and the source snippet does exactly that (Template-dashboard-bento.reference.html:920, <body class="tpl-bento-body" data-theme="light">, which is legal there because the snippet's CSS is un-scoped). Follow the parenthesis and put both on <body> and nothing in the dark block ever matches: this build's first dark render came out with unreadable dark-on-dark header type and both masterbrand marks visible at once. Moving data-theme to <html> fixed it in one attribute. No gate saw it: the screen gate passed the broken version too.

  2. Rules 13/14 and rule 2 pull in opposite directions on controls that are rendered, not authored.

    Rule 13 says the markup renders from DATA; rule 14 says every control does something. A control that lives inside a rendered fragment does not exist when the page's event wiring runs. Both kpi-cta buttons here are dead for precisely that reason — measure.json → kpi_cta.changed: false — while the identical data-view hook on a control that is in the static markup (View all) works: view_all → {before:"Group treasury overview", after:"Payment instructions", status:"Awaiting approval"}. The skill has no word about delegation, and nothing in the pack demonstrates it.

  3. No component in the library can be data-driven by copying it, so rule 2 has to be broken to satisfy rule 14.

    Every chart-* snippet is a static SVG with baked coordinates (Template-dashboard-bento.reference.html:1124-1135 — six <rect>s with literal x/y/data-fx). Rule 14 says "a filter that moves the grid but leaves a chart identical is a defect". There is no third option: the geometry must be authored. This build authored renderBars() and spark() against dv-behaviour's own data-fx/data-fw fraction grammar, so the carried engine re-fits geometry it never saw baked (chart_tooltip → "USD→USD: 1,871 thousand pounds" off a hover). It works — but it is the one place the build knowingly re-drew rather than spliced, and the pack has no way to tell the difference.

  4. A receipt that covers zero regions still passes both gates.

    GATE-validate_screen.log line 4 reads - receipt: ✅ 0 region(s) re-hashed and matched. The page copies markup from four snippets and carries no splice markers, so the receipt proves nothing about provenance and the gate is content. Relatedly, the APOLLO-DEMO check is fence-shaped, not string-shaped (_validate_receipt.py:769 matches a START/END pair): this page names the marker three times in honest prose and passes. Both are fine as designed — they are worth knowing before either number is read as evidence.

  5. Obeying rule 2 on the Data-grid checkbox fails the composition gate — unchanged since v4.

    Measurement 13, in full, above. _validate_compose.py:130 demands the literal string cn-selection-controls; Data-grid.reference.html:357 and :573 — the bytes the skill tells you to copy — do not contain it. The gate is right about the intent and wrong about who can satisfy it: only an edit to spliced snippet markup can.

  6. Ten of eleven chart types are still unused, for the fifth run running.

    All three charts on this page are columns, because the only chart the bento template demonstrates is a column chart and rule 2 says copy what you were shown. showroom/index.json lists chart-line, -donut, -combo, -bullet, -candlestick, -scatter, -stacked-area, -histogram, -boxplot, -butterfly-h/-v and -pie, all stable. A corporate treasury screen wants a line for the liquidity curve and a bullet for limits; the pack routes to neither.

06 · The creativity judgement — labelled as a judgement, not a measurement

What the rewrite bought this run is a derivation layer plus a router: one DATA object, one rows() predicate that every panel reads, and one renderAll() that re-derives four KPI tiles, three charts, five summary blocks, the status strip's counts and a 54-row grid from it — then hands the freshly emitted SVG back to a carried behaviour by dispatching a resize, so dv-behaviour.js re-fits geometry that did not exist when it loaded. A 2a-bound build cannot produce any of that, because none of it belongs to a component: a snippet cannot know which filter drives it, a template cannot know it has four views, and no file in the library can hold the sentence "when the entity changes, the corridor chart's domain changes too." The old rule forbade exactly the connective tissue that turns a wall of specimens into a dashboard. What it also invites — visible in F02 — is authored code with authored bugs, and the pack has no convention for wiring controls that are rendered rather than written.

07 · Ruling-shaped questions — for Dave, not answered here

  1. Does data-theme belong on <html>, full stop? Step 3's "root element (or <body>)" is a trap once canon's theme legs are descendant selectors. Either the parenthesis goes, or the generator emits :is([data-theme="dark"], [data-theme="dark"] *). Both are one-line changes; which one is yours.
  2. Should the pack ship a wiring convention for rendered controls? Event delegation off a stable container is the ordinary answer, and rule 14 cannot be met reliably without one now that rule 13 requires the markup to be rendered. Is that a skill rule, a guideline, or a worked example in the bento template?
  3. Is authored chart geometry legal, and how is it declared? This build emitted SVG columns from data. That is either the intended consequence of s258-D1/D2 or a rule-2 violation with a good excuse. A ruling here also decides whether chart-* components need a declared render contract.
  4. Does the Data-grid snippet get cn-selection-controls, or does the gate stop asking? Two runs have now hit the same line. One of the two files is wrong and neither is this lane's to change.
  5. Should a receipt covering zero regions pass? A page that copies four snippets and declares no splice regions currently mints a clean receipt. If the receipt is meant to prove provenance, zero regions is the one case it cannot.
  6. Is one chart type enough for the demo? Ten stable chart components have now gone unused five runs running, because nothing routes a request to them. Routing off the knowledge graph is W-333, banked at #232 and still yours.
