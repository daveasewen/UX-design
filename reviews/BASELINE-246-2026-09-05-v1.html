Findings

Each one a fact and the file that proves it

  1. No dashboard-set component wires to another, so "make filtering and navigation work" cannot be met without authoring JavaScript that rule 2a forbids.

    Filter-toolbar-bar.reference.html L388-405: the dropdown handler only writes the trigger label. behaviour key: none on 25 of 27 metas probed (READ-LOG.md row 5). Glue: arm-A-blind/dashboard.html, last <script>, 14 lines.

  2. The two gates enforce two incompatible composition models. A page spliced from snippets (rule 2, the receipt gate) fails compose on 281 hex colours and a .c-bento redefinition that ARE the spliced CSS; it passes compose only after every spliced style is thrown away for a canon.css link.

    arm-B-sighted/gate-it1-screen.txt (receipt ✅, compose ❌ 281 hex) vs gate-it3-screen.txt (both ✅, page 225 KB → 119 KB). knowledge/_validate_compose.py L108-114.

  3. Template-dashboard-bento ships its chart stripped: no toolbar, no legend, no table, no engine. "Charts partially retrieved" is built into the template a dashboard must start from.

    Template-dashboard-bento.reference.html L102-108 and L911-946; meta antiPatterns: "Do not host a source component's JavaScript engine here." drive.json charts.chart-bar: controls 0, animation none.

  4. The blind copy truncated Filter-toolbar-bar's CSS one comment short of its organism rules, and the toolbar rendered stacked full-width. Only sight caught it.

    Filter-toolbar-bar.reference.html L231-251 (the .ftb-* block); arm-B-sighted/probe-it0.json vs probe-it2.json; render-it0-1440-light.png vs render-it2-1440-light.png.

  5. Tabs' markup carries no type composite; the snippet depends on its own body{font-family}, so in a composed page the tabs fell to a serif.

    Tabs.reference.html L76 (body font) and L132-137 (no t-cm-*); probe-it0.json tabFont "Times New Roman".

  6. Persistence exists nowhere in the system: no snippet, partial or rule stores state, and the page loses tab and filters on reload.

    drive.json persistence.after-reload: t1, 24 results, All currencies, localStorage 0 — both arms.

  7. Composing the toolbar and the grid produces two search fields and two applied-filter bars; the toolbar's search has no consumer.

    render-1440-light-payments-USD-sorted.png (both arms); drive.json toolbar-search-Bayer: grid count unchanged.

  8. The receipt gate cannot judge behaviour for the dashboard set because the metas carry no typed behaviour.script address; it reports UNPROVEN for every markup region.

    arm-B-sighted/gate-it3-receipt.txt: "NO-BEHAVIOUR-DECLARED · meta:NONE" ×3; s234-D5 named as the open item.

  9. Data-grid's demo data lives inside its script, so real content forces the one edit rule 2a forbids.

    Data-grid.reference.html L462-487; both arms' dashboard.html head comment, deviation (2).

  10. Sight bought two visible fixes and two green gates, and moved none of the four scores; the scripts and the driven interactions are identical across arms.

    drive.json diff (5 keys, all metrics); ITERATION-LOG.md "What sight bought".

  11. Running the screen gate on a page under outputs/ writes into knowledge/ — a read-only lane cannot gate without a side effect.

    knowledge/_validate_screen.py L128-147, L201; index restored via git show HEAD:; knowledge/_screen-gate/dashboard.md left on disk (rm refused by the mount). A stale .git/index.lock from 4 Sep 07:33 blocked git checkout.

  12. Rule 7 sends the builder to knowledge/_render/_bento_edit_rails.json, which is not among the pack surfaces a blind builder may read; the template carried the mono dashboard defaults inline, so nothing was lost this time.

    generate-from-canon/SKILL.md L86-91; brief §Arm A read list.

Ruling-shaped questions

Only Dave can answer these. This page does not.

  1. Rule 2a says author no JavaScript; the demo prompt says make filtering and navigation work; no component wires to another. Which yields — may generate-from-canon author declared glue, or does wiring become a registered partial (a "consumer" contract on toolbar controls)?
  2. Two composition models, two gates: splice (receipt) or canon.css-link (compose). Which is canon for a composed page, and must the other gate be told which mode it is reading?
  3. Should Template-dashboard-bento carry its chart's toolbar and engine, given every dashboard starts from it and its stripped chart is the "partial retrieval" the stakeholder will see first?
  4. Is persistence — filters surviving reload, a remembered tab — a system responsibility (a partial every page can copy) or the app's? For the two-week demo, which?
  5. The toolbar's entity dropdown, period switch and search field have no declared consumer. Should a control's meta name what it filters, so a builder can wire it without guessing?
  6. Mono is the skill's default when nobody answers the theme question. Is mono what the stakeholder should see, or should the demo prompt (or a brief) fix the theme first?
  7. May a lane's gate run write into knowledge/? If not, the screen gate needs an output-path switch before any read-only baseline can be repeated.
