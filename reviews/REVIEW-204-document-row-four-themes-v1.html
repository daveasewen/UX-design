★ First, the thing you actually need to rule — and it is about the OTHER row. Lane N was given two itinerary rows. Row 91, “Transaction / ledger row”, is not a gap. You built it and promoted it two months ago. list-items.meta.json says so in its own words: “PROMOTED 2026-06-22 (Dave) — TRANSACTION row brought to the Tabs-bar standard”, scope “Transaction row only (the ★ payments-journey row)”, graded 9.0/9. The gated file’s own title is “List items — Transaction row (reference implementation, gated)”. So I built no transaction row. The itinerary is overstating, not the store understating — row 91 should be marked Duplicate, and that is your call, not mine.

Row 92 is different, and the difference is structural, not stylistic. In List-items the whole row is a <button>. That shape allows exactly one action per row. A downloadable document row has two actions that are not the same action — open the document, and download the file — and you cannot legally nest one control inside another. So this row is built as a passive row with a stretched-link title plus a sibling download button. Two independent targets, both 44px or more, neither inside the other. That is the whole reason it is a separate component.

⚠ And the honest converse, which you should look at before you accept any of this. Scroll to Variant B in every pane. That is the single-action form — the whole row downloads, no preview. Variant B is structurally a List-items row and should be one. If the product only ever needs Variant B, then this component should not exist either and row 92 collapses into List-items exactly as row 91 did. I have drawn both so you can rule by eye rather than by argument.

⛔ I invented no money colour, deliberately. A statement/ledger row is precisely where a debit/credit red-and-green binding gets improvised into canon. This row carries no amount at all, so there was no seat to invent and none was invented. Where an amount is genuinely wanted on such a row, the answer is the gated Amount-display atom, which already holds the approved treatment: monochrome value, a real U+2212 minus, and the only coloured seats being rag/success-ink and rag/error-ink, mono only. Copied from amount-display.meta.json; not extended by one value. The only colour on this row is the status chip, which is the Status-indicator tint chip copied verbatim from List-items — and every status carries its word as well as its hue.

Everything below is PROPOSED. The fintech semantics are yours. The document-type vocabulary (statement / certificate / tax / contract), the statement periodisation (“1 Jun – 30 Jun 2026” on line two vs folded into the title), the download affordance’s form (icon-only button vs a text link vs a whole-row download vs an overflow menu), whether a document carries a status chip at all, whether file size shows, and the row density. Not one of those is ruled. Seven open questions in all — they are listed in document-row.meta.json under openQuestionsForDave, each with the store search that failed to settle it.
