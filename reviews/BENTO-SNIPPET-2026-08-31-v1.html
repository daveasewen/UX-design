The bento dashboard snippet

A new file — knowledge/snippets/Template-dashboard-bento.reference.html — so a cold builder can COPY a bento dashboard instead of paraphrasing one out of canon.css. Everything below is the real file, alive, rendered through canon.

Why it exists. s230-D1 made your demo condition checkable in five beats, and beat 3 measured PARTIAL for one mechanical reason: grep -rl '\.c-bento' knowledge/snippets/ returned zero files. The instruction "copy component markup from knowledge/snippets/" had nothing to point at for a bento dashboard. It does now.
Nothing here is ruled by this lane. Two things want your eye and one wants your word: the dark page ground (§5) is a real open question, the four themes (§4) differ only in radius because a snippet is mono-authored, and the whole file is PROPOSED — not registered, not gated, not in _rulings.json.
1

What was built, and what it obeys

The page is one dashboard-role bento wall whose tiles are themselves bentos — the bento-of-bentos of s217-D2/D3. Canon detects that structurally (:has(> .c-bento__grid > .c-bento)) and gives the outer wall the open gutter while the inner walls stay tight. There is no second role name and no switch.

Every region is a byte-identical splice from a file already on disk: the bento grammar from canon.css's own AUTO-BENTO block, the modules from Template-dashboard.reference.html, the masthead and the brand mark from App-shell-top-nav.reference.html. Nothing was re-drawn.

The responsive spread — and why there are no orphans

A bento wall is its own container, so the bands answer the wall, not the window. Canon compiles them to 6 → 3 → 2 → 1 columns at 1100 / 820 / 520 container px. The four frames below are 1180, 900, 680 and 420 px wide.

The squaring pass is mint-time (s217-D3/D7) and a static snippet cannot run it. So the spans here are chosen from the one set that needs no pass: canon clamps any data-c above the live column count, so data-c="6" is a full row at every band and data-c="3" is a half row at six columns and a full row at three, two and one. Every wall holds an even number of 3s. Orphans are impossible by construction — look along the bottom edge of every group in every frame.

The four themes

Rendered through canon, so the theme cascade is canon's own and not this lane's hand. What differs is the radius — console's --border-radius-container is non-zero, so its sub-bentos are rounded containers with square tiles inside, exactly the s217-D2 model; mono, legacy and supercharge resolve it to 0 and draw the same picture square.

Declared  What does NOT differ is the spacing, and that is honest rather than complete. s219-D1 gives each theme its own dashboard pair (mono 40/4, legacy 24/4, console 40/4, supercharge 24/2). A snippet is mono-authored by convention, so only mono's pair is minted here; the other three are addressed at knowledge/_render/role_defaults_219.py rather than typed into a second home. Whether a bento snippet should carry all four is in §6.

AWAITING DAVE — the dark page ground

Awaiting Dave

s219-D1 rules the dashboard page ground as grey. In light that is surface/subtle = #F0F0F0 under white modules, and it works. In dark the same token resolves to #1F1F1F — which is byte-identical to tertiary/background/default, the module surface. Ground and module become one colour, the 4px gutters disappear, and the wall stops reading as a bento at all. s219-D3(4) leaves the dark page-ground derivation expressly open ('dark equivalents to be derived from tokens'), so this lane did not decide it.

AWAITING DAVE — a module’s own radius inside a rounded group

Awaiting Dave

s217-D2 puts the theme radius on the bento’s container and says the tiles stay square inside the clip. Canon enacts that by writing no tile radius at all — deliberately, and its own comment says why: a literal border-radius:0 would trip the radius gate (ADR-0010) and would square off the very inner containers whose radius IS the dashboard role.

But a bento tile here is not an empty box — it is a component, and a Kpi-tile carries border-radius:var(--border-radius-surface) of its own. In mono, legacy and supercharge that resolves to 0 and the question never appears. In console it resolves to 20px (measured), so the modules come out rounded inside an already-rounded group. Canon never ruled on that case, because canon’s tiles have no radius to rule on.

Left is what the file ships (the component keeps its own radius — no new CSS, nothing overridden). Right is the same wall with the modules squared, which is what “tiles stay square” reads as if it reaches components too.

The other things that are yours, not mine

None of these were decided. Each is a real fork with a measured cost.

  • Should a snippet be allowed to link canon.css? Today none does — the true probe (grep -l 'href="../canon/canon.css"' knowledge/snippets/*.reference.html) returns 0 of 137. So a snippet that uses a canon STRUCTURAL component has to carry a COPY of the generated block. This file carries a declared copy of the AUTO-BENTO block, and the projector then puts that copy back into canon.css under its own scope: +8 KB of duplicated bento rules, measured. Linking canon.css, or teaching the projector to skip canon-owned selectors, are both convention changes and both yours.
  • Should this file carry the keylines-ON construction? Keylines are OFF by ruling (s219-D2(4)), so the file is correct as it stands. But the ON construction's corner assignment is minted per responsive band by gen_bento_matrix_217.corner_rules() (s218-D1) — hand-copying ~36 selectors into a static snippet would be a third home for a generated fact, so it is ADDRESSED, not duplicated. If a cold builder must be able to turn keylines on from the snippet alone, that wants a generator, not a copy.
  • Should a bento snippet carry all four themes' spacing defaults? See §4. Today only mono's.
  • The period switcher was left out. Template-dashboard's header ends with a .seg spliced from View-options, and View-options writes height:40px — off the 28/36/44/48 ramp, one of the three findings the #230 eye lane raised. Measured at head: grep -ln 'height:40px' knowledge/snippets/*.reference.html returns 13 files, View-options among them; Segmented-control.reference.html — the component s229 actually ruled — is not among them. Nothing was edited at source. If you want a period switcher on this page, the source to splice is Segmented-control.
  • Two bento parameters cannot be token-bound today. layout/bento/columns comes back as the string "6px" because the projector's unitless list does not know the path, and layout/bento/packing lives under $extensions by s217-D4 so it has no $value at all. Both are declared as literals with the reason attached; the one-line fix for the first is priced in the report, not applied.
