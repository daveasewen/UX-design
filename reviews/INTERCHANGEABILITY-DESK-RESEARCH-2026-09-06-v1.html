#249/#250 · Lane DESK · desk research, not a pick · 2026-09-06

Five fields already have a grammar for “this instead of that, when”. Apollo should borrow the grammar, not the weights.

Dave: “can you do some desk research on the structure of interchangeable- etc, there might not be anything directly applicable from the design world (but there maybe), there might be related taxonomies out there that we might get inspiration from.”

One-line answer: the design world has the vocabulary (variants, swap, “when not to use”, related components) but not the structure; the structure lives in three older systems — military form-fit-function (three axes must all match), Debian’s Provides / Replaces / Conflicts + update-alternatives priority (three relation types plus a tie-break, in production since 1995), and thesaurus standards (USE/UF, RT, exactMatch/closeMatch — canonical vs alias, and a graded not numeric “same-ness”). Every field that grades substitutability uses 3–4 named grades, never a 0–1 float; every field that works in practice attaches a condition to the edge; and every field keeps substitutes, complements and conflicts as separate relations. Below: 22 sources, one table, six recurring structures, a traced vocabulary of eight terms, and what not to copy.

01

Design world

Design systems name the relations in prose and hang the structure on folder names.

Figma’s “related components” are the ones in the same slash-path. Carbon’s “when not to use” is a sentence. Alexander is the only one with a graded edge — and it is a hand-set asterisk, not a number.

W3C Design Tokens (DTCG) — alias / reference

Vocabulary alias ({group.token}), $extends group inheritance · graded no · conditional no · symmetric no (a pointer) · authored

A token’s value may be a reference to another token; “the same value can have multiple names or aliases”. Circular references are forbidden. The spec also lets a deprecation message point at the replacement: “Please use {button.activeBorder} instead”. Lesson: the one structural relation the design world has formalised is canonical + alias — a name that resolves to another — and tooling is expected to resolve it. Apollo’s variant-of is this shape. [S5]

Figma — component sets, variants, swap instance

Vocabulary variant properties, instance swap, “related components” · graded no · conditional no · symmetric yes (any → any in the group) · derived from naming

The Instance menu offers swaps; “related components are components that share the same hierarchy” (same file/page/frame) and “Figma also groups related components organized using the slash naming structure” — UI/Button/Active and UI/Button/Hover are related because of their path. Swapping “will try to preserve any overrides”. Lesson: the most-used design tool derives relatedness from location and naming, not from declared semantics; it has no notion of whether a swap is a good idea, only whether it is possible. Do not copy. Apollo’s $family/category already gives this for free. [S9]

Material 3 — component × variant × state

Vocabulary types (elevated, filled, tonal, outlined, text), emphasis levels, states · graded yes, on emphasis (high/medium/low), not on similarity · conditional prose (“use for primary actions”) · authored

M3 buttons are one component with five types ranked by emphasis; the guidance says which type for which prominence of action. Lesson: variants inside one component are ordered by prominence, which is exactly Apollo’s prominence 1–3 — but M3 never says a button is interchangeable with anything that is not a button. Variants are a within-family axis, not a between-family relation. [S22]

IBM Carbon — “When to use / When not to use / Related”

Vocabulary when to use, when not to use (“Do not use buttons as navigational elements. Instead, use links”), variants with purpose, “Related” list · graded no · conditional yes, prose · symmetric no · authored

Carbon’s usage page is the design world’s closest thing to a conditional substitution: when not to use X, use Y instead. It also carries an emphasis order (primary once per page; secondary only with a primary) and a table of allowed/forbidden button-group combinations — a hand-written Conflicts list. Lesson: the three things a factory needs (instead-of, with, not-with) are all present in Carbon, as sentences. Apollo’s $differsFrom/mustNotNeighbour prose is the same thing at the same maturity. [S17]

Alexander, A Pattern Language — pattern links and asterisks

Vocabulary larger patterns this completes → this pattern → smaller patterns it needs; numbered cross-references “(12)” · graded yes: 0–2 asterisks = “our degree of faith in these hypotheses” · conditional yes, the problem statement is the condition · symmetric no (contains / is-contained-by) · authored

“Structured as a network, where each pattern may have a statement referenced to another pattern by placing that pattern’s number in brackets.” Each pattern states a problem, then a solution “in a very general and abstract way — so you can solve the problem, in your way”. Lesson: two things. The edge is problem-first (Apollo’s answers); and the only grading is a coarse, hand-set confidence, not a similarity score. Also a warning: the network lives inside prose, which is why it took wikis to make it navigable. [S13]

ui-patterns.com — problem / solution / usage / related

Vocabulary problem summary, solution, usage (“use when…”), rationale, alternate titles, neighbouring patterns · graded no · conditional yes (“Use when you want to reduce feelings of being overwhelmed”) · authored

The catalogue card is Alexander’s card with a UI: the condition is a “use when” bullet and the alias is “alternate titles: Revealing Interfaces”. Lesson: confirms the design pattern tradition carries answers + when + alias, never a weight. [S12]

Brad Frost — Atomic Design; Nathan Curtis — component API

Vocabulary atoms → molecules → organisms (contains); anatomy, props (text / variant / boolean / instance-swap / slot), subcomponents that “forward to, add to, inhibit and facade” a parent · graded no · conditional no · authored

Frost’s five stages are a containment hierarchy, “not a linear process” but a mental model. Curtis’s API work names the prop types — and one of Figma’s prop types is literally instance swap, i.e. a slot whose filler is interchangeable. Lesson: contains/hasPart is well-trodden; Apollo already has it. The slot is the interesting part: a slot declares an interface (what may go here), which is FFF’s “fit” in design-system clothing. [S16][S20]

Design-world verdict: vocabulary yes, structure no. Every system reviewed encodes instead-of as a sentence and related-to as a folder. The one graded edge (Alexander) grades confidence in the pattern, not similarity between patterns. Nothing here would let a factory produce three solutions without a person reading prose.

02

Knowledge organisation

Thesauri solved “same-ish” forty years ago: a canonical term, its aliases, and a small ladder of match strengths.

SKOS refuses to make “close” transitive because chaining close matches compounds error — the exact hazard of a weighted kpi → stat → status walk.

W3C SKOS — broader / narrower / related; exactMatch / closeMatch / relatedMatch

Vocabulary skos:broader, narrower, related; mapping: exactMatch, closeMatch, broadMatch, narrowMatch, relatedMatch · graded yes, two rungs · conditional no · symmetric related, closeMatch, exactMatch yes; broader/narrower inverses · authored

Verbatim: closeMatch links “two concepts that are sufficiently similar that they can be used interchangeably in some information retrieval applications. In order to avoid the possibility of ‘compound errors’ when combining mappings across more than two concept schemes, skos:closeMatch is not declared to be a transitive property.” exactMatch = “high degree of confidence that the concepts can be used interchangeably across a wide range of applications”, transitive, a sub-property of closeMatch. Lesson: the world’s most-deployed “interchangeable-with” predicate is two-valued, not weighted, symmetric by declaration, and deliberately non-transitive at the weaker rung. A 0–1 weight invites exactly the chaining SKOS forbids. [S1]

ISO 25964 — USE / UF / BT / NT / RT, reciprocity, compound equivalence

Vocabulary USE (→ preferred term), UF (use-for), BT, NT, RT, SN (scope note); USE A + B / UF+ compound equivalence; Part 2: exact / inexact / partial equivalence mappings · graded yes (exact / inexact / partial) · conditional scope note, prose · symmetric RT yes; USE/UF and BT/NT reciprocal · authored, reciprocals enforced by software

The standard requires reciprocity: if A BT B then B NT A; if E USE F then F UF E. Compound equivalence says one non-preferred term may be replaced by a combination of preferred ones (USE A + B). Part 2 §11 grades cross-vocabulary matches “exact, inexact and partial”. Lesson: (1) author one direction, derive the reciprocal — Apollo’s validator can do this and today nothing does; (2) compound equivalence is the case Apollo’s status example needs: “status-indicator strip” ≈ kpi-tile + threshold is a USE A + B, one component replaced by a pair; (3) the grade ladder is three words. [S11][S11b]

WordNet — synset, hypernym, meronym, troponym, antonym

Vocabulary synonymy (synset membership), hypernym/hyponym (is-a), meronym/holonym (part-of), troponym (manner-of, verbs), antonym · graded no · conditional no · symmetric synonymy and antonymy yes; is-a and part-of inverses · authored (lexicographers)

Words are “grouped into synsets with short definitions and usage examples” — interchangeability is set membership, not a pairwise edge: if two words are in the same synset they are substitutable in that sense. Lesson: the cheapest representation of a substitute group is a named set (Debian’s virtual package, below, is the same idea): declare “status-surface” once and list its members, rather than n² pairwise interchangeable-with edges. The sense (which synset) is the condition. [S15]

schema.org / GoodRelations / UN-CEFACT — isSimilarTo, isRelatedTo, isVariantOf

Vocabulary isSimilarTo “a pointer to another, functionally similar product” (equivalent property unece:SubstituteProduct), isRelatedTo, isVariantOf, isAccessoryOrSparePartFor · graded no · conditional no · symmetric not declared · authored

Commerce keeps similar (substitute), related (complement, loosely) and variant-of (same product, different attributes) as three properties; the standards body maps isSimilarTo straight onto “SubstituteProduct”. Lesson: confirmation that substitute / complement / variant are three predicates in the most-deployed product vocabulary; none carries a weight. [S7] GS1 GDSN substitute-item link not fetched — UNVERIFIED

Wikidata — P460 “said to be the same as”, P1889 “different from”

Vocabulary “this item is said to be the same as that item, but the statement is disputed”; “different from” for disambiguation · graded yes: a hedged identity, one rung below owl:sameAs · conditional via qualifiers · symmetric in practice · authored, not transitive

Lesson: even a triple store with millions of editors chose a named hedge (“said to be”) over a confidence number, and a separate explicit negative (“different from”) to stop bad merges. Apollo’s $differsFrom is “different from”; it is the negative edge that stops a factory swapping kpi-tile for stat-card when the brief has a series. [S8]

03

Engineering & packaging

Form, fit, function — and Provides, Replaces, Conflicts — are the two structures that map onto Apollo’s tags without translation.

FFF names the three axes a substitute must match; Debian names the three relations a resolver needs and adds a numeric priority only at the very end, to break ties.

Form, Fit, Function (US DoD, 1960s; 22 CFR 120.42; NASA F3 + Reliability; Navy F3I)

Vocabulary form (configuration, material — “for software, the design, logic flow, and algorithms”), fit (“ability to physically interface or connect with … another commodity”), function (“the action or actions it is designed to perform”) · graded binary per axis; all three must hold · conditional no · symmetric yes if all three match · authored (data rights contract)

“If F3 for two components have the same set of characteristics, i.e. they have the same shape or form, same connections or fit, and perform the same function, they can be substituted one for another.” The point of F3 was to let the customer second-source the part. Lesson: the strongest analogue in the set. Apollo’s three leverage tags are FFF in a different order: fits = form (what tile it occupies), data-shape = fit (what it connects to), answers = function. Substitutability is then derived from three per-axis comparisons — not authored as a pairwise weight. And the reason FFF exists — competition between suppliers — is Dave’s reason: three solutions to one brief. [S6]

TI cross-reference — four grades of equivalent part

Vocabulary DROP-IN REPLACEMENT “same function, same pinout, parametrically equivalent or better” · PIN-FOR-PIN “same function, same pinout but different parameters” · SAME FUNCTIONALITY “same function, but different pinout and parameters” · SIMILAR FUNCTIONALITY “similar function, pinout and/or parameters” · graded yes, 4 rungs · conditional implicit in the grade · symmetric no (drop-in allows “or better”) · derived from a parts database

Lesson: this is FFF turned into a ladder: each rung drops one axis. Function held, fit (pinout) held, form/parameters relaxed → pin-for-pin; function held, fit relaxed → same-functionality; function relaxed → similar. The ladder is the weight — ordinal, four named values, and every engineer knows what each means. Apollo’s weight 0–1 should be this ladder: drop-in · same-shape · same-answer · similar. [S18]

Debian Policy §7 — Depends / Recommends / Suggests / Enhances / Breaks / Conflicts / Provides / Replaces; restrictions

Vocabulary Depends (absolute), Recommends (“would be found together … in all but unusual installations”), Suggests, Enhances (the reverse of Suggests), Breaks, Conflicts (“cannot be unpacked at the same time”), Provides (virtual package), Replaces; alternatives with |; version relations; architecture restrictions [amd64] and build-profile restrictions <!nocheck> · graded yes: Depends > Recommends > Suggests is a three-rung strength of complement · conditional yes, first-class: foo [!i386] | bar [!amd64] · symmetric no; Enhances exists precisely to state the reverse direction · authored per package

Key structure: a package says Provides: mail-transport-agent and any dependency on that virtual name “can be satisfied … by any other concrete package which provides the virtual package”. Providers of a one-at-a-time facility add Conflicts: mail-transport-agent and Replaces: mail-transport-agent. “To specify which of a set of real packages should be the default … list the real package as an alternative before the virtual one.” And: “Having similar functionality or performing the same tasks as another package is not sufficient reason to declare Breaks or Conflicts” — similarity and conflict are kept apart on purpose. Lesson: the three relations a factory needs, and the trick that makes them scale: the role (virtual package) is the thing that is named; substitutability is membership in the role, complement is Recommends/Suggests, exclusion is Conflicts, and the condition rides on the edge in brackets. Apollo’s when is Debian’s [arch]. [S2]

Debian update-alternatives — priority to pick a default

Vocabulary alternative name (vi), providers (nvi, vim), priority, auto/manual mode · graded yes: an integer priority per provider, compared only within one alternative group · conditional no · symmetric n/a · authored by each provider; resolved by the system

“When several packages all provide different versions of the same program … it is useful to have the system select a default, but to allow the system administrator to change it and have their decisions respected.” Lesson: the only number in the whole packaging stack is a tie-break priority inside a named group, and it is overridable by a person (“manual mode”). That is the right home for Apollo’s weight: not on the pair, but on the provider of a role — and Dave’s s248-D4 “the choice is the designer’s” is manual mode. [S3]

Software substitutability — semver, Liskov, peerDependencies

Vocabulary MAJOR (incompatible) / MINOR (backward-compatible addition) / PATCH; Liskov: S substitutes T if every property provable of T holds of S; npm peerDependencies = “designed to work with a compatible version of a host” · graded semver yes (3 rungs); Liskov binary · conditional version ranges are the condition · symmetric no — subtype substitutes supertype, never the reverse · authored (declared API)

Semver only works because “you first need to declare a public API”; Liskov substitution is one-directional by definition. Lesson: substitutability is directional and depends on a declared interface. A kpi-tile can stand in for a stat-card (it carries a superset: value + delta + series) but not the reverse — the META report’s $differsFromStatCard “a KPI tile with no series is a Stat card” is a Liskov statement. Author edges one way; derive the reverse only where the shapes are equal. [S14][S19][S21]

04

Recommenders

Amazon needed two graphs, not one — and 144 million reviews to learn the weights.

The weights are the least transferable part. The two-relation structure is the most.

McAuley, Pandey, Leskovec (2015) — “Inferring networks of substitutable and complementary products”

Vocabulary substitutes (“products that can be purchased instead of each other”), complements (“products that can be purchased in addition to each other”) · graded yes: link-prediction probability · conditional yes, by stage: “while a user is looking for mobile phones … recommend other phones, but once they buy a phone … recommend batteries, cases, or chargers” · symmetric substitutes ≈ yes, complements no (directional) · derived from 9M products, 237M links, 144M reviews

The paper treats the two relations as a “supervised link prediction task” with topic models over review text; weights fall out of the data. Lesson: (1) two relations — a factory choosing a status surface wants substitutes; a factory filling the rest of the row wants complements (“also bought”: a status strip is usually bought with a needs-attention list). Apollo names them interchangeable-with and related-to; they must stay two keys. (2) The condition is the stage of the task — before choosing vs after choosing — which is Apollo’s answers (before) vs contains/groupsWith (after). (3) The weights were learned. Apollo has 137 files and no behavioural data; a 0–1 weight there would be an opinion wearing a decimal point. [S4]

Collaborative filtering / “also viewed · also bought”

Vocabulary item–item similarity (cosine over co-occurrence) · graded yes, continuous · conditional no · symmetric yes · derived

Lesson: continuous weights are legitimate only when there is a co-occurrence matrix to compute them from. Apollo’s nearest equivalent would be counting which components co-occur across the four baseline dashboards and the template ($composes, 11 slugs) — a derivable related-to, weak but honest. general knowledge — no single source fetched

The six recurring structures

  1. Three independent axes, all must hold — FFF.

    Form/fit/function; Liskov’s declared interface; Figma’s slot type. Apollo already named the three: fits, data-shape, answers. Substitutability should be derived from them, and authored only where derivation is wrong.

  2. Grade is a short ordinal ladder, never a float.

    TI 4 rungs · SKOS exact/close · ISO exact/inexact/partial · Alexander 0–2 asterisks · semver major/minor/patch · Debian Depends/Recommends/Suggests · Wikidata “said to be”. The only continuous weights (McAuley, CF) are learned from millions of events. 137 files cannot learn a weight; they can carry a word.

  3. The condition is a first-class field on the edge.

    Debian [!i386] / <!nocheck>; the tritone substitute works because it keeps the 3rd and 7th and resolves to I; Carbon “when not to use”; McAuley’s before/after-purchase stage; Alexander’s problem statement. Apollo’s when is right — but it must be a predicate the validator can read (over shape, prominence, cols), not prose, or it is Carbon again.

  4. Substitutes, complements and conflicts are three relations.

    Provides / Recommends / Conflicts; substitutes / complements; synset / meronym / antonym; isSimilarTo / isRelatedTo; “said to be the same” / “different from”. Debian says it outright: similarity is not a reason for Conflicts. Apollo has the negative (mustNotNeighbour) and the complement (commonPattern, groupsWith) — it lacks only the substitute.

  5. Name the role, not the pair.

    Debian virtual package; WordNet synset; ISO preferred term (USE → one canonical). A brief asks for a role (“status surface”); components declare provides: status-surface; substitutes are co-providers. O(n) declarations instead of O(n²) edges, and complements hang off the role once. The tie-break priority (update-alternatives) lives here too.

  6. Author one direction; derive the reciprocal; forbid chaining.

    ISO 25964 requires BT↔NT, USE↔UF reciprocity and software enforces it; SKOS makes closeMatch non-transitive to stop “compound errors”; Liskov and TI “or better” are one-way. Apollo’s $differsFromStatCard is a one-way Liskov statement that should stay one-way.

07

Not worth copying

Five things the sources do that Apollo should not.

  • A 0–1 weight on an authored edge. No authored system in the table uses one. McAuley’s and CF’s weights are learned from ≥10⁸ events; with 137 metas a decimal is an opinion with false precision, and it invites the chaining SKOS forbids (0.8 × 0.8 = 0.64 looks like a fact). Use the four-word TI ladder. [S1][S4][S18]
  • Transitive equivalence. SKOS makes exactMatch transitive and closeMatch not, for “compound errors”. Apollo should make nothing transitive: kpi → stat → status is exactly a compound error (the series is lost at the first hop). [S1]
  • Relatedness derived from naming or folders. Figma’s “related = same slash path”. Apollo’s $family already does this; it is not a substitution signal. [S9]
  • The full lexical relation set. WordNet’s troponym/holonym/entailment, Debian’s Pre-Depends/Breaks/Enhances/Built-Using — each earned its place in a system with 10⁵ nodes. Apollo needs three relations and a role. Every extra key becomes another $-prefixed spelling (130 today). [S2][S15]
  • Prose conditions. Carbon’s “when not to use”, Alexander’s problem statements, ISO scope notes: correct, human-only. Apollo already has 25 files of this ($differsFrom…, 8 spellings). A when that the validator cannot evaluate is the same prose in a new key. [S13][S17]

Also not copied: semver. Versions are about the same component over time, not about substitutes; Apollo’s packs are releases (designer-skills v1.0.6) and that vocabulary is already spoken for. [S14]

08

Decide

Ruling-shaped questions.

None of these is ruled here. Each names the options and what the research leans toward.

  1. Grade as a four-word ladder, or a 0–1 weight?

    Options: (a) drop-in · same-shape · same-answer · similar, derived from FFF comparison and overridable; (b) an authored float as in the META proposal. Research: every authored system chose (a); floats only where learned. Leans (a).

  2. Pairwise instead-of edges, or a provides: role list Dave owns?

    Roles are a vocabulary (like chart-intents.json, five words) — someone must own its size. Debian, WordNet and ISO all name the role. Leans roles, with instead-of only for exceptions. Cost: Dave rules the role list.

  3. Is when prose, or a predicate over shape, prominence, span?

    Prose = Carbon (human-only, already 25 files of it). Predicate = Debian [arch], C9-readable. Leans predicate; the field list is then a ruling too.

  4. Author both directions, or author one and derive the reciprocal?

    ISO 25964 requires reciprocals and has software enforce them. Leans: author one way, validator derives; Liskov-style one-way statements ($differsFromStatCard) marked non-reciprocal.

  5. Promote mustNotNeighbour to not-with with a required slug?

    50 of 69 entries are ref:null prose. Debian and Wikidata both keep the negative explicit and addressable. Leans yes; the 50 notes are the backlog.

  6. Who owns the 1100 alternative — the band (template) or the chart?

    update-alternatives puts the group on the facility (vi), not on a provider. Leans band. This is also the W2 “fit must move into the chart components” tension (#248): the fit moves to the chart; the choice stays on the band.

  7. Is any of this worth doing before the SH demo (≈09-19), or after?

    The META report’s cheapest true thing (rails dial + data-shape) is unchanged by this research; the research only changes the shape of the weight (word not float) and adds the role. Dave’s call, in Dave’s words: “it might not be the solution”.
