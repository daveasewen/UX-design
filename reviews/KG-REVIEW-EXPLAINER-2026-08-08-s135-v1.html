1 · Near-miss node

35 of these

The graph has a pattern node whose name contains a component's name. Question: is it secretly that component, or its own thing? Example — a pattern called "card-grid" mentions cards:

Today — two separate nodespattern:card-grid (a layout idea) component:cards (the component) — no link between them
→
Default: LEAVE DISTINCTpattern:card-grid stays its own node component:cards untouched (a pattern that MENTIONS cards is not cards — your graph-mark ruling, same logic)
Default: change nothing · sole exception proposed: context:card = EXACT name match → merge into cards

2 · ref:null prose edge

98 of these

A rule like "never put an Alert next to a Toast with the same message" exists as an edge, but its target is written as free TEXT, not a link to the toast node. The text was kept, the link is null. Example from alert.meta.json:

Today — edge points nowheremustNotNeighbour: ref: null note: "Toast (same message twice)"
→
Default: PROMOTE when the name is exactmustNotNeighbour: ref: component:toast ← now a real link note: "same message twice"
Default: promote ONLY rows whose note names an existing node verbatim (the amber-flagged ones) · vague ones ("a second chart…") stay null — declared, not invented

3 · governedBy candidate

47 of these

Should a past ruling of yours be attached to a component, so anyone touching that component sees it? Example — does ruling ds-034 (the button/primary scope question) belong on button?

Today — no attachmentbutton.meta.json: governedBy: [] ds-034 says: "…measure the other 35 colliding names…" (mentions button)
→
Default: ATTACH only on hard evidenceattach IF ds-034's own governs list names button's file. A ruling that merely MENTIONS a component does not govern it.
Default: attach only where the ruling's governs list already names the file · no guessing from prose

4 · Token-claim split

5 samples (sets the grammar for all future ones)

Some token values have your decision prose fused INTO the value field. Machines then can't read the value cleanly. Example — button secondary text colour:

Today — value and story fusedlabel: "text/on-inverse (NOT text/reverse) — secondary inverts to a light fill in dark… #FFF light / #333 dark (decision: Dave 2026-06-19)"
→
Default: SPLIT value / note$value: "text/on-inverse" $note: "NOT text/reverse — inverts to a light fill in dark… (Dave 2026-06-19)" — nothing deleted, just separated
Default: bare value in $value, full story preserved in $note · this is the value/$note split already sitting in your queue
