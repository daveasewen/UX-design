Apollo hit-area standard — ✓ RULED + enacted 2026-07-24 · target/min=44 minted · 9-anchor built · gate owed

You're happy for a visible control to be smaller than its touch target, as long as an invisible hit area makes up the difference — and you added the key constraint: that invisible area must be able to anchor so the visible control still lines up with its neighbours (align top / bottom / left / right / centre — all nine combinations). This sheet checks that against the standards, proposes one Apollo rule + a token, and gives you a live matrix to feel the 9 anchors. The mechanism is already built into the segmented-control atom as the reference.

01What the standards actually require

SourceTargetThe rule (and its escape hatch)
WCAG 2.5.8 (AA)24 × 24Minimum. Has a spacing exception: an under-24 target passes if a 24px circle centred on it doesn't touch a neighbour's circle. This is the floor, not the goal.
WCAG 2.5.5 (AAA)44 × 44Enhanced. No spacing escape — 44 unless inline / user-agent / essential. This is the bar most banks aim at.
Apple HIG44 × 44 ptFirm recommendation for every control (~7 mm).
Material 348 × 48 dpBaseline (~9 mm). Icon/small controls may be visually 24 but the touch target extends to 48 via transparent padding — exactly this mechanism.
IBM Carbon44 × 44All interactive icon targets ≥ 44; pad with CSS to reach it.
HSBC (our repo)44 × 44Default (aid-009, ID-26). 24 is the exception (≥1px inactive gap). icon-005 is BLOCKING 44×44. Shared bands already sanctioned: tags/chips 12+20+12 = 44; links 44 unless inline.

The read: 44 is the consensus target (AAA, Apple, Carbon, HSBC) — Material's 48 is the only outlier and it endorses the very technique we want (visible-small + invisible-padding-to-target). Nobody requires the visible pixels to be 44 — only the hit area. That is precisely your position, and it's already how our tags, chips and links behave.

02The mechanism + your 9-anchor matrix — click the grid

One transparent ::before per control, sized min-width/height: var(--hit, 44px), so a small visible control still presents a 44 touch surface. Because a symmetric expansion would push the target past a container edge or a neighbour, the ::before anchors to any of 9 points — the visible control pins to that point and the padding grows into the free space. 03The Apollo rule — one default, one token, one axis

Proposed standard (recommended)

1 · Default target = 44×44. Every interactive control presents a ≥44 hit area (matches HSBC default, WCAG 2.5.5 AAA, Apple, Carbon). The visible control may be any size ≥ the minimum legible.

2 · Mint a target/min token = 44px (a semantic geometry role, sibling to how --phys-size is local). Controls bind --hit: var(--target-min); a theme or dense context could dial it (never below 24, the AA floor).

3 · The hit area anchors (9-point matrix). Default centre; .hit-* pins the visible control to any of the 9 positions so it aligns to neighbours while padding grows outward. Gate: a control whose visible box < 44 must declare an anchor (fail-loud if it shrinks without one).

Cost: one token + one gate rule + the (built) ::before mechanism. Upside: small, tidy controls everywhere (charts, toolbars, dense tables) that still pass AAA — with alignment under your control.

Alternative — AA floor (24) + spacing

Adopt only 24×24 + the WCAG spacing exception. Cheaper conceptually but weaker (AA not AAA), off HSBC's own 44 default, and the spacing maths is fiddly to gate. Not recommended for a bank aiming at "most accessible".

Paste-ready ruling (edit before I inscribe):
"Adopt the hit-area standard: default target 44×44, mint target/min = 44 (dial-down floor 24), invisible ::before mechanism, and the 9-anchor matrix with default centre. A visible control < 44 must declare an anchor (gated). Apply to the segmented-control atom + the small chart controls first." — or pick the AA-floor alternative, or change the default anchor.
