Cases 1 & 2 are the same atom drifting between 14 and 12px. Case 3 borrowed the name for a masthead eyebrow — it's scoped .h .tag so nothing breaks today, but the shared name is what blocks binding .tag to a type composite cleanly (it would drag the masthead label along at the wrong weight).

DECISION 1 — the atom's size

PROPOSED Two sizes, but named. .tag = 14px default (as in the Tags component); add .tag--sm = 12px for dense inline use (Account-card, List-items). Names the drift instead of leaving it silent.
A · Default + .tag--sm (recommended)

Both sizes are real needs — a roomy filter tag vs a compact status tag in a dense row. Make the small one explicit rather than an accident. One atom, one declared variant.

B · Normalise to one size

Force every tag to 14px (or 12px). Cleaner vocabulary, but overrides a real density difference — 12px tags exist because 14px crowds a list row.

DECISION 2 — the name clash

PROPOSED Rename the masthead label. .h .tag → .h .eyebrow (it's a category eyebrow, not a tag). Frees .tag to mean one thing and unblocks its binding.
  • It's a different component — weight 500, capitalised, 8px tall, non-interactive. Nothing about it is the tag atom.
  • Scoping hid it, naming clears it — .h .tag works, but the name overload is exactly what the blast-radius gate would make you register as a conscious collision. Cleaner to not collide at all.
  • Contained sweep — the 9 tranches + DataViz + Masthead share the identical .h .tag line; a single find-and-replace, then re-render to confirm no visual change.
