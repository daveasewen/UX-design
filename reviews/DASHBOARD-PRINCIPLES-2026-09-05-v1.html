Lane P3 added the sixth, locality, DP-28…29, plus one thought Dave asked to hold — the horizon/banding idea — validated, not encoded, not built.

Research digest

Six topics, one sentence per finding, source beside it

Primary sources where they exist (Nielsen, Few, SAP, IBM, Shopify, MOJ). Two claims that only secondary sources carry are marked as such.

A · Progressive disclosure / reveal

  1. Nielsen's definition: show only a few of the most important options first and disclose the larger set on request — the presence of a thing on the initial display is itself a signal that it matters.nngroup.com/articles/progressive-disclosure/
  2. The two things you must get right are the split between initial and secondary (everything frequently needed goes up front) and an obvious, well-labelled path to the secondary level; designs beyond two levels usually lose users.nngroup.com/articles/progressive-disclosure/
  3. Staged disclosure is the linear variant (wizards) and differs from progressive disclosure in that users are expected to reach every stage; a dashboard is the hierarchical kind, where most users never leave the first level.nngroup.com/articles/progressive-disclosure/
  4. SAP Fiori's overview page puts the filter bar in the page header and ships it snapped (collapsed) by default "since content is already available on the cards and users can start right away"; it expands on scroll or click and filters in live-update mode with no Go button.experience.sap.com/fiori-design-web/v1-50/overview-page/
  5. Shopify Polaris index filters toggle between a "View" mode and a "Filter" mode — the search field and filters are revealed by a button, and no more than two or three filters are promoted (pinned) into the visible bar.polaris-react.shopify.com/components/selection-and-input/index-filters
  6. MOJ (GOV.UK family) filter-a-list: the list appears unfiltered first, the filter panel starts hidden on wide screens behind a Show/Hide filter button, and filters do not persist across sessions unless a user need is shown.design-patterns.service.justice.gov.uk/patterns/filter-a-list/
  7. Carbon's filtering pattern separates batch (apply at the end) from live filtering, requires a dismiss-all when several categories are applied, and says the start state may differ per category.carbondesignsystem.com/patterns/filtering/
  8. Applied filters are shown as dismissible tags between the bar and the data with a clear-all beside them (Helios / HashiCorp, a secondary system echoing Carbon and Polaris).helios.hashicorp.design/patterns/filter-patterns

B · Density and stat rows

  1. Few defines a dashboard as the most important information consolidated on a single screen so it can be monitored at a glance — density is the point, not a cost.perceptualedge.com/…/Formatting_and_Layout_Matter.pdf
  2. Few's emphasis map: the upper-left is the most valuable region, lower-right the least; place the seven key metrics in the upper-left band and give the rest less room.perceptualedge.com/…/Formatting_and_Layout_Matter.pdf
  3. Few's failure 4, "sizing content larger than it deserves": size each section to be easily seen, then adjust sizes to reinforce relative importance — a KPI given a chart's height is the failure in one line.perceptualedge.com/…/Formatting_and_Layout_Matter.pdf
  4. Carbon's presentation-dashboard rules: strongest hierarchy at the top following the F-pattern, limit the number of metrics, and use white space to group rather than borders.v10.carbondesignsystem.com/data-visualization/dashboards/
  5. NN/g: dashboards impart at-a-glance information users act on quickly; length and 2D position (bars, lines, sparklines) are read preattentively, area and angle are not.nngroup.com/articles/dashboards-preattentive/
  6. SAP's analytical card puts a mandatory KPI header (title, value with unit, optional trend triangle and percentage) above the chart — the delta is a header property, not a second module.experience.sap.com/fiori-design-web/v1-50/overview-page/
  7. Secondary sources converge on 5–9 primary metrics per view; no primary source fixes a number, so this page treats the count as ADVISORY.clearpointstrategy.com/blog/kpi-dashboard-best-practices
  8. In-house: the KPI tile already has a compact variant "for dense boards where many tiles share a row" — the row form exists and is unused.knowledge/components/kpi-tile.meta.json · variants[compact]

C · Execute on the page + feedback

  1. SAP's overview page tagline is "view, filter, and take immediate action": micro actions let users react on the spot, and a role's overview needs at least three cards that are not all the same type.experience.sap.com/fiori-design-web/v1-50/overview-page/
  2. SAP's card header carries a counter "[items on card] of [total]" (5 of 40) and the whole header navigates to the full set — the "View all" is the header, and the count is mandatory when there is one.experience.sap.com/fiori-design-web/v1-50/overview-page/
  3. SAP action rules: at most six actions per card footer, right-aligned with overflow; an action with no input fires immediately and the item leaves the stream; one with input opens a dialog on the card; errors and confirmations show on the overview page itself.experience.sap.com/fiori-design-web/v1-50/overview-page/
  4. SAP list cards show at most five standard items (three extended) before handing off to the parent app.experience.sap.com/fiori-design-web/v1-50/overview-page/
  5. Salesforce's Lightning home composes an Assistant (up to ten overdue or ignored items), Today's Tasks, Today's Events and Key Deals — a tasks/exceptions surface is a standing region, not an afterthought.trailhead.salesforce.com/…/lightning_app_builder_homepage
  6. Atlassian dashboards keep a filter count on the Filters button and show a "No data" message with a Clear when a gadget's result is empty under the active filter.support.atlassian.com/…/add-and-manage-dashboard-filters/
  7. Carbon's exploration-dashboard rule: linked charts — a filter applied in one place updates every related view.v10.carbondesignsystem.com/data-visualization/dashboards/
  8. In-house: the app "button activity" pattern (loading → notification state) and the notification severity ladder are already ruled at ctkb-012 and ctkn-008; execute-on-page inherits both.knowledge/guidelines/_rules-index.json

D · Bento rhythm and hierarchy

  1. Few's failure 9, "enforcing a rigid symmetrical grid": equal quadrants are rarely useful; layout should follow the arrangement and sizing that communicates best, and asymmetry may be used deliberately to say things are not equal.perceptualedge.com/…/Formatting_and_Layout_Matter.pdf
  2. Few's failure 5, "separating content excessively": borders and fills should be just visible enough to group and no more — the counterweight that keeps an irregular wall from reading as clutter.perceptualedge.com/…/Formatting_and_Layout_Matter.pdf
  3. Müller-Brockmann: the grid is a system for hierarchy, rhythm and proportion, with text and images occupying whole modules — irregular spans are legal so long as every edge lands on a module line.archive.org · Grid systems in graphic design (PDF)
  4. Apple's keynote bentos: hierarchy is enforced by area — the largest tile carries the one message, and without one fact that earns the biggest tile every tile competes and the slide goes flat.deck.gallery/blog/apple-bento-grid-breakdown/
  5. Material 3's supporting-pane canonical layout fixes the primary/secondary ratio at roughly two-thirds to one-third — the 4/2 split as a named default.m3.material.io/foundations/layout/canonical-examples/overview
  6. SAP's card layout is a Z-flow of fixed-width columns with variable card heights — order carries importance where size cannot.experience.sap.com/fiori-design-web/v1-50/overview-page/
  7. In-house: the ruled bento grammar is a 6-column wall with data-c 1–6, container-query bands at 1100/820/520, and a mint-time squaring pass that promotes the last span so the wall closes (s217-D3/D7).knowledge/_render/gen_bento_matrix_217.py L1660–1690
  8. In-house: Dave has ruled the row floor (minmax(unit, auto), s245-D8) and the rung ladder B 120/240/96 (s245-D9) — so heights are settled, and the open axis is width.knowledge/_rulings.json · s245-D8 · s245-D9

E · Signal (preattentive) — lane P2

Vision science first, then the industries that turned it into rules (flight decks, control rooms), then the design systems' copy rules for status words.

  1. Healey & Enns: a display property is preattentive if a target is found in under 200–250 ms regardless of how many distractors surround it; the catalogue includes hue, intensity, size, length, orientation, closure, flicker, direction and velocity of motion — and a target defined by a conjunction of two features (red and circular) is not found preattentively but by serial search.csc2.ncsu.edu/faculty/healey/PP/
  2. The same page: motion and flicker pop out even against colour and shape — the one channel that beats hue — which is exactly why it must be the rarest.csc2.ncsu.edu/faculty/healey/PP/ · Table 1
  3. Few: contrast in any preattentive attribute "nags us to assign meaning", colour above all; his aesthetic rule for dashboards is to keep bright colours to a minimum "using them only to make a few items stand out" and to give the rest the same lightness so nothing else competes — and he names the commercial-jet cockpit as the model.perceptualedge.com/files/Dashboard_Design_Course.pdf
  4. Bertin's retinal variables: size is the only quantitative variable and value (lightness) is ordered, while colour (hue) is selective and associative but not ordered — so hue can say "which kind" and never "how much" or "how important".axismaps.com/guide/visual-variables (secondary, a faithful digest of Bertin)
  5. Airbus dark cockpit (A310 onward): an overhead pushbutton stays unlit when its system is normal and lights only when a fault needs the crew — "if the cockpit is dark, all is well"; the human-factors case is reduced scan load and faster reaction to the one thing that lit.airflow.blog · dark cockpit philosophy (secondary; primary is the Airbus FCOM, not public) · lean.org · the dark cockpit
  6. Alarm management (EEMUA 191 / ISA-18.2): rationalised alarms distribute roughly 80 % low · 15 % medium · 5 % high priority, and more than ten alarms in ten minutes at one operator position is a flood — the ancestor of "needs attention" as a budgeted, tiered surface rather than a wall of equals.industrialmonitordirect.com · IEC 62682 / ISA-18.2 / EEMUA 191 (secondary; the standards are paywalled — isa.org/…/isa18)
  7. GOV.UK tag: a tag shows status only, uses adjectives not verbs (a verb reads as clickable), colour may draw the eye to one especially important tag ("Urgent" in red), and absence is itself a status — an item without a tag is understood as incomplete.design-system.service.gov.uk/components/tag/
  8. Polaris badge: one word for the tone of an object, two only for a compound state ("Partially refunded"), always past tense; tones are success · attention · warning · critical · info, and no new badge word is minted while an existing one fits.polaris-react.shopify.com/…/badge
  9. In-house, already ruled: the two-red law s151-D1 and its green mirror s155-D1 make red/green text lawful in exactly one seat (monetary values carrying a symbol); s182-D3 makes the spark stroke semantic; neuro-036 puts movement last and neuro-014 caps bright colour at 20 % of the screen; col26-003 carries the sentence "if everything competes for attention, nothing stands out". What is not there: a tiering, a per-screen budget, a metric's good-direction, a motion role for monitoring pages, a written mono rule, and copy tiering.knowledge/guidelines/_rules-index.json · knowledge/_rulings.json

F · Locality: action beside object, feedback at the eye — lane P3

Perception first (why nearness reads as belonging), then the two HCI laws that price distance, then the systems that turned it into placement rules — and, for the held thought, what makes a horizontal band read as a zone.

  1. Palmer (1992) added common region to the Gestalt set: elements inside one bounded region group together, and the cue is strong enough to overcome proximity and similarity — a container, not just nearness, is what tells a reader "these belong".sciencedirect.com · Palmer, Cognitive Psychology 24(3) 1992 · nngroup.com/articles/common-region/
  2. NN/g proximity: elements close together are read as related and things set apart are assumed to play different roles — and proximity can overpower colour or shape similarity.nngroup.com/articles/gestalt-proximity/
  3. Nielsen's "closeness of actions and objects": users overlook a control that is "too far away from the objects they act on" and assume the feature does not exist; his iTunes case is a button in a separate coloured stripe at the bottom of a window acting on icons at the top — the fix he shows is the button beside the object.nngroup.com/articles/closeness-of-actions-and-objects-gui/
  4. Fitts's law (MacKenzie's Shannon form, MT = a + b·log₂(D/W + 1)): time to acquire a target grows with distance and shrinks with width, so an action far from the hand's current locus is paid for on every use; NN/g's applications — put the button below the last field, reduce the distance between sequential actions.nngroup.com/articles/fitts-law/
  5. Norman: natural mapping is spatial correspondence between control and effect (switches laid out like the lights they run), and feedback is continuous information about what an action did — both are broken when the control and the thing it changes are in different regions of the screen.nngroup.com/articles/natural-mappings/
  6. Raskin: a person has one locus of attention; anything the interface wants noticed must appear where that locus already is, and the more absorbed the person is the less they notice anything elsewhere — the case against feedback that lands in a corner the eye is not in.raskincenter.org · The Humane Interface
  7. Nielsen heuristic 1, visibility of system status: keep users informed with appropriate feedback within reasonable time; whether an action succeeded is "perhaps the most basic guideline" — and it is only visible if it appears where they are looking.nngroup.com/articles/visibility-system-status/
  8. GOV.UK error summary: on a validation failure show both an error summary at the top of the page (focused on load, each error linking to its field) and an error message beside each field — the pair covers the out-of-view case and the locus case at once.design-system.service.gov.uk/components/error-summary/
  9. Material: a snackbar is for brief, non-critical confirmation; do not use it for critical, persistent or bulk errors, never as the only route to an action, and never stacked — errors that need attention go inline where the failure is.m1.material.io/patterns/errors.html · m1.material.io/components/snackbars-toasts.html
  10. Material's contextual action bar: when items are selected the top bar transforms into a bar carrying only the actions for the selection, and closes when the selection does — the action set is scoped to the object set, and its lifetime too.m2.material.io/components/app-bars-top
  11. SAP Fiori action placement: actions that affect the whole page go in the header toolbar, closing/finalising actions in the footer bar, and object-level actions on the object (table toolbar, card footer); groups ordered business → content → layout → generic, importance left to right.sap.com · Fiori action placement · experience.sap.com · toolbar overview
  12. Polaris card layout: a card is header · body · footer; the header carries the action that modifies the card's contents, the footer the call-to-action; the point of the fixed structure is that merchants learn to attach meaning to places — the surface an action sits on is part of its meaning.polaris-react.shopify.com/patterns/card-layout
  13. For the held thought — Tufte, Envisioning Information ch. 3, layering and separation: clutter is a design failure, not a data property; separate layers by value, weight, texture or size so they do not compete, and beware 1 + 1 = 3 (two edges make a third thing between them). A tonal band is a layer; two bands make an edge.eclass.uth.gr · Envisioning Information (PDF)
  14. For the held thought — Bertin: the two planar variables (x, y) are the richest of the eight; a horizontal band is a y-interval carrying value (lightness, ordered) — so bands can say "above / below" and "lighter / heavier" and never "which kind" without a second variable.cs.stonybrook.edu · Bertin, Semiology of Graphics (lecture digest) (secondary)
  15. For the held thought — W3C APG landmarks: every perceivable area of a page, "which designers typically indicate visually using alignment and spacing", gets a landmark; banner and contentinfo are one-per-page and top-level, main one-per-page — the sky / field / ground split already has a programmatic name.w3.org/WAI/ARIA/apg/practices/landmark-regions/
  16. In-house: aid-004 (proximity: labels close to controls, form errors close to their fields, reflow keeps related content directly after its section); acd-023 (added content placed AFTER its trigger, focus moved or announced); ctkn-004/011 snackbar scope and placement; toast.meta.json antiPatterns (an error toast; an action that exists only in the toast); popconfirm.meta.json ("if the object is off-screen … the pattern should be a Modal"); acd-005 landmarks; edges triggeredBy (13/137 metas, 2 resolved refs) and groupsWith (s245-D7). What is not there: a rule that the action sits on the surface it acts on; a rule for where feedback lands relative to the trigger; any word on tonal bands as zones._rules-index.json · knowledge/components/*.meta.json

Rationale

DP-03reveal

HELDhorizon / banding

The page as a landscape: a light band above (navigation, title, controls — "white controls all below"), a field in the middle (the work), a dark band beneath (the footer as ground); a change of colour in a band reads as a change of state, the way a red horizon reads as morning or nightfall. Dave: "maybe hold this thought I'm not sure it's useful, unless you [find] something that validates it." Held, not proposed as a DP.

What validates it
Three things, all primary. Common region (Palmer 1992): a tonal band is a bounded region, and it groups what is inside it more strongly than nearness does — so a band is a zone, perceptually, not a decoration. Tufte (layering and separation): layers separated by value do not compete, and two edges make a third thing — which is why a page reads calm with three bands and busy with six. Landmarks (W3C APG): the sky / field / ground split already has names — banner (one, top, full width), main (one), contentinfo (one, bottom) — and the APG's own instruction is to derive them from the areas designers indicate "using alignment and spacing"; Dave's bands are the visual half of a split the a11y layer already requires. Bertin adds the limit: a band carries position and value (ordered), so it can say above/below and heavier/lighter, and cannot say which kind without a second variable — the red-horizon half of the thought (colour = state change) is a signal question and belongs to DP-19/21, not to banding.
Already encoded
The structural half: all seven app-shell snippets carry header · nav · main · footer[role=contentinfo]; showroom/index.json has a shell level with the seven shells; acd-005 makes landmarks ADVISORY; the masthead chrome is ruled per theme (s230-D2 logo defaults on light/dark chrome — so the sky already has a tone). The signal half: s151-D1 / s155-D1 / DP-19…27.
Not encoded
A tonal rule: nothing says the three landmarks carry three values (light / field / dark) or that a page has a ground at all. The dashboard template has no footer (0 hits), so both baselines shipped sky + field and no ground. No rule names vertical banding (rail / field) as a zone either, though the side-nav and nav-rail shells do it in practice. "Horizon", "banding", "zone" — 0 hits in rules and rulings.
At most
ONE advisory line, if Dave wants it and only then: "A page shell carries its three landmarks as three tonal bands — banner, main, contentinfo — and a dashboard has a ground." That is the whole proposal. No new component, no dial, no rail, no gate, no id until ruled — and Dave's own "maybe hold" stands until he says otherwise (RSQ Q16).
