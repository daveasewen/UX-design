Specimen-chrome section labels — treatment

The little headings that caption each demo inside a reference file — "Inline — dot + label", "Transaction list — live". This picks one treatment for all of them, and shows it above real components in every state.

Review copy · 2026-07-18 · demo scaffolding only — no product / component impact

PROPOSED — for your sign-off Full strength, no muting. 12px, --text, weight 400. Opacity muting dropped entirely. Each label stays a semantic <h2> (document structure / screen-reader navigation) — only the visual weight changes.

WHY NOT MUTED

  • The current fade is opacity:.55 — opacity is untokenised, so it dodges the contrast gate entirely and can't be governed.
  • Opacity multiplies whatever is behind it — on any tinted or dark specimen surface it goes muddy and unpredictable, unlike a real colour.
  • A section label is document structure, not a de-emphasised aside — full strength reads honestly as "this is a section," which is what an <h2> is.

SCOPE — WHAT ACTUALLY CHANGES

A single standalone utility .spec-h (12px / --text / weight 400), defined once and not part of any canon type composite — specimen chrome isn't product type. Each affected file's inline h2{…} loses its font-size + opacity; margins stay. Files touched:

filenowafter
Avatar, Badge, Links, Notifications, Selection-controls, Tagsh2 12px, opacity .55.spec-h 12px, no opacity
List-items, Status-indicator.spec-h 14px (from earlier fix).spec-h 12px full-strength
Buttonh2 14px, opacity .6.spec-h 12px, no opacity

No effect on any component, token, or product output. Blast-radius gate stays green; .spec-h is a scoped class, not a global element. Nothing is committed until you sign this off.
