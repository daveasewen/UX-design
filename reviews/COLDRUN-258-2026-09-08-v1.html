Findings

Each one fact, and the file that proves it.

  1. The skill's own step 5 fails the skill's own step 7a.

    Rule 7a: "Bento-first means you splice the snippet … start from knowledge/snippets/Template-dashboard-bento.reference.html." Step 5: "Prove it. Run the gates … python3 knowledge/_validate_screen.py." Doing the first makes the second impossible. Copying the pack's own unmodified Template-dashboard-bento.reference.html to a scratch file and running the pack's own copy of the gate on it prints compose: ❌ 146 hex colour(s) in <style>; redefines canon class(es): ['c-bento','c-bento__caption','c-bento__grid','c-bento__tile'] → RESULT: FAIL ❌. Every snippet ships an AUTO-TOKENS ramp of literal hex inside its own <style>; the compose gate counts them as rogue. My spliced page reports 256 because it carries four snippets' worth. #246 recorded the same shape at 281 hex and got green only by abandoning the splice model entirely at iteration 2 — so this is unchanged and it is structural, not a build error.

  2. Rule 2a's premise is false for exactly the components the prompt asks about.

    Rule 2a: "Every snippet whose component carries behaviour declares its ADDRESS in knowledge/components/<slug>.meta.json (behaviour.script)." 21 of 136 metas in the zip carry a non-null behaviour key. data-grid.meta.json, filter-toolbar-bar.meta.json and sidebar-nav.meta.json have no behaviour key at all — the key is absent from their top-level key list — yet all three snippets ship a real, working <script> (17,594 / 5,403 / 3,908 bytes). So _validate_receipt.py, which "reads the meta and checks the page loads what it names", has nothing to check for the three components that carry the page's entire interactivity. Same for kpi-tile, stat-card, segmented-control, tabs, quick-actions, chart-combo, chart-line, pagination, dropdown, search-field, tags and app-shell-side-nav — 15 of the 17 dashboard-relevant slugs checked.

  3. The filter toolbar cannot filter, and nothing in the pack can make it.

    Filter-toolbar-bar.reference.html lines 381–455 are its entire behaviour: Search-field's clear button, Dropdown's open/choose, Segmented-control's indicator, Tags' dismiss. Not one line reads or writes a dataset. Driven: selecting "Northgate UK plc" left the grid at 8 rows, the lead KPI at £184,205,100.10 and every chart bar height byte-identical. Rule 2a — "author no JS … never write a handler yourself" — forbids the ~14 lines that would connect it. This is #246's finding 1, reproduced unchanged against v1.0.7.

  4. Navigation is a highlight, by the snippet's own declaration.

    Sidebar-nav.reference.html line ~301: e.preventDefault(); // href="#" is a specimen stub, not a destination. All 7 links move aria-current and change nothing else (main_text_len_changed:false, url_changed:false). The masthead's 4 links have no script at all and never move aria-current off "Accounts". A prompt that says "make navigation work" has no component in the pack that can satisfy it.

  5. The template's demo chrome is labelled removable and is not safe to remove.

    Template-dashboard-bento.reference.html line 896 marks the .demo-bar "demo chrome only — not part of the template", and line 1784 marks its script "DEMO CHROME. Not the template." — but the script is unguarded: var btn = document.getElementById('themeBtn'); btn.addEventListener(…). Deleting the markup the snippet tells you to delete throws Cannot read properties of null (reading 'addEventListener') on load, plus Cannot set properties of null (setting 'textContent') from reportWidth() on every resize. Eight uncaught page errors in the frozen arm. Removing the bar also removes the only theme toggle — the built page has no dark-mode control, and the dark renders on this page were produced by setting data-theme from outside.

  6. Splicing two snippets collides their symbol ids silently.

    Sidebar-nav and Template-dashboard-bento both define <symbol id="ic-account"> with different artwork — a card/wallet in one, a person in the other. Copied verbatim as rule 2 requires, the first definition wins for every <use href="#ic-account"> on the page, so the sidebar's "Accounts" row renders the wrong glyph and nothing warns. icon-source passes: ✅ all paths library-matched — both glyphs are real library assets, so the gate cannot see the collision.

  7. Every snippet ships a page-level body{} rule, so splice order decides the layout.

    Filter-toolbar-bar, Data-grid and Sidebar-nav each declare body{margin:0; padding:2.5rem; …}; the template declares body{margin:0; padding:0; …}. Concatenated in the order the skill implies, the last snippet's 2.5rem padding wins over the template's zero. I dropped those three rules by hand as a marked splice edit. Nothing in the skill mentions this, and no gate catches it.

  8. The screen gate refuses to run on a page name it has not seen before — inside the repo.

    Run on a fresh path in the repo: ⛔ SCREEN-GATE INDEX REFUSED — untracked subject: _screen-gate/tpl-unmodified.md … Commit the subject. It also keys its ledger on basename, so a page called dashboard.html anywhere in the tree overwrites the tracked row for any other dashboard.html — which is what happened here and had to be restored by hand. The refusal is repo-only: the same gate inside the unzipped pack ran clean on a brand-new filename, which is the condition a consumer is actually in.

  9. Only one of the six grill questions has a declared default.

    ADS-grill-me gives a default for Q1 only — "the build will use Mono, and it will say so". Q2 through Q6 (light/dark, density and width, brand assets, real vs placeholder data, fixed and off-limits) declare no default anywhere in the file, while the skill's own contract is that "a skipped question is written down as skipped, and where a default has to be used it is said out loud". In the blind condition all six are skipped, so five of them were answered by my judgement with nothing to cite. The zip also has no briefs/ and no brief-template.md, though the skill says "Use the shape in brief-template.md, beside this file".

  10. The skill name and the command name disagree.

    The frozen prompt is /generate-from-canon. The directory is still skills/generate-from-canon/, but the frontmatter is now name: ADS-generate-from-canon, and every cross-reference inside the skills uses the ADS- form (ADS-grill-me, ADS-draft-a-new-pattern, ADS-check-with-gates). The prompt still resolved, so this is a naming seam, not a break — but the demo prompt and the pack's own vocabulary no longer match.

  11. The dashboard template ships the chart engine but not the chart's legend.

    Chart-combo.reference.html carries two behaviour partials: dv-behaviour (19,965 B) and dv-legend (15,313 B). Template-dashboard-bento's behaviour.partial is ["dv-behaviour","dp08-anchor"] — dv-legend is not in it and its markers appear nowhere in the template. So the dashboard every build starts from has an animated, fitted, tooltipped chart with no legend and no series controls. This is the residue of #246's finding 3: the engine landed, the surrounding controls did not.

  12. Reading the template costs more than a blind consumer will spend.

    Template-dashboard-bento.reference.html is 1,801 lines / 123,798 bytes, and rule 7a makes it mandatory reading for every dashboard. Reading it whole is roughly 35K tokens before a single component is chosen; Chart-line is 108,462 bytes and Chart-donut 90,977. In VS Code, with no way to render and check, a model that reads these in full has spent its budget on one file, and a model that skims them is guessing at exactly the markup rule 2 forbids it to re-draw.

For Dave

Ruling-shaped questions

Not answered here. Each one is a thing only you can decide, and each is blocking something named.

  1. Does "make the interactive elements work" mean cross-component wiring, and if so, who is allowed to write it? Rule 2a says the builder authors no JS. Nothing in the pack wires one component to another. Either the rule gets an exemption, or a wiring component/partial has to exist, or the demo prompt's second sentence is a promise the system does not make. Three different roadmaps.

  2. Should the compose gate stop counting a snippet's own AUTO-TOKENS ramp as rogue hex? Today the pack's own unmodified template fails the pack's own gate at 146 hex. Every faithful splice inherits it. Fixing this is a gate change; not fixing it means step 5 of the skill can never print green for a spliced dashboard.

  3. Is persistence in scope for v1.1? It has scored 0 in both baselines, no rule mentions it, and it is one of the three words in your #246 brief ("richer, fuller and more persistent"). It cannot be measured into existence.

  4. Should dv-legend join template-dashboard-bento's behaviour.partial? The engine is in; the legend and series controls are one line of meta away, and their absence is what still reads as "partially retrieved charts".

  5. Is one chart the right default for a dashboard the stakeholder sees first? Eight chart components ship stable and unused. The template's shape, not the model's choice, is what put one chart on the page.

  6. Does the demo prompt become /ADS-generate-from-canon? The command and the skill name diverged at #257. Both currently resolve; the frozen prompt should probably say one of them on purpose.

  7. Should the six grill questions each carry a declared default? Only Q1 does. In the blind condition — which is the VS Code condition — five answers are the model's judgement with nothing to cite, which is the opposite of what the skill promises.

  8. Should the template's demo chrome be guarded, or removed from the shipped snippet? It is labelled "not part of the template" and its script crashes when you act on the label. Eight page errors in a stakeholder demo is a bad first frame.
