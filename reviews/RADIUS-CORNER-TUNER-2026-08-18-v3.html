Segmented-control scale tuner — 2026-08-18 v3 · dimension-first · four steps

v2 tuned corners with padding as a side dial. v3 turns it round, per Dave at #200: the segmented control has four scale steps and the tuned input is the control's total height — 24 / 36 / 44 / 48 px by default. Padding scales inside each step, container radius is set per step, and the thumb radius is never typed: it derives as container − padding (s200-D1 clause c). The page derives live so you can tune; the export is a mint draft of concrete numbers — no runtime derivation anywhere (s200-D1 clause a).

What this page decides

  • Total height per scale step (four steps, 4px increments).
  • Padding per step (2px steps, s200-D1 clause d).
  • Container radius per step — and whether one radius can serve all four.
  • The derived thumb radius that falls out of the two above.
  • The names of the four steps (see the label note below).

What this page does not do

  • Nothing mints here. The export is a draft; it mints only if you paste it and it is enacted through the normal route.
  • The existing small / medium / large tokens (2 / 4 / 6 with thumbs 18 / 16 / 14) stand on disk unchanged until then.
  • No other theme is touched — s200-D3 scope is console-only, and mono / legacy / supercharge have no container entry at all.
  • No formula is ruled. The derivation is a tuning aid and a mint-time step, not machinery.
