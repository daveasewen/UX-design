The three differences, named

Fable — Arm A authored 14 lines of glue

Its blind arm met "make filtering and navigation work" by writing handlers, which rule 2a forbids, and reported the violation. Result: masthead nav and a currency filter that actually filter.

Opus — Arm A authored none

Its blind arm carried each component's own <script> verbatim instead: sort, filter, pagination, selection, edit-in-place, tabs and the chart engine all arrive from the library. The three lines Opus does author appear in Arm B, after a render showed an invisible control, and are flagged as a rule-2a violation on the page.

What the library did to both: neither arm could wire the toolbar to the grid without authoring, because Filter-toolbar-bar.reference.html L388-405 only writes the trigger label. Fable authored and got a working currency filter; Opus did not and shipped a decorative toolbar. Same defect, two different honest answers.

Fable — went green by leaving the splice model

At iteration 2 lane B switched to canon.css-linked .cn-* composition and both gates exit 0 at iteration 3.

Opus — stayed spliced and both gates stay red

Arm B still fails compose on 188 hex colours and a .c-bento redefinition, and fails the receipt gate for having no receipt. A control run proves the gate is failing the library, not the page: the gated template snippet itself fails the same two clauses (finding 04).

Fable — blind defects: a truncated CSS copy and a serif fallback

A stacked toolbar from a CSS copy that stopped at L231, and tabs rendering in a serif because the tab rule depended on a body font the template does not declare.

Opus — blind defects: a demo width and a behaviour collision

A 640px demo dial narrowed the whole page, and two copies of the segmented atom on one page fought: the toolbar's inlined handler set aria-pressed as the click bubbled, so dv-behaviour.js's early return killed the chart's sort switch.

What the library did to both: all four blind defects are the same class — a snippet's demo scaffolding, or a duplicated atom, leaking into a composed page and being invisible to every gate. Two models, four different symptoms, one cause.

Findings

Each one a fact and the file that proves it

  1. Rule 2a's behaviour address is unpopulated for every component this dashboard needs.

    The skill says a behaving component "declares its ADDRESS in knowledge/components/<slug>.meta.json (behaviour.script)". A builder that follows that literally finds nothing and ships a dead page. This build has working interactions only because it went looking for a <script> in the snippet body, which no rule tells it to do.

    20 of 137 metas carry a behaviour key. None of data-grid, filter-toolbar-bar, tabs, sidebar-nav, segmented-control, chart-bar, chart-line, chart-donut, chart-combo or template-dashboard-bento is among them. Probe: outputs/baseline-246-opus/arm-A-blind/READ-LOG.md §5 G-1.

  2. The bento template ships its chart with the attributes of an interactive chart and none of the machinery.

    Every dashboard starts here, by rule 7a. The template splices Chart-bar's rects complete with data-grow="up", animation-delay, data-tip, tabindex="0" and role="img" — and carries no @keyframes dvGrowY, no .dv-animate, no .dv-tip, no controls and no script. The attributes are inert. Recovering the layer cost a second file of 1,384 lines.

    Template-dashboard-bento.reference.html L931-936 (the rects) against a grep of the same file for keyframes|dv-animate|dv-tip|dv-csv|dv-tablepanel|fitCharts — all ABSENT. This is Dave's "the charts are only partially retrieved", located in the file.

  3. Three snippets on one page carry a demo width, and one of them silently ate two thirds of the viewport.

    Tabs.reference.html L80, Data-grid.reference.html L144 and Filter-toolbar-bar.reference.html L256 each size themselves from a --demo-width fallback. s210-D3 rules that the container decides. The blind arm carried all three faithfully and rendered a 1440 page inside 576 pixels, with every gate green over it.

    .tabs{ width:var(--demo-width, 640px); max-width:100%; } — Tabs.reference.html:80. Measured: .tpl-wall 576px of 1440 (arm-A-blind/drive.json), 1376px after the one-line fix (arm-B-sighted/drive.json).

  4. The composed-screen gate fails the library's own gated template on the same two clauses it fails this page on.

    A page built by obeying rule 2 — splice the snippet — cannot pass compose, because the snippets' own theme blocks are raw hex and the bento grammar the template tells you to copy is a canon-class redefinition. This is not a property of the page; it is a contradiction between two rules, and it was proved by running the gate on the template.

    Arm B: compose: ❌ 188 hex colour(s) in <style>; redefines canon class(es): ['c-bento', 'c-bento__caption', 'c-bento__grid', 'c-bento__tile'].
    Control, same gate, on knowledge/snippets/Template-dashboard-bento.reference.html: compose: ❌ 130 hex colour(s); redefines canon class(es): ['c-bento', 'c-bento__caption', 'c-bento__grid', 'c-bento__tile'] — RESULT: FAIL. Lane B reached exit 0 only by abandoning the splice model at its iteration 2.

  5. Two copies of the segmented atom on one page, and the older copy silently disables the newer one.

    Filter-toolbar-bar inlines the Segmented-control handler and binds it to every .seg button on the document. It sets aria-pressed="true" as the click bubbles. canon/dv-behaviour.js then receives the same click and its first line is if (btn.getAttribute('aria-pressed') === 'true') return;. The chart's sort switch never runs. Nothing errors; the console is clean.

    Filter-toolbar-bar.reference.html L413-416 vs knowledge/canon/dv-behaviour.js L212. Measured Arm A: chart sort switch — orig off=False, desc on=False. After scoping the toolbar's copy to .ftb-view: orig off=True, desc on=True.

  6. A component revealed by a tab measures zero and never re-measures, and in dark mode that makes its label disappear.

    The segmented indicator is positioned by getBoundingClientRect at load. Inside a hidden tab panel every rectangle is zero, so the white indicator has width 0, and .seg button[aria-pressed=true]{color:var(--on-sel)} paints #333333 text on the #1F1F1F surface it was supposed to sit above. The pack has no lifecycle hook, no re-place entry point, and placeAll is bound only to resize.

    Arm A: .ind style.width = "0px" at first reveal; arm-A-blind/final-1440-dark-payments.png shows the sliver and the missing label. The three lines Arm B authors to fix it are the page's only authored JavaScript and are a declared rule-2a violation (ITERATION-LOG.md, B-i2-b).

  7. The filter toolbar filters nothing, in either arm, and could not without authoring.

    Every one of its five controls behaves correctly as a control — the dropdown opens, roves, commits a label; the chips dismiss with focus management; the segmented indicator slides — and none of them is connected to anything. The block is a control bar with no consumer.

    toolbar-probe.json: entity dropdown, currency dropdown, toolbar search, chip dismiss — all 24 results → 24 results, both arms. Filter-toolbar-bar.reference.html L393: choose() writes val.textContent and closes the menu. That is the whole contract.

  8. Nothing on the page survives a reload, and no rule anywhere asks it to.

    State inside a session is real: the grid's filter, sort, page and selection survive tab navigation because the DOM is never rebuilt. Across a reload everything resets. There are zero storage keys, and neither the skill, the metas nor the guidelines mention persistence.

    After reload the selected tab is t1 and localStorage.length === 0, both arms (drive.json, toolbar-probe.json). Dave's word was "persistent"; the library has no vocabulary for it.

  9. The chart's geometry is mint-time and the mint is not reachable from a build.

    dv-behaviour.js is explicit: "geometry is generated, never computed here". The generator is canon/gen_canon_bento.py's sibling in the dataviz pipeline and nothing in the skill points a builder at it. To put its own numbers on the chart the build had to read the baked scale off the snippet and extrapolate.

    knowledge/canon/dv-behaviour.js L180. _build/build_arm_a.py, bars() — the one function in the compositor that computes rather than slices, declared as Gap in READ-LOG §4.

  10. Six visual values had to be renamed to compose four snippets, and the library already knows this class of bug.

    --border means border/subtle (#E1E1E1) in the template and form/border/default (#808080) in the toolbar; .sep is a breadcrumb separator in one and a menu divider in the other. Put them on one page and one silently wins. The template's own header records the identical class at --grid-alpha and calls it "a sixth member for W-59's ledger". This build adds a seventh and an eighth.

    Template-dashboard-bento.reference.html L196-205 (the W-59 note) against Filter-toolbar-bar.reference.html L68 and L161. Renames declared in READ-LOG §3, A-e1 and A-e2.

  11. No page-level navigation behaviour exists anywhere in the library.

    The masthead every dashboard inherits is four <a href="#"> and a CSS aria-current underline. There is no shell-level script. In-page navigation had to be borrowed from tabs, an element. The masthead links are dead by construction in both arms and in both lanes.

    Template-dashboard-bento.reference.html L795-800 and L689-695 — markup and CSS, no script. app-shell-*.meta.json: no behaviour key on any of the six.

  12. Context was not the constraint for this model, so the pack's retrieval cost is untested by this lane.

    Dave's diagnosis is that VS Code retrieves partially. This run read every file it wanted: five snippets in full, the whole index, all 137 metas probed. If a real Copilot session cannot, the cause is the host's budget, not the pack's shape — and that is a different fix from the one the other findings ask for.

    READ-LOG §1, last row. Largest single reads: Template-dashboard-bento 1,172 lines, Chart-bar ~330 of 1,384, Data-grid 746, Filter-toolbar-bar 457.

Ruling-shaped questions

Only Dave can settle these. Nothing below has been decided.

1 · What does "persistent" mean on the scoring rubric — across navigation, or across a reload?

The two lanes measured the same two facts and scored the axis differently (Fable 0, Opus 1) because the word is undefined. Whichever it is, it decides whether #247 needs a storage contract or only a DOM one.

2 · Which rule gives way — rule 2 (splice the snippet) or the compose gate?

They cannot both hold: the gated template fails the gate. Either the snippets stop carrying their own theme blocks and start linking canon.css, or the compose gate learns that a spliced page is a legitimate shape. Lane B chose the first by iterating; this lane chose neither and reported the contradiction.

3 · May a composed screen author the glue that connects two components?

Rule 2a says no. A filter toolbar that filters nothing, a masthead that navigates nothing and a segmented control that measures zero are all the same consequence. If the answer stays no, something in the library has to grow a wiring contract; if it becomes yes, the rule needs a boundary so "glue" does not become "a hand-rolled component".

4 · Should behaviour.script be mandatory on every meta whose snippet carries a script?

Twenty of 137 carry it today and none of the dashboard set does. A gate that fails a meta whose snippet has a <script> and whose meta has no behaviour key would close finding 01 mechanically.

5 · Should --demo-width be forbidden in a snippet?

Three of the five snippets on this page size themselves from one, against s210-D3. A grep gate is a few lines. The alternative is that every consumer keeps discovering it by rendering.

6 · Should the bento template carry a whole chart, or an explicitly empty chart slot?

It currently carries neither: it carries a chart that looks whole in the markup and does nothing. Both options are honest; the present state is the one that misleads a builder.

7 · How many charts and how many groups does a dashboard get?

template-dashboard-bento.meta.json:12 already says group count is the designer's decision, never the builder's. The consequence is that every blind build ships the template's three groups and one chart, and "fuller" is unreachable by construction. Fable composed two charts, Opus one, and neither had a rule to appeal to.

8 · Is a duplicated atom (two .seg copies, two segmented handlers) a build error?

Today it is silent and it disabled a working control. W-59's ledger already tracks the CSS half; the JavaScript half has no ledger at all.
