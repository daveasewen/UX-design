--pri-hover: stored colour-equivalent vs re-derived at --alpha-68

reviews/PRI-HOVER-COMPARE-2026-08-17-v1.html · session #197 · BUILD ONLY — nothing promoted, no live token touched. Dave rules by eye.

What is being compared. The primary button's hover in canon renders as an operational opacity: .cn-button .btn.primary:hover{background:color-mix(in srgb, var(--pri-default) calc(var(--alpha-68) * 100%), var(--page));} (canon.css:1089). Separately, --pri-hover holds a stored colour-equivalent hex for colour-only / chromatic consumers — --surface-action-primary-hover, canon.css:467 (light) and :825 (dark). Those two hexes were derived at the retired alpha 0.70 (ADR-0009 / B-D3), before #99-D1 migrated the render to the 4%-ladder value 0.68. So the stored hex and the rendered hover no longer come from the same number. This page shows both, on the real specimen, in both themes.

The derivation basis (measured, not assumed)

MONO LIGHT --pri-default = --button-primary-background-default = --surface-action-primary = #1A1A1A (canon.css:466) --page = --background-default = #FFFFFF (canon.css:272) stored --pri-hover = --surface-action-primary-hover = #626262 (canon.css:467) MONO DARK --pri-default = --surface-action-primary = #FAFAFA (canon.css:824) --page = --background-default = --surface-digital-black = #1A1A1A (canon.css:816, :633) stored --pri-hover = --surface-action-primary-hover = #B7B7B7 (canon.css:825) ARITHMETIC (color-mix in srgb — straight per-channel mix of the gamma-encoded values): out = alpha * pri-default + (1 - alpha) * page LIGHT @ 0.70 (retired): 0.70 x 26 + 0.30 x 255 = 18.20 + 76.50 = 94.70 -> 95 = #5F5F5F LIGHT @ 0.68 (live): 0.68 x 26 + 0.32 x 255 = 17.68 + 81.60 = 99.28 -> 99 = #636363 <-- RE-DERIVED DARK @ 0.70 (retired): 0.70 x 250 + 0.30 x 26 = 175.00 + 7.80 = 182.80 -> 183 = #B7B7B7 DARK @ 0.68 (live): 0.68 x 250 + 0.32 x 26 = 170.00 + 8.32 = 178.32 -> 178 = #B2B2B2 <-- RE-DERIVED
Finding surfaced by the arithmetic, NOT ruled here. The dark stored value reproduces the 0.70 composite exactly (#B7B7B7). The light stored value does not: 0.70 over white gives #5F5F5F, but the stored hex is #626262 — which implies an alpha of ~0.6856 (solve 98 = a·26 + (1−a)·255 → a = 157/229 = 0.6856). So the light stored hex was never a clean 0.70 composite; it sits one step from the live 0.68 answer (#636363, Δ1 per channel) and five steps from the 0.70 one. The dark delta is the larger move: #B7B7B7 → #B2B2B2, Δ5 per channel. Stated as an observation for Dave's eye; no change made.
