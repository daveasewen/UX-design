Segmented control — four scales × four themes

Rulings on this page: s202-D1 (#202 — mono / legacy / supercharge inherit Console’s tuned segmented dimensions; radii 0) · s201-D5 (square themes: thumb = max(container − padding, 0)) · s201-D1 (xs/s/m/l dimension-first scales) · s201-D2 / s201-D3 (44 = hit zone, hit = max(44, visual)) · s200-D1 clause a (concrete numbers, minted, never live).
Values read at runtime from knowledge/canon/canon.css via the token vars — this page hardcodes no geometry. Page baked 2026-08-18. Version v2 (v1 was console-only).

What changed since v1. v1 showed console alone with numbers typed into the page. v2 shows all four themes, light and dark, on the real palettes from the built cascade, and every height, inset and radius is read out of the stylesheet — so if a theme fails to resolve a token, this page shows it rather than hiding it behind a typed-in number.

The asserts below are DRIVEN, not described. On open, the page measures the rendered control with getComputedStyle for every theme × scale, including the pseudo-element that carries the hit zone, and prints a pass/fail line per check.

Type size and label padding are still PROPOSED. No token exists for them; they are tagged PROPOSED and are not part of the s202-D1 mint.
In plain words
  • The three square themes now have the same sizes as Console. Same heights (24/36/44/48), same track insets (2/2/4/4). Only the corners differ.
  • Console is round, the other three are square. Console’s corners are 6/8/10/12 outside and 4/6/6/8 inside. Mono, Legacy and Supercharge are 0 and 0 — a square inside a square.
  • A square theme does not get a nudge of curve. The old proposed “floor of 2” would have rounded them slightly; s201-D5 rules it out. Squares stay square.
  • 44 is a finger, not a box. At xs and s the visible control stays small while the tappable area is stretched to 44. Turn the overlay on to see it.
Controls are live — click a segment, the thumb moves.
