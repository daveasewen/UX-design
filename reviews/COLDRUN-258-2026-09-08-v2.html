Findings

  1. The payments region renders broken, and nothing in the build could have told me

    At 1440 and 820, light and dark, the .dg renders about 400px wide inside a ~1300px tile, the #dgHint keyboard-help paragraph overlaps the table, and the Data-grid's demo state switcher (.dgseg, the Live/Loading/Empty buttons) is on the page as three full-width bars. Cause: the splice took Data-grid.reference.html L323–402, and L323 is the demo switcher, not the component; and .dg{width:var(--demo-width,760px)} (L144 of that file) is a demo dial that an inline --demo-width:100% did not override once the tile's own width participated. Every one of these is invisible without eyes — the gates pass composition, the console is clean, and the drive log reports the grid working correctly throughout. This is the residue of the VS Code condition after both rulings.

  2. A build that obeys rule 2 and rule 7a cannot pass _validate_screen.py. Unchanged from v1, and now proven twice

    The control run puts Template-dashboard-bento.reference.html, byte-unmodified, through the pack's own gate: compose: ❌ 147 hex colour(s); redefines canon class(es): ['c-bento','c-bento__caption','c-bento__grid','c-bento__tile']. Rule 7a orders a dashboard build to splice that file. Rule 2 orders it not to re-draw. So the failure is inherited, not authored — 147 of my 262 hex are the template's, and all four class redefinitions are. s258-D1/D2 did not touch this.

  3. The skill now states two requirements the surface it ships to cannot meet

    Rule 16 — "Open the console before you claim it" — and Procedure step 6 — "Load the page, read the console, then work every control and reload once" — both require a browser. Dave, #246: "we do not have vision in VS, and we cant install playwright". In this arm both were performed only after the freeze, as measurement. A VS Code consumer following the skill honestly reaches step 6 and has to either skip it or claim it. The skill gives no fallback wording for the skip.

  4. Rule 13 and rule 2 pull against each other, and the skill does not say who wins

    Rule 13 says one in-page DATA that every panel reads. Rule 2 says copy the snippet. But Data-grid.reference.html's script opens with its own 24-row const DATA literal (L478–L503) — a second data model inside the component. Obeying rule 13 therefore requires editing the snippet's script, which rule 2a now permits but rule 2 still discourages. I resolved it by replacing the literal and declaring the edit; the skill should say that is the intended resolution rather than leaving each builder to invent one.

  5. _validate_screen.py writes into knowledge/ from a subject under /tmp/

    The ledger is keyed on the page's basename, so gating /tmp/gate/dashboard.html overwrote the tracked row knowledge/_screen-gate/dashboard.md and flipped its line in knowledge/_SCREEN-GATE.md. v1 hit the same thing and restored with git show HEAD:. Three files are left for the conductor: knowledge/_SCREEN-GATE.md, knowledge/_screen-gate/dashboard.md, knowledge/_screen-gate/tpl-probe.md.

  6. The template the skill routes every dashboard to is declared unregistered by its own header

    Template-dashboard-bento.reference.html L8–9: "PROPOSED, NOT RULED, NOT GATED, NOT REGISTERED" — not in CATEGORIES, component-types.json, canon.css or _rulings.json. Rule 7a nonetheless makes it the mandatory starting point for "build me a dashboard". A consumer reading both is told to build on a file the pack disclaims.

  7. In mono, a monetary delta carries no colour, and only the arrow says which way it went

    Measured: the four .delta figures resolve to rgb(26,26,26) in light and rgb(255,255,255) in dark — ink, not the reds or greens of rule 6. That is mono behaving as documented (colour only in status and charts), and mono is what a skipped grill question defaults to. So the default theme is also the one theme in which rule 6's up/down colour rule is silent — the demo's headline numbers lose their at-a-glance direction unless the arrow is read.

  8. What was NOT invented, and stayed on the Gaps list

    Eight gaps are declared in outputs/coldrun-258-v2/arm-A-blind/GAPS.md. The load-bearing ones for a banking demo: no FX-rate or currency-pair component and no approve/reject action component for a payments queue, so the Needs-attention card can state a status but cannot act on one; and no entity switcher — an entity filter is not "acting as subsidiary X". kpi-tile.meta.json declares behaviour: null, so the sparkline geometry is authored with no address to carry.

One line, labelled as a judgement

06

Code creativity

Judgement. What the rewrite bought is the wiring between components that no single snippet can own: one filter change fanning out to a grid, four KPIs, a re-derived chart and two cards in a single pass, and the state of all of it reflected into the URL so the page comes back where it was left. A 2a-bound build could copy every one of those components and still not connect any two of them — the connective tissue is, by definition, code that belongs to no component, so the old rule forbade exactly the part that makes a dashboard a dashboard rather than a wall of specimens.

Ruling-shaped questions — not answered here

  1. Does a build that splices the template as rule 7a orders get to fail the compose gate? Today it must (F02). Three exits exist: exempt spliced AUTO-* runs from the hex/class check; fix the template; or accept FAIL as the expected verdict for a bento dashboard and say so in the skill. Only you can pick.

  2. Should rules 16 and step 6 carry a declared blind fallback? Something a VS Code consumer can honestly write — "console not read: no browser in this environment" — rather than skipping the rule silently or claiming it (F03).

  3. Is replacing a snippet script's own const DATA the intended way to obey rule 13? If yes, rule 13 should say so and name the pattern. If no, rule 13 cannot be met by any page that carries a data-grid (F04).

  4. Should the demo chrome inside reference snippets be marked so a splicer can find its edges? .dgseg and .demo-* carry the convention in comments only; a machine-readable boundary would have prevented half of F01.

  5. Is mono still the right default when the grill is skipped, given that mono is the one theme where rule 6's monetary red/green is silent (F07) — and this is the demo condition David Rice will see?

  6. Does the FX-rate / approve-reject / entity-switcher gap get filled before the demo, or does the demo route around it? It is the difference between a dashboard that reports and one that acts.
