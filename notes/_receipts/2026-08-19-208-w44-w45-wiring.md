### ① The sampler's exit-code blindness — **CLOSED** (verifier finding 1, the one that blocked wiring)

`rc` alone proves **runnability, not reproduction**: `git show`, `grep -c`, `find`, `ls`, `sed -n` exit 0 for *any* content, which is how `EVIDENCE GATE PASS` certified two rows the verifier had just proved false.

Two OPTIONAL row fields, **added, never substituted** — every pre-#208 row samples exactly as before:

* `expect_stdout_contains` (str) — substring of the command's stdout
* `expect_count` (int) — the last non-empty stdout line, parsed as an integer (`grep -c`, `wc -l`)

Typed in `_claimtable.py`, so a mistyped expectation is a **parse** failure, not a sampler surprise. An unparseable count is a LOUD failure, never a pass. **A row that declares an expectation is ALWAYS drawn** — it asked to be checked, so it is never left to the seeded sample. New selftest arms: contradicting stdout at rc=0 is caught; a true expectation reproduces; a wrong `expect_count` is caught; the true count reproduces; the forced draw bites in a 31-row table sampled at n=1.

## 3 · TWO THINGS I FOUND THAT THE BRIEF DID NOT PREDICT

**A · ⛔ The registry's `--run` never emitted 77 — a run that asked NOTHING exited 0 and read as green.**
The brief said *"verify that path actually receives the registry's 77 — the refusal is the test"*. It did **not**. Refusals were counted per probe, printed, and then **dropped at the exit**: `--run --probe P-3` (Playwright absent) → **rc=0**. That is the #193 confusion inverted — not a refusal counted as a failure, but a refusal counted as a **pass**, in the exact code path a build step was about to depend on. Fixed: *all selected probes refused and not one ran* → **77 + the `COULD-NOT-ASK:` line**. A full `--run` still exits 0; `--survey` still exits 0; the loader selftest still passes. Then driven end-to-end: through the real `_build_all` loop, that step printed *"COULD-NOT-ASK (exit 77) — declared refusal, build continues"* and the build carried on.

**B · An UNSAFE marker inside a FILE NAME made every claim about the commit script unverifiable.**
`grep -c PREFIX_ACK knowledge/_git_commit.sh` was REFUSED [UNSAFE] — the substring `commit` is in the **path**. Three rows of my own table hit it. `classify()` now matches action verbs on the command **with its path-like operands removed**, while redirects and `$(`/backtick substitution are still matched on the full string. `git commit` / `git checkout` / `git push` / a redirect are all still refused — both directions in `--selftest`. Same shape as NEW-2: a substring match standing in for a structural one.

Also closed, from the verifier's list: **finding 8** — `_registry.py --run` is now sampleable rather than refused as side-effecting, keyed **narrowly** on the registry's own directory, not on the word `--run`.
