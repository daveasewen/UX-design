## ★ THE HEADLINE — [107] read chain: PROVEN, and it is not one mechanism but three

The conductor's hypothesis (a real-token stamp measured differently in CI) is **PROVEN as
to the fact, REFUTED as to the reason.** `tiktoken` is not the measurer. It is the
**estimate fallback**. `_gauge_tokens.count()` returns `'real'` only from the Anthropic
token-counting API (`API-KEY.txt`) or from its content-keyed cache
(`knowledge/.token-cache.json`). **Both are gitignored** (`.gitignore:57,58`). CI therefore
has neither, falls through to `tiktoken`, and stamps every figure
`tape (cl100k ESTIMATE)` where the committed `_CHAIN.md` says `real`. The regenerated text
can never byte-match. This is **structural and permanent**, not flaky.

**Isolation, single variable.** In `/tmp/ci`-style shallow clone, unshallowed, nothing else
touched:

| step | env | `_gen_chain.py --check` |
|---|---|---|
| clone, no cache | no `.token-cache.json` | `✗ STALE` rc=1 |
| **+ copy `knowledge/.token-cache.json` in, nothing else** | cache present | `✅ FRESH … 16,094 real` **rc=0** |

One file, gitignored, flips the gate. That is the proof.

**Second, independent mechanism — the shallow clone.** `.github/workflows/gates.yml` uses
`actions/checkout@v4` with no `with:`, i.e. **fetch-depth 1**. `_gen_chain.build_verdict_line()`
runs `git show 18c7789:knowledge/_build_all.py` (`VERDICT_SHA`, `_gen_chain.py:146`). Measured
directly, same commit, two clones:

- full history → `⛔ **BUILD VERDICT: 75 of 117 steps green (#62, 18c7789) — 42 steps…**`
- depth 1 → `⛔ **BUILD VERDICT: 117 steps on disk — … COVERAGE is UNMEASURED (git show 18c7789:knowledge/_build_all.py failed rc=128 (fatal: invalid object name '18c7789'))**`

That line is embedded in `_CHAIN.md:35`. It is a **second sufficient** divergence: fixing the
tokens alone would not turn [107] green.

**Third mechanism, found while checking the dashboard — `outputs/` is gitignored.**
`gen_dashboard.py` embeds the live words of `knowledge/_governs.py --selftest`. Locally that
is *"4 checks fail across 2 rulings"*; in the CI-parity clone it is *"20 checks fail across
16 rulings"*, because 16 rulings' `governs` pointers aim into `outputs/…` and those files are
not in a checkout. So [59] cannot match in CI even when freshly generated.

### ⚠ A stale premise, in the workflow's own header
`gates.yml` lines 15–19 claim: *"`_gen_chain.py --check` now REFUSES on the estimate fallback
rather than silently under-reporting, so without tiktoken step [70] is honestly red, not
quietly green."* **Observed false.** With tiktoken present and the API/cache absent, `--check`
does **not** refuse — it rebuilds with estimate stamps and reports **STALE**, which is a
verdict about the *artefact* dressed over a fact about the *environment*.
[[assertion-propagation-gap]], [[measuring-tool-must-not-guess]].

### What the gate should assert instead — RECOMMENDED, Dave's to rule
When the method actually reachable differs from the method the committed artefact was stamped
with, `--check` must exit **COULD-NOT-ASK**, not STALE. `_build_survey.py` already has that
third bucket and it reads **0** today; this is exactly its case. Reporting the *measurement*
and never prescribing the region is the standing posture here.
