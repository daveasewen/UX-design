## What Hindsight is (read from the repo at 017b3f5, 2026-10-02, and its docs; paper arXiv 2512.12818, Dec 2025)

- MIT-licensed agent-memory server by Vectorize. Postgres + pgvector (or embedded pg0), an LLM for extraction, REST/SDK/MCP. Modes: Hindsight Cloud, self-hosted, or a local daemon (`hindsight-embed`, on a Mac needs a current Rust toolchain).
- Three operations: retain (an LLM extracts facts, entities, dates, relations), recall (semantic + BM25 + entity graph + temporal, fused by reciprocal rank, re-ranked by a cross-encoder), reflect (an agent reasons over mental models → observations → raw facts).
- Observations: background consolidation of facts into deduplicated beliefs, each with exact-quote evidence and a proof count, refined not overwritten; contradictions folded into a "was X, now Y" belief.
- Mental models / knowledge pages: a standing question whose answer the bank rewrites as it learns; reading one is a database read (no retrieval, no LLM). Pages carry a freshness signal — if newer memories in scope have not been folded in, the page is shown but not trusted. Pages are views, not storage: delete one and it re-projects. `hindsight fs mount` mirrors them as markdown.
- Coding-agents plugin: per-repo bank built from git history and past sessions, five seeded pages (component map, concepts, conventions, key decisions, initiatives), hooks into Claude Code CLI and ~20 other CLIs.
- Claims: LongMemEval 91.4%, LoCoMo 89.6% (conversational recall benchmarks). Its own docs: "Extraction is not fully deterministic — a borderline document can yield facts on one run and none on the next."

## Verdict: it cannot replace Memento; it can replace one layer of it, and it has four things worth taking

Why not a replacement:
1. It paraphrases by design. Retain turns words into LLM-extracted facts; observations are LLM-written beliefs. Memento's founding rule is the opposite: his words verbatim, quote never paraphrase (946 rulings in `_rulings.json`, each with the verbatim source). Hindsight has a `verbatim` extraction mode, but observations and pages are always synthesised.
2. It has no authority. Contradictions are reconciled by an LLM's judgement. In Apollo only Dave supersedes a ruling; "who said it" outranks "what is newest".
3. It holds beliefs, not obligations. Nothing like `_state.json` (1,189 items, close conditions, owner Dave/mine) or the gates that refuse a claim with no evidence.
4. It is a server, not files. The repo travels to the work machine and to designers as plain files + Python; Hindsight needs Postgres, an LLM key (or the Claude Code CLI) and, on a Mac, Rust. Cloud mode sends the record to a third party — not for HSBC work.
5. Its Claude hooks are for Claude Code CLI. Dave's seats are claude.ai cloud sessions and Cowork; the only route in is its MCP endpoint, which a cloud session reaches only via Hindsight Cloud or a tunnel.

What to learn (in order of value):
1. RETRIEVAL. `_search_core.py::score_record` counts stemmed token hits (original ×2, lexicon-expanded ×1) over a 93-line hand lexicon — no term weighting, no meaning match. That is the cause behind `unrun-search-indistinguishable-from-absent-record` (search with the record's vocabulary or miss). Take Hindsight's shape: BM25 weighting + a small local embedding leg, fused by reciprocal rank. Keeps the two-stage refs/verbatim fetch untouched.
2. FRESHNESS ON EVERY GENERATED SURFACE. Hindsight marks a page stale when newer memories in its scope are unfolded. Memento's worst failures were stale surfaces read with full trust (#118 stale mount, the GM header in the chain). Give `_CHAIN.md` and the handoff a generated line: "folded up to <sha>; N newer commits / rulings not in this view".
3. STANDING QUESTIONS AT BOOT. Mental models = fixed questions, answers kept current in the background, read for free at boot. Memento already does the shape by generation (`_CHAIN.md`, the OPEN WORK block). The lesson is to name the questions a cold seat asks and generate one short answer each, instead of reading banners. Boot was 134,612 at #313, 388 under the ceiling.
4. SOURCE-SPLIT BELIEFS. Its `per_source` scope keeps "what the commits say" apart from "what was decided in conversation". Memento's analogue: keep "Dave said", "an agent claimed", "a gate measured" as separate, queryable axes (the `status: observed` / `by: Dave` fields already exist; retrieval does not filter on them).

Also noted, smaller: near-duplicate reconciliation threshold (≈ the n-gram `_near_dupes.py` door, already advisory); per-bank "mission" (= the bar for what is durable); "Memory Defense" PII/secret scan on write (relevant if Memento ever ships to banking colleagues).

## ADDENDUM 14:25 BST — second research ask: move the graph to Neo4j? is Memento's graph hyper-relational?

His words, verbatim (Fri 14:01): "I have another research task for you, as Apollo is getting pretty big, do you think that would be any benefit to shifting the graph to a product like Neo4J or something else? Also is the graph for memento hyper-relational, does it need to be?"

Measured at the seat (importing `_build_kg_explorer.py` read-only, output to /dev/null, nothing written):
- The whole graph as the explorer assembles it: 6,317 nodes, 12,382 edges (121 declared nulls), 32 node types, 68 edge types. Base 1,075 / 1,709; additive families 5,242 / 10,673. Largest: evidence 1,850 nodes, rulings 946; evidencedBy 3,192 edges, governs 2,260.
- Load time: extract 0.2 s + additive 0.3 s. A 2-hop neighbourhood for every node in plain Python: 0.04 s.
- Layout: base 2D 16.5 s, base 3D 9.7 s, `place_extra` 139.3 s. The #313 "explorer build timed out at 100 s" is the drawing step, not storage or query.
- Edge qualifiers present: note 12,382 · maker 12,291 · born/died 1,626 · paths 828 · derived 296 · why 255 · grade 67 · recommended 67 · daveNote 42 · ruling 16 · overruled 13 (and more).

Verdict: no database. At this size a graph database is a server to babysit for no speed gain, it breaks "the repo is the record" (a second home, not diffable, not in git, not on the work machine or with designers), and it would not touch the slow part (layout). External, dated 2026-10-02: Kùzu, the usual embedded pick, was archived 2025-10-10 (successor LadybugDB); DuckDB has a SQL/PGQ extension (DuckPGQ); RDF 1.2 triple terms (statements about statements) are a W3C Candidate Recommendation, 2026-04-07.
The real gap is that the graph has TWO loaders: the explorer builder's `extract()` + `extract_extra()` (a drawing tool) and `_compose_slice.py`'s own LIVE reader (the ASK door, s277-D13), which re-implements the joins and is kept in step by a selftest bite that cross-checks it against the explorer (`_compose_slice.py` ~line 2333). The graph IS on the retrieval path now (the 2026-08-05 research's gap is closed by ASK); the cost is two copies of the join logic.

Hyper-relational: yes, in two forms already. (1) Every edge carries qualifiers (who made it, why, his note, born/died) — statements about statements, stored as edge fields. (2) N-ary relations live as nodes: s238-D1 ruled polarities "HYPER-RELATIONAL NODES AND THE NODE IS THE ONE HOME", and a ruling node already joins session, evidence and artefacts. Does it need to be: the qualifiers yes (they are Memento's evidence rule applied to edges); general edges-on-edges no — s238-D1's node-as-home shape is the right size and projects down to plain edges, which is also the only shape Neo4j could hold.

Proposed §C lines:
- One read-only graph loader (`knowledge/_graph.py`) that both the explorer and `_compose_slice.py` import, so the joins live once and the cross-check bite becomes unnecessary.
- Layout speed: `place_extra` 139 s — cache positions by node id and place only new nodes, or a Barnes-Hut / sfdp layout. Separate from storage.
- A graph engine only if a query language is ever needed: generated from the JSON at build time, gitignored, never canon (DuckDB + DuckPGQ or LadybugDB; not Kùzu).
