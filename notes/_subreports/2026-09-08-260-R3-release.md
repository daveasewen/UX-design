## ⬛ RULING-SHAPED, NEW — the sanctioned commit path cannot leave a clean tree, and `--release` needs one

`--release` calls `require_clean`, which is `git status --porcelain` with **untracked included**.
`knowledge/_git_commit.sh` runs the capture/wrap gate as part of every commit, and that gate
**appends a row to `notes/_REHEARSAL-LOG.jsonl` AFTER staging** — measured here, not inferred:
the file was staged in `a53ed79` and was dirty again the moment the script returned. So the
runbook's own commit path leaves exactly one dirty path behind, every time, and a release can
never be reached through it: each commit made to clean the tree dirties it again.

Two honest ways out, and only one was available. `git stash` is forbidden; `git checkout` on the
file is the two-lanes-wiped-each-other move (#253) and would discard an instrument's record. So
the row was committed with a **plain `git commit`** — commit `e20a8f0`, subject
`#260 R3: the rehearsal row _git_commit.sh wrote during its own run` — which is a deliberate step
**outside** the sanctioned path, named here rather than buried.

⬛ **The decision is Dave's**, and it is the same policy question W-22 already floats and does not
answer: `notes/_REHEARSAL-LOG.jsonl` is EXCLUDED from the push gate by `s137-D1` but nothing
excludes it from `require_clean`. Candidates: (a) `require_clean` ignores the three declared
instrumentation appends the way the push gate ignores one of them; (b) the capture gate writes its
row **before** staging so the same commit carries it; (c) the log moves out of the tree. **No
option was taken.** It is a small hole and it is load-bearing: it stands between the ratifying word
and the bake on every single release.
