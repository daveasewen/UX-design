## THE DIFFS THAT MATTER

### ★ The pitfall was real, and it was NOT in the packer

The brief warned that packers drop dot-directories. `_gen_pack_manifest.py` handles them fine —
`.github/` has always shipped. **The block was one level down, in the repo's own `.gitignore`.**
The ship list is generated from `git ls-tree` at a named commit, so an *ignored* file can never
enter the tree, and no manifest rule can rescue it. Measured in both directions:

```
BEFORE:  git check-ignore -v apollo-spider/.vscode/settings.json
         .gitignore:4:.vscode/   apollo-spider/.vscode/settings.json      ← IGNORED
AFTER:   .gitignore:13:!apollo-spider/.vscode/settings.json               ← NOT ignored
```

**Two lines were required, not one** — git does not descend into an excluded *directory*, so the
directory has to be re-included before the file can be:

```gitignore
.vscode/
# EXCEPTION (s224-D1, v1.0.3): the RELEASE SURFACE's .vscode/ is not editor noise — it is a
# SHIPPED FILE. ... ⛔ The pack's ship list is generated from `git ls-tree` at a named commit,
# so an IGNORED file can never ship, however the manifest rules are written. Two lines are
# required, not one: git does not descend into an excluded DIRECTORY ...
!apollo-spider/.vscode/
!apollo-spider/.vscode/settings.json
```
