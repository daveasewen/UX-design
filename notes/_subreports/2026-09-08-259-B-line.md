## What I could NOT do — first obstacle, named

1. **A line cannot escape the zero baseline.** `dv-render.js` runs `if (lo > 0) { lo = 0; }` for
   every type, AFTER the type's own `fn.domain` has been called — so neither a domain function nor
   anything inside a partial can opt out. dv-line-001's asymmetry (quoted in the dataviz gate's own
   header: *"dv-bar-009 zero baseline — bar-family only … MUST NOT fire on lines"*) says a line
   should be free of it. Left alone rather than worked around; **core request, verbatim below.**
   Nothing regressed: the promoted snippet was zero-based too.
2. **Chart-line carries no `APOLLO-DEMO` fence** (neither does Chart-bar). Its showroom chrome is
   three bare `<h2>` headings, unfenced before this lane. The DATA + `dvRender()` bootstrap is
   deliberately NOT fenced — it is the pattern a build must copy, not harness. Whether the `<h2>`s
   should be swept is s258-D3's business, not a type lane's.
3. **`gen_showroom.py` has no per-page flag**, so nothing was regenerated; 6 pages are stale and
   none of them is chart-related.
4. **`_validate_screen.py` and `_build_all.py` not run** — fenced by the brief.

## CORE REQUEST — verbatim, for the engine-core owner

> `dv-render.js`, in `dvRender()`:
>
> ```js
>     if (lo > 0) { lo = 0; }                      /* dv-bar-009 — the baseline is zero, always */
> ```
>
> This fires for EVERY type. dv-bar-009 is a bar-family rule and `_validate_dataviz.py`'s own
> header says it "MUST NOT fire on lines (dv-line-001 asymmetry)". A type partial cannot opt out,
> because the clamp runs after `draw.domain(spec)`. Requested shape: make it conditional on the
> type — e.g. skip the clamp when the registered function declares `fn.zero === false` (symmetric
> with the existing `fn.axis` / `fn.domain` opt-ins), so `dv-render-line` can let a balance series
> of 82…104 fill its plot instead of hugging the top eighth of it.

## What the snippet looks like now, in one paragraph

Two `figure.dv` canvases ship as empty `<svg class="dv-svg dv-fit">` boxes; a bootstrap script at
the foot of the file holds MONTHS × BALANCE × LAST-YEAR and a three-product series set, calls
`dvRender(figure, spec)` once per figure, and re-calls it when the monthly / year-to-date segmented
control changes what the figure shows. The engine rewrites each `<table class="dv-table">` from the
same numbers; the bootstrap appends one extra column so the last-year overlay's values stay in the
a11y spine. The two additive overlays (last year, target) are re-appended after each render as
author-side markup that rides the render's OWN scale, read back off the series polyline — the spec
has no overlay concept and inventing one would change the shape Dave ruled at s249-D4. The
token manifest, the legend, the empty-state figure and the JS-off table
spine are all unchanged; there is no `APOLLO-DEMO` fence in this snippet to change (obstacle 2).
