## 1 · What the option grammar now says

**The spacing rails are the six ruled stops, and every spacing dial is on them.**
`s219-D1(4)` is typed ONCE, as the quotation `RULED_SPACING_RAIL = (1, 2, 4, 16, 24, 40)`, and the
working rail `SPACING_STOPS` is derived from it. Every dial, every CSS rule and the manifest are
built from the working rail by one derivation (`_rails()`); the two are asserted equal, and the
mutation arm moves the working rail only.

| dial | before | after |
|---|---|---|
| `spacing` (display, gallery) | 3 words: Tight 1px · Standard 24px · Generous 40px | **6 stops: 1 · 2 · 4 · 16 · 24 · 40 px** |
| `mainSpacing` (dashboard) | 2 stops — **Tight ABSENT** (s217-D5 "never tight") | **the same 6 stops**, 1px reachable |
| `subSpacing` (dashboard) | snapping slider over 1·2·4·8·12·16·20·24 (s217-D6) | **the same 6 stops**; the slider survives, the ladder under it is the rail |

The dial now speaks in pixels: the buttons read `1PX 2PX 4PX 16PX 24PX 40PX`. The
tight/standard/generous word trio is **gone from the grammar**, not re-labelled — a stop has no
name but its size. Three hand-typed CSS triplets (`.bm-wall`, `.bm-outer` main, `.bm-just`) are now
GENERATED one-rule-per-stop, so a dial and its stylesheet cannot drift apart.

**The dashboard's two-dial split is the shipped grammar (s219-D1(5)).** `mainSpacing` +
`subSpacing` already existed from s217-D6; what #219 changes is that both draw from the ONE rail.

**Every dial is available in every theme (s219-D1(2) / s219-D2(4)).** `KEYLINE_EXCLUDED` is now
**empty**: s217-D6's removal of the keyline control from gallery-in-console is retired, the
reachable count is theme-INDEPENDENT again (2106 in all four themes, was 2106/console-less-than),
and the page prints both columns so the agreement is read rather than claimed. The exclusion
MECHANISM is kept (empty) as the one place a theme lock could be expressed, and the selftest drives
it with a fixture so "empty" is a statement about the rules and not a broken instrument.
The gallery rounding dial was relabelled **"Image rounding"** (was "Console image rounding") — it
was never console-only, and under s219-D1(2) a label that names one theme reads as a theme lock.

**Reachable, per theme, all four equal:** display 108 · gallery 1350 · dashboard 648 · **total
2106**.

## 2 · The manifest — `knowledge/_render/_bento_edit_rails.json` (NEW, GENERATED)

Minted by `python3 knowledge/_render/gen_bento_matrix_217.py --rails`, from the same objects the
controls are built from. 474 lines. It carries: the rail and its `free_values_allowed: false`; the
ten dials with option set, labels, control kind, `types`, `themes: "all"` and `theme_locked: false`

dashboard 5 — exactly the shape of Dave's twelve exports); the two legality rules; the reachable
counts; the defaults **by address**; and two `$open_questions`.

⛔ **Never hand-kept:** selftest bite `R6d` asserts the file on disk is byte-identical to a fresh
generation, so a hand edit is a RED rather than a drift. **Re-run `--rails` after any change to the
option grammar** (and after lane B's defaults land, to refresh the embedded values).

⚠ **Groundwork only.** No editor is built or proposed. This is the vocabulary Dave's parked bento
editor would read, minted at the moment the vocabulary was ruled.

**Defaults are ADDRESSED, not copied.** The manifest looks for
`gen_foundations_217.ROLE_DEFAULTS_219 / BENTO_ROLE_DEFAULTS / ROLE_DEFAULTS`, records which one it
found, and validates every value it reads against the option space. It deliberately does NOT read
`GALLERY_SETTINGS`: that name is the **#218 photography-wall** table, a different subject with a
similar name, and reporting it as the #219 gallery default would be a confident false statement.
At generation time it resolved `gen_foundations_217.ROLE_DEFAULTS` (lane B, landed mid-lane) with
**0 complaints** — every one of Dave's twelve default states is a reachable option in the widened
space.
