### ⛔ 1 — `gen_dashboard.py --check` is a BLOCKING gate with no reachable FAIL path

`knowledge/_build_all.py:261` wires it blocking:

```
("dashboard sync — generated progress dashboard (RULED #164, built #165)", "gen_dashboard.py", ["--check"]),
```

Driven against the committed page in a tree with full git history, it returns **rc=77**, not rc=1:

> `COULD-NOT-ASK: dashboard/index.html — the page differs, but a live gate baked into it is reading
> INPUTS OUTSIDE THE COMMITTED TREE … provenance names `_inscribe_ruling.py`. Every one of those
> paths is untracked …`

**The mechanism, isolated to one variable.** `_governs.py --selftest` — one of the eight gates the
page bakes in (`gen_dashboard.py:147`) — prints a remedy sentence containing the bare token
`` `_inscribe_ruling.py` ``. `untracked_inputs()` (`gen_dashboard.py:210-237`) scrapes path-like
strings out of every gate's output and asks git about them **from the repo root**:

```
$ git ls-files -- _inscribe_ruling.py            # what the scraper actually asks
[]                                                # empty  => classified UNTRACKED
$ git ls-files -- knowledge/_inscribe_ruling.py  # the file's real home
knowledge/_inscribe_ruling.py                     # tracked all along
```

The scraper takes a **basename** and resolves it as a **root-relative path**. It never matches, so
`mismatch_verdict()` fires every time. And `mismatch_verdict()` is only reached when `cur != html`
— i.e. **exactly when the page is stale**. Proven both directions in the sandbox:

| state of `dashboard/index.html` | `--check` rc |
|---|---|
| regenerated (in sync) | `0` — "in sync" |
| committed (stale) | `77` — COULD-NOT-ASK |
| *any* | **never `1`** |

**Class:** false-green / [[instrument-without-a-consumer]] — an honest-refusal path (s172-D1,
correct in principle) that has become the *only* path, so the gate cannot accuse its artefact.
`gates.yml:54-55` names step `[59] gen_dashboard.py --check` as one of four "retrofitted to 77"
arms and states the cause as `_governs` naming `outputs/…` evidence files; **the live cause today
is a different one — a bare basename, not an `outputs/` path** — so the comment is also stale.

**Fix, PRICED:** make `untracked_inputs()` refuse to classify a bare basename — either resolve it
by search before asking git, or exclude non-slash tokens from `cand`. ~25 lines in
`gen_dashboard.py:219-237` plus a known-answer bite (feed a gate line naming a basename, assert the
verdict is not COULD-NOT-ASK). **~4–6K tokens.** ⚠ It will turn the build step RED until finding 2
is cleared — that ordering is the conductor's to sequence.

### ⛔ 5 — `gen_library_214.py` silently degrades 7 components on Linux (i.e. in CI)

Seven component metas are committed with a **capital** prefix while every sibling is lowercase:

```
$ git ls-files knowledge/components/ | grep -i 'chart-'
knowledge/components/Chart-boxplot.meta.json        <- capital
knowledge/components/Chart-bullet.meta.json         <- capital
knowledge/components/Chart-butterfly-h.meta.json    <- capital
knowledge/components/Chart-butterfly-v.meta.json    <- capital
knowledge/components/Chart-candlestick.meta.json    <- capital
knowledge/components/Chart-histogram.meta.json      <- capital
knowledge/components/Chart-scatter.meta.json        <- capital
knowledge/components/chart-bar.meta.json            <- lowercase (and 13 more)
```

`gen_library_214.py:553` builds the path from the lowercased slug:

```python
mpath = os.path.join(META, slug + ".meta.json")
```

On macOS (case-insensitive APFS) this resolves and the index is correct. On Linux it misses, and
`level_of()` falls through to its final `return "unfiled"` while `blurb` falls to `""`:

```
chart-boxplot      level 'pattern' -> 'unfiled' | blurb 117ch -> 0ch
chart-bullet       level 'pattern' -> 'unfiled' | blurb 115ch -> 0ch
chart-butterfly-h  level 'pattern' -> 'unfiled' | blurb 113ch -> 0ch
chart-butterfly-v  level 'pattern' -> 'unfiled' | blurb 149ch -> 0ch
chart-candlestick  level 'pattern' -> 'unfiled' | blurb  93ch -> 0ch
chart-histogram    level 'pattern' -> 'unfiled' | blurb  88ch -> 0ch
chart-scatter      level 'pattern' -> 'unfiled' | blurb 142ch -> 0ch
```

The index gains a bogus **7th ladder tier** ("Unfiled", 7 members), Pattern drops 33→26, and the
"Ladder tiers" stat reads 7 instead of 6. **The miss is silent** — no warning, no refusal, which is
the enumerate-and-skip pattern this codebase forbids elsewhere in as many words.

**Single-variable isolation** (the proof it is case and nothing else): giving the Linux sandbox
lowercase copies of just those 7 metas and regenerating produced `showroom/index.html` **and**
`showroom/index.json` **byte-identical to committed**. So the generator is clean; the filenames are
the defect.

**Reach:** all three CI jobs are `runs-on: ubuntu-latest` (`gates.yml:224, 281, 363`). Any Linux
designer running the shipped pack hits it too. **Class:** [[gate-cannot-pass-in-one-environment]]
in a new shape — here it is the *artefact* that differs by environment, not the verdict.

**Same class, other consumers** (exact-case lookup from a lowercase slug):
`knowledge/_build_prototype_grade_audit.py:81` (`name.lower() + ".meta.json"` — will always miss the
7), `knowledge/gen_itinerary_status.py:621`, `knowledge/_render/verify_wave3_alpha_218.py:152,209`.

**It has already been found once and patched locally.**
`knowledge/_render/verify_wave3_gamma_218.py:154` carries a case-insensitive fallback:

```python
if f.lower() == "%s.meta.json" % slug.lower():
```

One file was immunised; the class was not fixed. Dave, #215: *"always real fixes never patches, they
just get lost."*

**Fix, PRICED — three options, Q2:** (a) rename the 7 files to lowercase (`git mv`, ~1K tokens, and
a repo-wide sweep confirms **0 case-folding collisions**, so the rename is safe on both filesystem
kinds); (b) case-insensitive resolution in a shared helper all five consumers import (~60 lines,
**~6K**); (c) a gate that fails when a `showroom/<slug>.html` has no exact-case meta (~40 lines,
**~4K**). Recommend **(a) + (c)** — (a) fixes it at cause today, (c) stops it returning.

### 8 — `SPACING_STOPS` is STILL two homes, and one module denies it

The divvy names this as a solved-once exemplar. It is not solved.

`knowledge/_render/gen_bento_matrix_217.py:189-195`:

```python
# ⛔ TWO NAMES, AND THE PAIR IS THE GATE. `RULED_SPACING_RAIL` is the QUOTATION — the six numbers as
# Dave ruled them, and the only place they are typed. `SPACING_STOPS` is the WORKING rail every
RULED_SPACING_RAIL = (1, 2, 4, 16, 24, 40)
SPACING_STOPS = list(RULED_SPACING_RAIL)
```

`knowledge/_render/role_defaults_219.py:92`:

```python
SPACING_STOPS = ["1", "2", "4", "16", "24", "40"]
```

The comment's claim — *"the only place they are typed"* — is **false**: the same six ruled numbers
are typed again 300 lines away in another module, as **strings** rather than ints. Both homes have
live consumers, so neither is dead code:

- `verify_bento_matrix_217.py:941,947,1088` reads `matrix.SPACING_STOPS` (the int home)
- `gen_foundations_217.py:406,411,415,431,484,488` reads `defaults219.SPACING_STOPS` (the string home)

Nothing asserts the two are equal. A seventh ruled stop edited into one home leaves the other
silently wrong, and the type difference (`int` vs `str`) means a naive `==` between them fails even
when the values agree. **Class:** ADR-0017 write-once violation — one live fact, two homes.

**Fix, PRICED:** `role_defaults_219.py` imports `RULED_SPACING_RAIL` and derives its string form
(`[str(s) for s in RULED_SPACING_RAIL]`); strike the false clause from the matrix comment; add one
equality assert. ~15 lines, **~3K tokens.** ⚠ Check import direction first — if `role_defaults_219`
cannot import the matrix module without a cycle, the rail moves to a third, dependency-free module
and both import it. That widens it to **~6K**.
