## Findings

**1 — THE BRIEF'S GENERATOR PREMISE IS FALSE, AND THREE PROBES SAY SO.** The brief: "whichever
module today injects `#token-manifest` into snippets gains the receipt injection beside it."
No module injects it.
  * `grep -rn 'type="application/json" id="token-manifest"' --include=*.py .` → 6 hits, every one
    a test fixture or a selftest string (`knowledge/_tests/test_gates.py:375`,
    `knowledge/_validate_binds_resolve.py:251`, and their two `_to_delete/` pack copies).
  * `knowledge/gen_snippet_tokens.py:139-141` — the manifest is READ, and a snippet without one
    is returned as `{"name": …, "warn": ["no #token-manifest"], …}`. It is reported, not repaired.
  * `apollo-spider/skills/check-with-gates/SKILL.md` Route C instructs a human contributor to
    write it: *"a `#token-manifest` block declaring every var you use and the token behind it."*
  * Population: `grep -rl 'id="token-manifest"' knowledge/snippets/` → **137**, i.e. all of them,
    hand-authored.
[[premise-ages-faster-than-rule]]. The clause's live intent — a SIBLING block, not a new key
inside the manifest — is honoured, and stated in `gen_provenance_receipt.py`'s docstring so the
next reader does not re-derive it.

**2 — AND THE RECEIPT COULD NOT LIVE THERE ANYWAY.** `#token-manifest` belongs to a SNIPPET (the
var → token bindings that snippet declares). A receipt belongs to a COMPOSED PAGE (what was
spliced in, and from where). A snippet has no provenance to record — it *is* the source. So the
injection point is the page, and the consumer is `_validate_screen.py <path>`, which `s234-D6`
already names as the one gate that takes a path.

**3 — ONE PARSE, TWO USERS, BY IMPORT.** `region_bytes()`, `sha256_of()`, the marker regexes and
`parse_receipt()` live in `_validate_receipt.py` and are IMPORTED by the generator
(`import _validate_receipt as VR`), never re-implemented. The dependency runs mint → gate, so the
gate stays self-sufficient for the shipped pack. This is the [[no-gate-parses-the-artefact]]
remedy applied before the defect: a drift between what the mint hashed and what the check hashes
is not expressible, because there is one definition.
The definition, verbatim from `knowledge/_validate_receipt.py`: *"everything strictly between the
START marker's closing `-->` and the `<!--` opening the END marker"*, UTF-8, sha256, **no
normalisation of any kind**.

**4 — THE HASH IS OVER THE PAGE'S BYTES, AND THE REFERENCE FILE IS NEVER HASHED.** The brief's
pitfall, taken literally. The one place the source file is opened is `_source_region()`, and it
runs ONLY after the verdict is already settled by the hashes, purely to name the byte that moved.
It is soft-imported inside a `try` and every failure path returns `None`, so a gate run never
depends on the generator being present. Proof it is doing real work: DRIVE 3 reports
*"first differing byte at offset 184 of the region"* — an offset the receipt alone cannot give.

**5 — THE BEHAVIOUR ADDRESS IS REAL FOR CHARTS AND HONESTLY NULL EVERYWHERE ELSE.** The generator
resolves an address mechanically in exactly one way: AUTO-BEHAVIOUR names present in the snippet,
looked up in `knowledge/component-types.json` `$behaviour/<name>.source`. Registry at probe time
(`python3` walk of that file): `dv-behaviour → canon/dv-behaviour.js`, `dv-legend → canon/dv-legend.js`,
`dv-donut-sweep → canon/dv-donut-sweep.js`, group `dataviz`, 14 members. `Chart-line` carries
`AUTO-BEHAVIOUR dv-behaviour` at line 665, so its receipt entry declares
`"script": "knowledge/canon/dv-behaviour.js"`, and DRIVE 2 reports it **LOADED**.
`knowledge/components/<slug>.meta.json` `behaviour` is DELIBERATELY NOT read as an address:
`knowledge/components/meta.schema.json:197` still types it `{"description": "optional behavioural
notes", "type": ["object", "array", "string"]}` — prose. Typing it is `s234-D5` and is L2's. A
region with no address gets `"script": null` + a `$scriptNote` naming that line, and the gate
prints `NO-BEHAVIOUR-DECLARED`. **Nothing was promoted.**

**6 — `retrievalSet` IS `null` WITH A NOTE, AND THE GATE REFUSES TO LET THAT PASS QUIETLY.** rC
Q4 is open, so no membership marker was invented. But `null` is not silence: the gate emits
`UNPROVEN:retrievalSet — … a ruled membership marker carried in the receipt would prove which
retrieval set the page was built from` on every run, above the verdict, and the verdict line
reads `PASS (+1 UNPROVEN)`. ADR-0016's finding — *"CLAIMED is not a soft PROVEN"* — at gate scale.

**7 — THE RATCHET, AND THE NUMBER BEHIND IT.** `python3 knowledge/_validate_screen.py` with no
arguments (the default `_fitness-test/*.canon.html` population): **7 of 7 screens report
`UNPROVEN:NO-RECEIPT`, and `RESULT: PASS ✅`, rc 0.** With `--receipt-strict` (or
`APOLLO_RECEIPT_STRICT=1`) the same population would be 7 reds. Every composed screen in this
repo predates the receipt, so a blocking step-0 on day one is
[[gate-cannot-pass-in-one-environment]], not enforcement. Standalone `_validate_receipt.py`
ALWAYS exits non-zero on `NO-RECEIPT` (DRIVE 1, rc 1) — the downgrade lives only in the chained
step, and prints itself. The switch exists before the ruling does; the ruling is question 1.

**8 — THE RECEIPT-BEARING PAGE PASSES STEP 0 AND REDS STEP 1, FOR A REASON THAT IS NOT MINE.**
`python3 knowledge/_validate_screen.py dashboards/international-banking-dashboard.regen-v2-receipt.html`
→ `- receipt: ✅ 12 region(s) re-hashed and matched` then
`- compose: ❌ 191 hex colour(s) in <style>: ['#F6604C', '#1A1A1A', '#1A1A1A', '#FFFFFF', '#1A1A1A']`.
The cause is structural, not a defect in the page: **a page composed by splicing snippet `<style>`
blocks verbatim inherits their `[data-theme]` hex**, which `_validate_compose` forbids in a
composed screen. `regen-v1` passes compose because its author hand-wrote CSS instead of splicing
it — i.e. the route that passes compose today is the route the receipt exists to distrust. That
is a real seam between two gates and it is question 2. It is NOT a regression: the receipt step
is green on that page, and the compose red is reproducible on any verbatim-CSS splice.

**9 — THE EXTRACTOR REFUSES RATHER THAN GUESSES.** `extract_element()` does a balanced tag scan
over a COMMENT-MASKED, length-preserving copy of the snippet's `<body>` (the
`gen_component_partials.py` / `_htmlmask` idiom), so a commented-out copy can never be the match
and the offsets still hold. A selector that matches nothing raises a named `SystemExit`
(`REFUSED: nothing in the snippet's live <body> matches .no-such-class-anywhere`) — generator
selftest arm E. [[measuring-tool-must-not-guess]].

## RULING-SHAPED QUESTIONS

**1. When does a MISSING receipt start blocking?** Today the chained step-0 reports
`UNPROVEN:NO-RECEIPT` and does not block; `--receipt-strict` / `APOLLO_RECEIPT_STRICT=1` blocks
now. Measured cost of flipping the default: **7 of 7** screens in `_validate_screen.py`'s default
population go red immediately (`notes/_subreports/assets/2026-09-02-235-L1-receipt-gate/chain-default-population.txt`),
plus `regen-v1`. Options: (a) leave advisory until the pages are re-minted — cheap, and the ADR-0013
ratchet posture; (b) block now and mint receipts onto all 7 first — one `--mint` per page, but
those pages were hand-composed, so their "spliced regions" would have to be invented, which is the
exact defect the gate exists to catch; (c) block for NEW pages only, by date or by folder — needs a
rule about which, and folder globs are what `s234-D6` refused to widen. **Recommend (a) now and
(b)-via-regeneration later**, i.e. the ratchet closes when a page is next regenerated by a
generator that can splice. `s234-D6` rules that the gate parses the receipt first; it does not
rule when a missing one blocks, so this is genuinely open.

**2. What does a composed page do about CSS?** Splicing snippet `<style>` verbatim carries 191
hex values into the page and reds `_validate_compose`; hand-writing CSS passes compose but is
exactly the un-receiptable authoring the receipt distrusts (finding 8). Options: (a) the composer
projects theme values through `gen_snippet_tokens`'s resolution instead of copying the block —
real work, and it makes the CSS region a DERIVED artefact whose hash still holds; (b) composed
pages link `canon/canon.css` — but the true probe is `grep -l 'href="../canon/canon.css"'
knowledge/snippets/*.reference.html` → **0 of 137**, so no snippet has ever done it; (c) exempt
APOLLO-SPLICE style regions from the compose hex check — a loosened gate, and I will not
recommend it. **Recommend (a)**, priced at a lane of its own. Not mine to rule and not in the
brief.

**3. Should `dashboards/*.html` be permanent subjects of the screen-gate index?** Running the
chain on them minted `knowledge/_screen-gate/international-banking-dashboard.regen-v1.md` and
`…regen-v2-receipt.md`, which `write_index()` now lists in `_SCREEN-GATE.md` forever. That is the
gate's designed one-home-per-subject behaviour (#230 T5), not a bug, but it enrols two dashboards
into an index that held seven fitness-test screens. Conductor's call at the reconcile: keep, or
drop the two files before commit.

## PITFALLS SEEN

1. **The brief's own premise was the first thing to break.** [[premise-ages-faster-than-rule]] —
   fifteen minutes of grounding turned a one-line instruction ("add it beside the manifest
   injector") into "there is no injector". Verifying a premise cost three greps; building on it
   would have cost the lane.
2. **The reference file is a trap that makes everything pass.** Hashing
   `Stat-card.reference.html` instead of the page's region would have produced a gate that is
   green on a paraphrase and green on a splice alike. The brief named it; it is worth naming
   again, because the code that does it is *shorter* than the code that does not.
3. **A "generated page" with no generator.** Nothing in this repo composes a page from snippets —
   an agent does, by hand. So "regenerate a page WITH the receipt" required building the splicer
   too. A receipt gate with no minting route would have been
   [[instrument-without-a-consumer]] with extra steps.
4. **A day-one blocking gate reds the whole existing population.** Seven screens. Measured before
   choosing the posture, not after — and the number is in the report so the conductor can flip
   the default with evidence rather than nerve.
5. **`test_gates.py` blew ~20K tokens of traceback into the window.** It failed on disk space and
   printed one `[Errno 28]` line per file it could not copy — hundreds. Second attempt was
   redirected to a log and grepped. **The rule for the next sub: never run a repo-wide test
   harness without `> log 2>&1` first.** [[a-crash-is-not-a-fail]] has a cost twin — a crash you
   let print is a crash you pay for.
6. **The screen gate writes as a side effect of being run.** Every `_validate_screen.py`
   invocation rewrites `_SCREEN-GATE.md` and a per-subject file; driving it on two dashboards
   enrolled them permanently. Flagged for the reconcile (question 3) rather than quietly reverted.
