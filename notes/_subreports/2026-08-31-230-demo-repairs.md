## THE FOUR FIXES

### 1 · F1 — the design contract now reaches a cold seat, by generation

**The class fix, in one sentence: placement is a GENERATED OUTPUT with a BUILD-TIME CONSUMER, so
a future contract edit cannot silently strand the hosts again.**

`cold-start/gen_projections.py` used to write three TEMPLATES into `cold-start/projections/` and
say so in its own docstring — *"THE PROJECTIONS ARE TEMPLATES, NOT PLACEMENT"*. It now ALSO writes
the three real host files at the pack root, through the same `render()` call, so the template and
the placed file cannot disagree:

    apollo-spider/CLAUDE.md                        (new, generated)
    apollo-spider/AGENTS.md                        (new, generated)
    apollo-spider/.github/copilot-instructions.md  (now a generated OUTPUT, was a hand-kept file)

⛔ **The second source had to move, and this is the trap it avoids.** The copilot host is a MERGE
of the contract and the pack's own boot rules, and the boot rules used to live at
`../.github/copilot-instructions.md` — the very path the merged file now occupies. Generating a
file from itself folds the contract in again on every run until the byte budget blows. The boot
rules are therefore now a plain source at `cold-start/COPILOT-BOOT.md`, and the host path is a
pure output. Selftest arm 14 bites exactly this: write twice, assert the bytes do not move AND
that the contract's opening line appears exactly once.

**The consumer that reds.** `verify_placement.py` keeps its designer-facing contract — bare run,
advisory, always exit 0, because a missing `CLAUDE.md` in a Copilot-only shop is a fact and not a
fault. It gained `--require`, which runs the SAME `inspect()` and refuses on the same rows:

    python3 cold-start/verify_placement.py --require --root <dir>   # exit 1 on any cold host

`build-designer-pack.sh` now runs BOTH questions over the **STAGE**, blocking, before it zips:

    python3 "$STAGE/cold-start/gen_projections.py" --check          # byte-derived from the source
    python3 "$STAGE/cold-start/verify_placement.py" --require --root "$STAGE"

They are not the same question — `--check` catches a hand-edit or an unregenerated contract,
`--require` catches a host file that never got written or a merge that dropped the markers. A pack
can pass either alone and still be cold. They grade the stage rather than the repo, because the
bytes that ship come out of the commit via `git archive`.

**Driven, both directions.** `verify_placement --selftest` gained four arms: a cold project REDS
under `--require` (the exact rehearsal state), the same tree with the files placed GOES GREEN (the
control — a gate that cannot pass blocks every cut), the bare advisory run still exits 0 (the two
policies did not merge), and a mistyped `--root` REDS under `--require` rather than shrugging.
`gen_projections --selftest` gained four: the placed files exist and carry both markers, a DELETED
placed host is red, a hand-edited placed host is red, and the self-generation bite above.

    verify_placement selftest OK — 10 arm(s).
    gen_projections selftest OK — 14 arm(s), drift planted and seen.
    gen_projections --check OK — 3 projection(s) and 3 PLACED host file(s) in sync.
    ✅ --require: all 3 hosts carry the contract.

`knowledge/_release/_gen_pack_manifest.py`'s `cold-start` group was widened to claim
`apollo-spider/CLAUDE.md` and `apollo-spider/AGENTS.md`. (`.github/copilot-instructions.md` is
deliberately NOT claimed there — `gumdrop` already claims `apollo-spider/.github/` whole, and
claiming a path twice is a collision.)
