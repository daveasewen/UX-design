### 2.1 · The mechanism, exactly as the ruled pattern prescribes

Per-rect `--b1…--b(n−1)` = the `height` attributes of the segments BELOW it in its own column, plus
`--self` = its own registered progress number; `n` `@property` numbers animate ONCE on the `<svg>`
over one shared `var(--grow-dur)`; every rect composes
`translateY(Σ belowⱼ × (1 − fⱼ)) · scaleY(f_own)`. The curve rule is DV-D16's POSITIONAL one —
first `var(--grow-ease-in)`, last `var(--grow-ease-out)`, everything between `linear` — which for
the pro-forma's 4-deep stack means **seg1 ease-in · seg2 linear · seg3 linear · seg4 ease-out**,
exactly the extension recipe Chart-bar's own comment writes down for `N > 3`. Pure CSS; zero JS in
the physics (DEF-003 / B-D7). Reduced motion: every float rule sits inside
`(prefers-reduced-motion:no-preference)`, and `reduce` + JS-off were **driven**, not reasoned —
both rest on the final frame.

`STACK_DEPTH = 4` is the page's own stack depth, and `build_stacked()` raises a NAMED `SystemExit`
if a stacked chart of any other depth is ever built against it. Without that guard a 5-series stack
would emit `--self:var(--dvf5)` against an unregistered property, sit at its initial value 1, and
render a chart that simply never animates — green in every static check
([[a-crash-is-not-a-fail]]).
