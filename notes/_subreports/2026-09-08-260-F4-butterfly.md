Split into two files, each member would consume `shared + its own routine` — **3,847** (h) and
**3,630** (v) — so splitting is **864–1,081 bytes cheaper per member** and **+2,766 bytes more code
in the tree**. I took the one file anyway, on two measured grounds and one argued one:

1. **The saving buys nothing.** The member page figure is **25,493 of 34,816 — 9,323 bytes of
   headroom.** A 1 KB saving against 9 KB of slack is not a constraint, it is a rounding error.
2. **The shared half is 59% of the file.** Duplicating the symmetric domain, the pair validation
   and the DV-D09 fill rule into two files means two places for the mirror rule to drift — the
   exact argument `dv-render-bar` makes for folding four bar types into `bars(ctx, horiz, stack)`,
   and that lane's de-duplication is what took Chart-bar from RED to green at #259.
3. **They are one idea rotated.** A butterfly-h and a butterfly-v are the same arithmetic with the
   band axis and the value axis exchanged. That sentence is `dv-render-bar`'s, verbatim.

If the budget ever bites this member, the split is mechanical and the numbers to do it with are
above.

## The design, and what it does NOT do

- **The mirror is the SECOND SERIES, not a sign.** The domain is symmetric — `[-M, +M]` over the
  largest magnitude in either wing — which is what makes both wings share ONE scale (a butterfly
  that scaled its halves independently would misrepresent the data; Chart-butterfly-v's own header
  says so). A negative inside a wing THROWS, named; so does a third series. Both are the metas'
  `antiPatterns` restated as error messages, and both are mutation-proven below.
- **⛔ It discards the core's cartesian furniture** (`ctx.out.length = 0`, the `dv-render-donut`
  move). Two reasons, and the second is the one that matters: (a) both references draw no
  gridlines and no value axis at all — "a butterfly's shared centre gutter substitutes for a value
  axis", an ds-020 declared gap gated green at #95; (b) on a symmetric domain the core's ticks
  label the lower/left half NEGATIVE, so a tick would read `-40` under a wing whose value is 40.
  The donut discards furniture it does not need; the butterfly discards furniture that would be
  **wrong**. Core request filed, not made.
- **The centre gutter is a FRACTION, 0.196 of the plot** — the reference's own 90/460. It has to
  be: the fit re-derives every rect's `x` AND `width` from `data-fx`/`data-fw`, so a fixed-px
  gutter could not survive a resize. Driven: 198.3px at 1180, 116.0px at 760, `data-fx` constant
  at 0.4020 / 0.5980 across both.
- **dv-004 is now REAL on butterfly-v.** The pre-engine bake had the up wing ending at `y=110` and
  the down wing starting at `y=110` — **0.0px of separation** between two adjacent filled blocks.
  The engine cuts half a `GAP` off each wing, so the pair is separated by **2.200px, measured in
  the browser in 8 of 8 combinations**. This is a rule the artefact did not previously satisfy and
  now does; the gate never asked, because butterfly is not in `_validate_dataviz`'s gapless-surface
  set (below).
- **§04.3 letter keys stay OMITTED.** Direction (left/right, up/down) is already the non-colour
  channel; the delta from the bar contract was receipted at #95 and is repeated in the partial's
  header, not re-decided by a lane.
- **DV-D09** — the two wings bind `data/series/1` and `data/series/3`, the pair both
  `#token-manifest` `contrastPairs` blocks already declare. A roled series keeps the s184-D3 ramp.

## Core requests — filed, not made (full text: `knowledge/_tmp/260/butterfly.core-requests.md`)

1. **SECONDING #259 lane D's request**: let a type partial opt out of the cartesian furniture
   (`fn.axis = "none"` / `fn.furniture = false`). Two independent types have now paid for the same
   `ctx.out.length = 0` discard, for two different reasons — which is what makes it a seam rather
   than a donut quirk.
2. **NEW — the core cannot label a MAGNITUDE axis.** `furniture()` formats every tick with
   `ctx.fmt(t)`, fixed before `draw(ctx)` runs, so a type whose domain is a mirrored magnitude
   cannot label a tick `|value|`. Requested: honour an optional `fn.tickFormat`. Not urgent here
   (butterfly draws no ticks by ruling) but it is the difference between "no value axis by design"
   and "no value axis because the engine cannot label one".
