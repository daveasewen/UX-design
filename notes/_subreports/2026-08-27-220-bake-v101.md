### Where the decision lives, and what was wrong with it

`knowledge/_release/_gen_pack_manifest.py` already had an import closure — `helper_closure` in
`build_manifest`. It is the right idea in the wrong scope, and naming that precisely is the whole
fix:

* it is keyed on the **gate probe** (`r["local_imports"]` for gates the probe ran), so it can
  only see files the probe touched;
* it resolves every helper through `HELPER_HOMES` into **`knowledge/`**, one directory.

A module packed anywhere else — the entire memento cut, the entire gumdrop cut — is outside its
reach. `SEED_PREFIXES` then moves `apollo-spider/gumdrop/` → `memento-package/`, which lands
`_could_not_ask.py` at `memento-package/machinery/` **and only there**. The plugin mirror at
`memento-package/claude-plugin/memento/machinery/` gets nothing, and nothing in the release chain
ever asked whether either copy runs.

⚠ **A measured aside that explains why nobody caught it.** In the repo, BOTH copies are
unimportable, and they fail *earlier* than the pack does:

```
$ cd memento-package/claude-plugin/memento/machinery && python3 _gen_chain.py --check
ModuleNotFoundError: No module named '_helpgate'      # and identically in ../../../machinery
```

`memento-package/` in the repo has no `_helpgate.py` — it acquires one only in the pack, from the
gumdrop seed. So the repo's `memento-package/` is a **staging area for a cut, not a runnable
tree**, and no amount of running things in the repo would ever have found this. The only place
the question can be asked is the pack. That is the argument for § ② as much as for § ①.

### The fix

New section in `knowledge/_release/_gen_pack_manifest.py`, "THE IMPORT CLOSURE", stating the
decision as: *any module a packed `.py` imports **at module level** must be reachable from where
that file lands **in the pack**.*

* `analyse_imports(src, packdir)` — module-level imports plus the bodies of top-level
  `try`/`if`/`while`, and the `sys.path` roots the file actually declares. It evaluates
  `__file__`-rooted expressions (`os.path.dirname`/`abspath`/`join` over literals and
  module-level names) with a tiny non-executing evaluator, and recognises the repo-wide help-gate
  preamble as the upward search it is.
* An insert it **cannot** read is counted and reported as `unmodelled`, never assumed harmless
  [[measuring-tool-must-not-guess]]. Live reading: **`unmodelled_path_inserts: 0`**.
* `import_closure(paths, read_blob)` returns seeds `{module, dest, src, needed_by}`; the fill
  source is the **nearest carrier in pack space** (longest shared prefix, then sort order), so a
  memento module is filled from the memento copy and not from `knowledge/`.
* `apply_closure(stage, seeds)` copies **within the stage**, i.e. from bytes `git archive`
  already put there. The fill never comes from the working tree, so the bake stays a function of
  a named commit and `check_pack` can verify a closure copy against the commit like any other
  path.
* `build_manifest` **REFUSES** if a packed module imports something the pack carries nowhere.
* The manifest gained a top-level `import_closure` block and `totals.pack_files` /
  `totals.pack_bytes`. `totals.files` is untouched, because `--manifest` refuses when
  `totals["files"] != len(all_paths(man))`.

## ② THE BLIND GATE, AT CLASS — `knowledge/_gate_pack_imports.py`

**ADVISORY AT BIRTH.** Exit is 0 whatever it finds unless `--strict` is passed, and **nothing
wires `--strict`.** It is not registered in `_build_all.py` (DO-NOT-TOUCH) and not in
`.github/workflows/gates.yml`. Promotion is Dave's word.

It does not model `sys.path` — it **imports**. It copies the pack into a throwaway directory and
imports each `.py` there in its own subprocess, with that file's own directory on `sys.path`,
under `__name__ = "_packprobe_<n>"` so `__main__` blocks and help gates do not fire. The copy is
why importing is safe: a module that writes at import writes into the throwaway.

Verdicts, and what deliberately is **not** a red:

| verdict | meaning |
|---|---|
| `MISSING-LOCAL` | the module is in the pack but unreachable from the importer — **the defect class** |
| `MISSING-THIRD-PARTY` | `playwright` &c. A named `pip install` is a documented prerequisite; the manifest already ships those gates as NEEDS-DEP |
| `RAN-AS-SCRIPT` | a module-level `SystemExit`. Several validators do their whole job at module scope. Exit 0 is a clean run; a non-zero exit is **that gate's** verdict about the pack and is named, not counted here |
| `ERROR-AT-IMPORT` | imported its dependencies, then raised at module level |
| `TIMEOUT` | named, never silently dropped |

⚠ The `RAN-AS-SCRIPT` bucket was added **after** the first live run: the first classifier reported
three `SystemExit: 0` files as errors. Importing them ran them, and they passed. Reporting another
gate's honest green as a packaging defect is how a new instrument earns a reputation for crying
wolf, so it was corrected before the verdict was written down.
