## 1 · RCA — five whys, and why the group is the answer

The #229 eye-repairs sub already took this to a two-part root cause. This lane's job was to test that
diagnosis against the *fourth* recurrence and then close it, so the whys are re-run against the four:

1. **Why were these four square in Console?** They declared `border-radius` on none of the three boxes
   and bound none of the minted vars. Nothing to resolve, so nothing rounded.
2. **Why did the #227 A1 sweep not reach them?** Because it was a **hand sweep**. It found and repaired
   eight files; these four were not in the list, and nothing anywhere recorded that the list was meant
   to be exhaustive.
3. **Why could a hand sweep be incomplete without anyone noticing?** Because *membership in the
   segmented family was not written down anywhere.* `component-types.json` had exactly two groups
   (`button-family`, `dataviz`). The only definition of "which files contain a segmented control" was
   whatever the person sweeping happened to grep for that day.
4. **Why did no gate catch the absence?** Every candidate gate is **presence-checking on a declaration
   that exists**: `_validate_radius.py` validates the *form* of a `border-radius` it can see;
   `_gate_minted_consumption.py` asks whether a mint is read *at all* — and it was, by the eight
   repaired files, so the token looked healthy while four consumers of it were square.
   **An absence in an unregistered file is invisible to every instrument in the tree.**
5. **Why does this class keep recurring?** #227's B6 (the chart toggle), #227's A1 (eight by hand,
   four missed), #229's F1 (the button, absent in all twelve) — three recurrences, one shape:
   **N hand-maintained copies of one geometry contract, and no instrument that can say a copy is
   missing or a file is not in the set.**

**ROOT CAUSE (two parts, and both are now closed).**
**(a) No single source** — the geometry contract was twelve independent copies. Closed by the
`seg-concentric` PARTIAL: one text in the atom, injected into eleven consumers, `--check` red the
moment one drifts. **(b) No membership record** — a copy could exist outside the set and nothing could
say so. Closed by `$scan`, which enumerates the tree rather than trusting a list.

**Part (b) is the load-bearing half, and it is what makes this a class fix rather than a bigger patch.
The partial alone would NOT have caught these four** — they were not members, so a member-integrity
check would have looked straight past them, exactly as every other gate did. Stated plainly because
it is the thing that was missing all three times.

**RCA discipline (`s228-D7`) — tactical and permanent, paired and both enacted.**
Tactical: the four snippets repaired at source, through the mint path. Permanent: the group + scan.
Permanent-fix owner: **this lane** — it is built, wired and driven, not priced and handed on.

## 2 · What changed

### 2a · The atom — the geometry contract is now authored ONCE

`Segmented-control.reference.html`: the three `border-radius` declarations were **removed from the
three rules that carried them inline** and re-authored as the source PARTIAL block, with the reasoning
above sitting on it:

```css
/* ===== PARTIAL seg-concentric START (segmented) ===== */
.seg{border-radius:var(--seg-rad);}
.seg .ind{border-radius:var(--seg-thumb);}
.seg button{border-radius:var(--seg-thumb);}
/* ===== PARTIAL seg-concentric END ===== */
```

Cascade-identical (same specificity, later in source order, nothing else declares a radius on those
boxes) — and now it is **one text**, not thirteen. The button binding stays on the **base** rule, not
on `:hover`, so hover, focus-visible and any future state inherit the corner from the box (s229 F1).
The block **never names a scale**: the locals are scale-selected by each member's own rules, which is
what lets one text serve the atom's four-scale grammar, the charts' `s`/`xs` pair and the templates'
single scale alike.

## 8 · REPLAY-THESE

1. **The render env at `outputs/_render-env-229` DID survive** — contradicting the eye-repairs report's
   REPLAY item 1, which found it gone. It is on the **mount**, and the mount persists; what does not
   persist is anything in `/dev/shm` or the sandbox home, which is gone **between every bash call**.
   Saved ~5 calls. Budget the rebuild, but **`ls` first**.
2. **One path in the receipted recipe is wrong.** `LD_LIBRARY_PATH=$M/chromelibs/root/usr/lib/…` — the
   real path has **no `root/`** segment: `$M/chromelibs/usr/lib/aarch64-linux-gnu`. With the wrong one
   Chromium dies with `libXdamage.so.1: cannot open shared object file`, which reads as "the deb was
   never fetched" when the deb is sitting right there. Cost one call.
3. **Everything in a mutation drive must be in ONE bash call.** `/dev/shm` and `/sessions/<name>/` are
   both wiped between calls; only the mount survives. A scratch copy of `knowledge/` minus `assets/`
   is **11MB** and fits `/dev/shm` comfortably (`assets/` alone is 5.2GB — never copy the whole dir).
4. **A partial group is only half a class fix.** The member-integrity check is blind to non-members,
   which is the failure that produced the four. **Any group that accretes should get a `$scan` at the
   same time**, or the next file to grow the control is invisible again.
5. **Check your mutation arm's own assertion against the baseline before trusting its verdict.** A
   sentinel string that already exists in the tree makes a passing gate look like a failing one
   (§5, M3b). Measure the baseline first; use a sentinel that cannot pre-exist.
6. **`re.sub` does not rescan its replacement**, which is what makes `rootSelector` `.seg` →
   `:is(.seg, .dv-toggle-seg)` safe. Worth knowing before anyone assumes a multi-control member
   selector will recurse.
7. **A plain read-only `git status` from the sandbox can leave a stale `.git/index.lock`** that the
   sandbox then cannot remove — not `rm`, not `mv`. It is not only *writing* git commands that need
   the delete grant. See the handover blocker in §9.
