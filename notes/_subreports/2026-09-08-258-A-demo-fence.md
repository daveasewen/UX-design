## Two judgement calls, both recorded rather than ruled

**WRAPPERS — a demo class sitting ON or AROUND a component element gets a CSS-only fence.**
`.col-demo` (Amount-display), `.demo-card` (Avatar-group), `.demo-frame` (Card-header-lockup),
`.demo-w` (Cascader), `.demo-col`/`.demo-stack` (the three lockups) all WRAP the component — in
Feature-grid-lockup `demo-col` is on the component root itself (`class="fgl-outer demo-col"`).
Fencing that markup would delete the component, which is the one thing the acceptance rule forbids.
So only their CSS is fenced. The class name can still travel with copied markup, but it is inert
without the fenced CSS. If Dave wants the class name itself fenced, that needs a marker grammar that
can delimit an ATTRIBUTE, which the probe's convention does not have — not invented here.

**FRAMES — five files widen when the fenced frame CSS is deleted, and that is the frame doing its job.**
Measured at 1440, light and dark, sizes only (position ignored — removing a label legitimately reflows
the page):

| slug | root | with fences | after strip |
|---|---|---|---|
| CTA-lockup | `.ctal[0]` | 858 × 198 | 1360 × 198 |
| Card-header-lockup | `.ch[0]` | 318 × 46 | 1366 × 46 |

| Feature-grid-lockup | `.fgl-outer[0]` | 900 × 188 | 1360 × 126 |
| Filter-toolbar-bar | `.ftb[0]` | 858 × 102 | 1360 × 102 |

Height changes where a container query legitimately re-fires at the wider width (Card-header-lockup's
`.ch[1]` un-stacks, 102 → 46). No console or page errors in any stripped page. This is Cascader's own
declared discipline, in its header verbatim: the component "declares no max-width (width is the
container's)" — `s210-D3`. A component that fills its container once the demo frame is gone IS the
component rendering correctly, so I read these as the brief's "chrome-only regions" exception rather
than a break. Flagging it because it is the one place where a lane-A file's strip is not byte-neutral.
