a CSS *string* was not, and both are the same claim.

two files that grow on different cycles, and it has flapped six times in 25 commits (19.4% → 46.5%).

a chain not much smaller than GM "buys nothing and would be worse than nothing." *(`_CHAIN.md`
content was not touched — DO-NOT-TOUCH.)*

**Q2 — do three `@property` registrations belong in `canon.css`, globally?** Unblocking `[45]`
puts `@property --dvf1/2/3 {syntax:"<number>"; inherits:true; initial-value:1}` at **top level,
unscoped**, in `canon.css:7191–7193`. Every page linking canon now has those three custom properties
**registered and inheriting with an initial value of 1**. Two consequences to weigh: it is what makes
the bar-chart stack animation work at all (an unregistered custom property cannot be interpolated),
**and** a registered property with an initial value can no longer resolve to nothing — which is the
signal the dangling-var gate reads (`[[dangling-dataviz-var-renders-silent-black]]`). The C2 gate is
green (`147 file(s), 0 failure(s)`), so nothing is broken today. The question is whether component
at-rules should reach canon's global scope **at all**, or be namespaced the way `@keyframes` already
is at `gen_canon_components.py:169–173`. *(Namespacing is the same shape as the existing keyframes
rule and would be mechanical — but it changes what canon exports, so it is not mine.)*

**Q3 — should `gen_canon_components.py` get a wired `--selftest`?** It has none. The `ds-039` guard
has been load-bearing since #122, has now failed **falsely for seven days**, and has never been
proven to bite in a test. Wiring one needs a `STEPS` entry **and** a `ROUTE_ROWS` row in the same
edit (a step with no route aborts every full build above step 1). Priced **small**; not built,
