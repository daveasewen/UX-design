# #261 G — the grid header (Data grid column-header design pass)

**Component**: the column-header row of `data-grid`. **Not shared with `table`** — Table's header is a passive
`th scope="col"` that collapses to cards (rubric decision A, 2026-06-22); it is untouched. Fence:
`Data-grid.reference.html`, `data-grid.meta.json`, generated `showroom/data-grid.html`, my `notes/` files.

## What shipped

1. **Anatomy per column** — one `.th-in` flex row: truncating label · sort · optional 24px column filter · resize
   handle. Nothing can collide with the label any more.
2. **Group header row** — optional `th scope="colgroup"` row ("Transaction detail" / "Value (GBP)"), sticky at
   `top:0` with the column row sticking below it at `top:var(--grp-h)`. It COUNTS: `aria-rowcount` and every
   `aria-rowindex` shift by one when it is on (18 with, 17 without, on 16 matches).
3. **Sticky, provably** — the scroll region took a `max-block-size` (`--dg-vh`, 380px) so sticky is a driven
   state, not a promise. Sticky + `border-collapse` drops cell borders, so every header rule is an inset shadow.
4. **Per-column filter** — a form-furniture button (Search-field precedent: colour states, no press physics)
   opening a menu under its own cell; Enter commits, Esc closes. Off/on are two DIFFERENT library glyphs
   (`global-controls/filter.svg`, `filter-active.svg`), never one recoloured (icon-011). Filters became
   `{key, term}`, so a column filter chips as "Payee: acme"; the toolbar filter is the same shape with `key:null`.
   Amount ships WITHOUT a filter — the affordance is per-column.
5. **Resize** — 12px grip, 24px hit area, `role="separator"` + live `aria-valuenow`, driving `<col>` widths in a
   `table-layout:fixed` table (96–480px clamp). Pointer drag, and keyboard WITHOUT a second tab stop: `Alt+←/→`
   on the header cell enters resize mode, arrows size (Shift = 32px), Esc/Enter returns.
6. **Density** — `data-density` comfortable|compact: 44px header row and targets dial to 32px — above the 24px
   dial-down floor, never below (s116-D1).
7. **Disabled column** — Reference (the editable one) is not sortable: re-ordering rows under an open editor is
   the bug. `aria-disabled`, no `aria-sort`, no glyph, alpha mute.
8. **Sorted vs filtered take DIFFERENT EDGES** — sorted = ground + 3px accent UNDER, filtered = 3px accent
   LEADING, so a column can be both. Each doubled by a glyph and by aria; colour never alone.

## Two things that want Dave's word

1. **The group row has no ground of its own.** `--grouphdr` binds `table/column/background`, which resolves to the
   same hex as `table/header/background` in all four themes today, so the row reads by caption type and its rule.
   Either a theme splits the two tokens, or the group row stays a typographic distinction. **split** or **type**.
2. **The disabled column is muted with alpha, not `text/disabled`.** That token is #E1E1E1, illegible on the
   #F0F0F0 header ground; `.pbtn[disabled]` only works because pagination sits on the page. **alpha** or **token**.
