## 3. A THING THE BRIEF DID NOT ANTICIPATE — `--release` DEMANDS A CLEAN TREE

`--release` calls `require_clean` and refuses on any dirty path:

> `die "the working tree is dirty. A RELEASE is cut from a clean tree so that what is on GitHub and
> what is in the zip are the same thing — commit or stash first."`

The brief's step 5 expected **one** commit carrying the rulings, manifest, ledger *and* the zip. That
is **mechanically impossible**: the zip cannot exist until the tree is clean, so the pre-bake state
must be committed *first*.

**This is not a new decision — it is the established mechanism.** Both prior bakes did exactly this,
each landing a separate commit containing essentially only the zip:

```
9f58516  after #220 — Spider v1.0.1 BAKED…    apollo-spider/dist/Apollo-Spider-v1.0.1.zip | Bin 0 -> 18992272
                                              notes/_REHEARSAL-LOG.jsonl                  |   1 +
ef44b1a  after #219 — #219 THE BAKE…          apollo-spider/dist/Apollo-Spider-v1.0.0.zip | Bin 0 -> 13339337
                                              reviews/RELEASE-SPIDER-2026-08-26-v1.html   |   4 ++--
```

So the bake, when it runs, is **two commits**: pre-bake state, then `--release` on the clean tree,
then the zip + ledger. Recorded here so the next attempt does not rediscover it.

## 8. PITFALLS FOR WHOEVER PICKS THIS UP

- **Do not seed the ledger before the bake.** `s223-D5(3)` seeds *at* the bake; seeding against a
  surface holding no v1.0.2 zip writes a false row **and turns the laundering arm red at the bake** —
  measured by the #223 version-ratify sub, whose report §3.3 has the receipt.
- **The bake is two commits, not one** (§3). `--release` refuses on a dirty tree.
- **Any tree change means a new commit, a new manifest and a new zip sha.** Fixing F2 invalidates
  both twins. Settle Q1 and Q2 together before cutting.
- **The VERSION arm is ADVISORY and exits 0.** It will not stop a bake shipping a wrong version
  string. Findings print at the *bottom* of ~217 lines.
- **A dry-run rewrites the go/no-go page and strips the review overlay.** Re-inject with
  `_make_review.py`, and regenerate the page from the manifest you actually intend to ship.
