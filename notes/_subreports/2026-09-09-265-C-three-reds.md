   = containedBy, usedInContext, commonPattern, mustNotNeighbour, groupsWith, triggeredBy,

   That is why Filter-toolbar-bar's `$contract` reds — a `$`-sigil key that would be legal
   anywhere else in the file. Recorded because it makes the "demote to a sigil" repair
   unavailable inside `edges` specifically.

## RULING-SHAPED QUESTIONS

1. **`stateModel` as a rich object — widen the schema, or demote to `$stateModel`?** Four metas
   (Data grid, Filter-toolbar-bar, KPI tile, Legend) authored `stateModel` as an object; the
   schema says `enum: simple|full` and 23 metas comply. Option (a) widen: `stateModel` accepts
   `string | object`, the four metas stand as written, cost = the prototype-grade scorer's
   `simple` signal must learn the object form. Option (b) demote: rename the four objects to
   `$stateModel` (legal today under root `^\$`), leaving `stateModel` absent = the schema's
   default `full`, cost = a second promotion lane later. **Recommend (a)** — this is exactly the
   s263-D12 shape (a `$status` sigil promoted to a first-class `status` field on "whatever is the
   best standard solution"), and four independent authors reaching for the same richer shape is
   the signal that ruled `variants[].status` in.

2. **`with[]` — bare slug strings and a `when` clause.** Data grid carries six strings where the
   schema requires `{slug, rel?}`; Legend carries `{slug, when}` where `when` has no seat.
   Option (a) mechanical re-shape: `"pagination"` → `{"slug": "pagination"}`, Data grid's prose
   entry → `{"slug": "selection-controls", "$note": "…"}`, Legend's `when` → `$when`; cost = zero
   content, but it silently invents `rel` grades by omission. Option (b) move both to
   `knowledge/roles.json`, which s251-D6 already rules is complements' one home, and empty
   `with[]`; cost = a roles pass. Option (c) add `when` to the `with[]` item schema beside `rel`.
   **Recommend (a) + (c)** — the shape is mechanical and the `when` clause is the same kind of
   fact s253-D1 made first-class at the meta root.

3. **Four edge types with no schema seat: `drivesConsumer`, `composedOf`, `delegatesTo`,
   `$contract` (Filter-toolbar-bar).** Minting edge types is s131-D2 / s133-D1 territory and none
   of these four is in the ruled grammar. `composedOf` has an obvious home (`consumes`, or the
   `$composes` top-level convention 13 templates use); `drivesConsumer` and `delegatesTo` are new
   relations with real content (the s258-D1 event/attribute wiring contract); `$contract` is a
   `$`-sigil key that only reds because `edges` is the one schema object without `^\$`
   patternProperties (finding 2). Option (a) mint all four as typed edges; option (b) fold
   `composedOf` into `consumes`, move `$contract` to the meta root, and mint only
   `drivesConsumer`/`delegatesTo`; option (c) add `^\$` patternProperties to `edges` and treat
   the three prose edges as `$`-notes for now. **Recommend (b)** — one mint, and it names a
   relation the repo demonstrably has (a filter bar driving a grid) rather than blessing four.

4. **`provenance.source` — is `hand-authored` a word the enum should carry?** Legend claims it
   and has a real `code_path`. Option (a) mint `hand-authored` into the enum (it describes a real
   and growing class — components this repo designed from nothing); option (b) re-source Legend
   to `code`, since `knowledge/canon/dv-legend.js` is where its state machine actually lives;
   option (c) `gap-report`. **Recommend (a)** — #261 produced at least three metas that are
   neither Figma nor code nor gap-report, and forcing them into `gap-report` makes the field lie.
   The same question decides whether `redesign` (Footer, restored to `gap-report` in this lane)
   should come back as a word.

5. **`relationships.composes` / `$composes-verbatim` (Data grid) — where does composition live?**
   `relationships` is a closed shape with no composition edge; the repo's answer since #213 is a
   top-level `$composes`, but Data grid's `$composes` is already a PROSE STRING, not the
   `["component:x"]` list `gen_bento_matrix_217.py:1314` parses. So the fix is not a move, it is a
   decision about a field two consumers already read differently. Option (a) make `$composes` a
   list everywhere and put the prose in `$composes-verbatim` at root; option (b) promote
   composition to a real `edges.composes` edge type (question 3's mint, one type larger).
   **Recommend (a)** — it is the smaller change and it un-breaks the bento matrix reader.
