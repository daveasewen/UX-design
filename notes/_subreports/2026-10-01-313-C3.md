### The checks, as built

The verdict object is the spec's (§ 7), plus `catalogue.id`. `timing_ms.surface` or `.page` is `null` when that layer did not run. Only a `fail` fails the verdict. A result of `unmeasured` is stated with its reason and never counted as a pass or a fail.

- **S1** Every message is checked against `server_to_client.json`, with `catalog.json` resolved to our catalogue.
- **S2** Each part is checked against its own entry.
- **S3** There is one root.
- **S4** Ids are unique.
- **S5** Every slot reference resolves, and so does any other ComponentId or ChildList reference.
- **S6** A slot's child must provide what the slot accepts. `accepts.provides` is checked against the child's provides role, and `accepts.tier` against the child's level. Both are decisive. The capability `anything` passes. A capability equal to the child's slug passes by name. Any other capability is UNMEASURED, because no registry says which parts offer which capability.
- **S7** No deprecated part, read from `x-apollo.status`.
- **S8** A part's `state` must be inside its `x-apollo.states.states`, where the entry has that list.
- **S9** A data setting's series count must fit its shape. The bounds are read from the shape's own name: `1–5-series` gives 1–5, `single-series` gives 1, `two-series` gives 2. Shapes that state no count are not checked. A binding is resolved through the surface's own `updateDataModel` messages. The counting form is C3's reading, not a ruling: a number is the count; an object's `series` list is counted; so is a list of objects that carry `values` or `points`. This matches C4's `mock/data.json`, where `balance-30d` is `{"series": [{"name", "points"}]}`.
- **P0** The receipt, through `_validate_screen.gate_receipt` (non-strict, so NO-RECEIPT is UNMEASURED).
- **P1** The in-memory twin of `_validate_a11y.check()`. It uses that module's own `motion_fails()` (motion judged per part, `s305-D54`), its `analyse` engine and its tiers, all read at call time.
- **P2** `_validate_screen.gate_composition`.
- **P3** `_validate_screen.gate_icons`, with the icon library memoised in the process at warm-up.
- **P4** `_validate_screen.gate_compose`.

### Where this departs from the spec's [spec] choices

1. **The stand-in page.** R5 pasted each snippet's `<style>`. The stand-in now links `canon.css` and splices only markup, because `s307-D74` refuses pasted styles and P4 would refuse the page. Each part sits in its own `APOLLO-SPLICE … kind=markup` region named by the snippet it came from, so motion is judged per part. A snippet's inlined `AUTO-BEHAVIOUR` block is replaced by one `<script src="knowledge/canon/<name>.js">` per page, which is the way the receipt grammar addresses behaviour. The `APOLLO-DEMO` showroom fences are dropped. It is still a stand-in, not emitter E1 (`s311-D9`).
2. **S7 is reached through a catalogue mutation.** The catalogue never publishes a deprecated part, so R5's ViewOptions case is now refused by S2 as an unknown part (P11). S7 is proven on a copy of the catalogue held in memory, with Metric flipped to deprecated (N4).
3. **The metric tile carries no figure in the fixtures.** Metric has no setting for the number it shows (C1's finding, repeated by C4). The probe used `target`, but that setting is the measure to compare against, so the fixtures leave it out rather than misuse it.

## Found, not fixed

1. **The catalogue refuses every bound data value** (C1's generator, `apollo-launchpad/catalogue/gen_catalogue.py`; probe F2). A data setting is typed `oneOf [ {type: object}, {type: array}, DataBinding ]`. A `{"path": "/x"}` binding is also an object, so the `oneOf` matches twice and the binding is refused at S1 and S2. Only literal data validates today. That is why the fixtures carry their data inline. The likely fix is `anyOf`, or an object branch that excludes `path`. It changes the generator's output, so C1's `out/` must be rebuilt and the version bumped. Not mine to change: it is C1's API, and the lane header forbids regenerating shared outputs.
2. **The page-layer composition check cannot be proven on a legal composed page.** On the treasurer page, P2 returns `UNPROVEN: C9 bands`. `_validate_composition.check()` reads the bento column bands from the page's own CSS. A page that links `canon.css`, as `s307-D74` requires, declares none of them inline. So C9 span legality is UNMEASURED on every composed page that obeys link-don't-paste. The fix belongs in `knowledge/` (read the linked canon's bands), is a gate change, and needs a verifier.
3. **The motion clause reads script text** (probe F1). Since `s305-D54` splits a page into parts, the phrase "turns it into a transition:" inside dv-render's inlined comment trips 2.3.3 for the Chart-line part. That part's reduced-motion block lives in the snippet's `<head>`, not its body. The disk gate is not wrong about any snippet file, because each file is one part. It will be wrong on composed pages that inline behaviour. The stand-in avoids it by loading behaviour by address. The fix is in `_validate_a11y.motion_fails`: mask comments and script bodies the way `_validate_screen.markup_only` does. This is the same family as R5's K2, which is still a known miss.
4. **Two path-only gates force the `/dev/shm` write.** `_validate_compose.check_screen(path)` and `_validate_receipt.check(path)` each take a path. A `check_text(html)` split in each, a few lines apiece, would make the page layer write nothing. A compose split that takes the canon class set once would also stop the per-call re-read of `canon.css`. These are canon changes and need a verifier (spec § 13 item 4).
5. **No registry says which parts offer which capability.** Slots that accept by capability cannot be checked:
   - `brand-mark`, `navigation`, `breadcrumbs`, `footer` and `icon-button` on the frame
   - `trend-series` on Metric's spark
   - `filter-control` on the data grid's filters
   - `chart-dataset` on the legend's rows

   S6 is therefore UNMEASURED for the worked example's two frame slots, `brand` (Headers) and `primaryNav` (Navigations). Only `provides` and `tier` are decisive today. The wall's tiles slot accepts by `provides`, so the four kinds Dave kept (`s313-D41`) are fully enforced.
6. **The render leg was not run** (T3.6). There is no seat in this lane. Its price is one seat call: `export TMPDIR=/dev/shm; bash knowledge/_render/ensure_env.sh; source knowledge/_render/seat_env.sh; time python3 knowledge/_validate_screen.py --render <page>`. It needs a page on disk: run `gate_mem.splice()` on the treasurer fixture and write the result to `/dev/shm`. Not measured tonight.
7. **The selftest has not run at the seat.** The seat's own python carries jsonschema 3.2, so the surface layer needs `$HOME/.launchpad-venv`, as C1's harness does. The page layer imports the seat's `knowledge/` modules unchanged. The code assumes Python 3.8+ (audit hooks) and nothing newer. Seat run owed: `PYTHONDONTWRITEBYTECODE=1 $HOME/.launchpad-venv/bin/python apollo-launchpad/gates/selftest.py`.
