## Findings

1. **⬛ THE FIX IS ONE INDEX BECAUSE ADR-0014 MADE THE DNA TIER LOAD-BEARING, AND I CHECKED THAT IN
   THE ARTEFACT RATHER THAN THE ADR.** `canon.css` declares `--color-neutral-*` at `:root` and
   supercharge's theme block **overrides all twenty** onto the warm ramp — measured, 20 DNA-tier
   declarations in `[data-apollo-theme="supercharge"]`, **none** in legacy's or console's. So one
   `css_var` gives four theme-correct answers. Had the tier been documentation only, this lane
   would have had to hand-pick four greys, and the brief's pitfall (hex-similarity vs lift) would
   have been live rather than discharged.

2. **⛔ THE MANIFEST WOULD HAVE REPORTED CONSOLE AND SAID NOTHING ABOUT THE THREE THEMES THAT
   MOVED.** `_bento_edit_rails.json` is what the library page reads (s219-D3(6)); its mint rows
   hang off **chord members**, and the capsule chord is console-scoped. Three values would have
   moved with no row naming the decision ([[no-gate-parses-the-artefact]]). Fixed at cause: a new
   scope-independent `caption_ground_mints` block — four rows, the band, the lift before and after,
   and `reachable_here` reported as **X6 reachability, explicitly not permission**. Driven by
   `C4k`.

3. **⚠ NEW — SUPERCHARGE'S DARK PAGE IS NEUTRAL WHILE EVERY ONE OF ITS SURFACES IS WARM, AND
   NOTHING HERE FIXES IT.** `[data-apollo-theme="supercharge"][data-theme="dark"]` declares
   `--background-default: #1A1A1A` **as a literal**, where the other three themes alias
   `var(--surface-digital-black)`. Under ADR-0014 supercharge's anchor is `neutral/4 → warm/2`
   `#13110E`, so its dark page "should" be warm and is not. **Consequence for this lane:** the lift
   for supercharge was solved against `#1A1A1A`, which is what the browser actually paints — not
   against what the token tree implies. If that page value is ever corrected to `#13110E`, **the
   supercharge lift changes** (`#312C26` over `#13110E` is ΔL\* **+13.18**, over the band). This is
   almost certainly the standing **SC-dark-awaits-Dave (G14)** item; it is named here because a
   lane that measured the paint and never said which premise it stood on would be storing up a
   silent regression. Price to prove which is intended: one question to Dave, ~0 tk.

4. **⛔ A REAL GATE FIRED ON THE CORRECT ANSWER, AND WIDENING IT WOULD HAVE BLINDED IT.** Bite
   `12` ("every authored colour is a NEUTRAL") went red on `#312C26` — spread 11, over its
   threshold of 8 — because supercharge's ruled warm step is chromatic **and right**. Raising the
   threshold would have admitted every warm hex, which is exactly the class Dave cannot judge by
   eye ([[colour-stability-red-yellow-problem]]). **The gate was SPLIT instead, and the split made
   it stricter:** (a) authored bare hexes — still zero chromatic; (b) `var()` fallback literals — a
   chromatic one is legal **only if canon itself resolves that token to that value** in some
   theme × mode. The proof page's own build script and probe carry the same split (three themes
   asserted `R=G=B`; supercharge asserted **monotone warm** and no warmer than its own ramp's
   widest step, 13).

5. **⛔ THE NEW DRIFT ARM IMMEDIATELY CAUGHT A PRE-EXISTING STALE LITERAL — AND THEN A SECOND
   LAYER OF IT THE FIRST ARM COULD NOT SEE.** `var(--border-strong,#767676)`: `#767676` is
   `color/grey/600`, and canon resolves `--border-strong` to `#808080` (mono/legacy/console) or
   `#524842` (supercharge). **In no theme and in no mode is it `#767676`.** Nothing painted
   differently (canon defines the token, so the fallback never ran) — which is precisely why it
   survived: an unrun fallback is invisible until the var goes dangling, and then it paints a
   colour nobody chose. **Three declaration sites** corrected
   (`gen_bento_matrix_217.py:1813`, `gen_foundations_217.py:608` and `:866`).
   ⚠ **THEN THE SECOND LAYER.** The page declares `--bm-line-2: var(--border-strong,#808080)` and
   **consumes** it as `var(--bm-line-2,#767676)` in **eight** places. Canon has no opinion about
   `--bm-line-2`, so the first arm correctly skipped them and they were governed by nothing at all.
   Bite 12 gained a second arm — *a fallback on a PAGE-LOCAL alias must be the literal that alias
   itself declares* — which went red on all eight; all eight corrected. This is the honest shape of
   [[gate-dont-patch]]: the first fix was a patch until the second arm turned it into a class.

   ⚠ **The gate lives in `gen_bento_matrix_217` bite 12 only.** `gen_foundations_217` has no twin
   (it has no page-local `var(--line-2, …)` consumers today, checked — but nothing stops one
   appearing). Price for the twin: ~2K tk.

6. **⛔ A REFUSAL NAMED THE FIRST OBSTACLE, NOT THE BINDING ONE — AND THE BRIEF'S OWN INSTRUCTION
   WALKED INTO IT.** Extending bite `6f` to all four themes went red: only console's message
   contained "MODE-FLAT". For the other three `validate_settings` refuses **first**, because
   `darkgrey` is not in their X6 option set at all — so the mode-flat mint fence is **never
   reached** there and an arm that stopped at the refusal would have proved the wrong thing
   ([[refusal-names-the-first-obstacle]]). `6f` now records **which fence answers in which theme**,
   and **`6g` drives the binding one**: it widens the capsule chord's `scope` (the one place chord
   reach is data), asserts every theme's mode-flat refusal by name, then restores the scope and
   re-asserts the ruled console-only reach.

7. **⛔ ROUNDING AN INTERMEDIATE MOVED A NUMBER THE PRIOR LANE HAD MEASURED IN A BROWSER.**
   `caption_lstar` first rounded L\* to 2dp; differencing two rounded values gave ΔL\* **11.07**
   for the pair the `#220` rung lane measured live at **11.06**. Caught by bite `C4i` asserting the
   recorded figure rather than whatever the code produced. `caption_lstar` now returns full
   precision and callers round the **difference**, once. A page and a manifest printing two
   different numbers for the same pair of colours is the class this whole lane sits inside.

8. **⚠ THREE OF THE FOUR MINTS HAVE NO CONSUMER IN ANY SHIPPED ARTEFACT, AND THE PROOF PAGE IS
   DELIBERATELY THE ONE THAT DRIVES THEM.** `bento-rails.html` pins `darkgrey` specimens in
   **console only**; the explorer refuses the ground elsewhere (X6). So mono/legacy/supercharge's
   new declarations paint nothing anyone can currently reach
   ([[instrument-without-a-consumer]]). They are driven in the browser on
   `reviews/THEME-LIFT-2026-08-27-v1.html`, four themes × dark, rendering through the enacted rules
   with no override. **This is the shape the `#220` rung lane's question 3(b) warned about — "three
   themes get a value change nobody can currently see" — and the answer is that Dave can see it,
   on that page, before he rules.**

## RULING-SHAPED QUESTIONS

*(All five are Dave's. Nothing below is decided and the proof page says so in its own footer.)*

1. **⬛ THE BRIEF'S NAMED VETO — the shipped LIGHTEST-GREY caption default. NOT ENACTED, and the
   reason is a RAMP GAP, not caution.** Mono and Console both ship `capBg: grey`, which in dark
   resolves `#1F1F1F` on a `#1A1A1A` page — **ΔL\* +2.49**, nearly as invisible as the ground that
   was just fixed. It cannot be lifted into the band: the band member is `--color-neutral-5`, and
   pointing `grey` at it too would make **two chord options the same colour with two different ink
   rules**, which stops the option being an option. The primitives below it are
   `raise-2` (**+4.45**, short by 4.55) and `raise-3` (**+6.37**, short by 2.63) — both drawn on
   the proof page, §5, with the shortfall printed. Options: **(a)** leave it; **(b)** move the
   shipped default onto the now-working `darkgrey` ground (a **default** change, no new value);
   **(c)** add a ramp step between `raise-3` and `5` — **a promotion, and promotions are Dave's**.
   ⚠ Under (a) the state the gallery actually ships in stays nearly invisible in dark; under (b)
   the default changes colour and ink token together; **⛔ no value was invented, per the brief.**

2. **Supercharge: warm or neutral?** Enacted **warm** (`#312C26`), because ADR-0014 rules the warm
   ramp for that theme and the DNA tier resolves it automatically. The neutral answer would be
   `#313131`, **ΔL\* +11.06** — the exact calibration, and a neutral grey inside a warm theme.
   Both numbers are on the proof page. ⚠ And see finding 3: the choice interacts with supercharge's
   **neutral dark page**, which is itself unresolved.

3. **Is `raise-3` the better supercharge answer?** `#322E29`, **+9.93**, numerically nearer the
   calibration than the pick's +9.08. Refused for provenance (calculated vs observed) and semantics
   (elevation family), not for taste — see the pick table. One word from Dave flips it; it is a
   one-line change to one table row.

4. **Does a SEMANTIC role get minted?** Unchanged from `#220`: the binding reads the **primitive**
   directly, which ADR-0014 says consumers should not do. Honest for a PROPOSED value with no role
   yet, wrong as a permanent shape. **(a)** leave it on the primitive while proposed; **(b)** mint
   a caption-ground role with a light and a dark value together — a promotion. ⚠ Under (b) the
   mode-inversion problem returns as a token-design problem, because the pair has to answer light.

5. **Does the chord open to mono / legacy / supercharge?** **Untouched — still expressly open**
   (s219-D3(3)/X6), asserted by new bite `C4j` in the generator and re-read in the browser. What
   changed is only what the ground **would** paint. ⚠ The stakes moved in Dave's favour: granting
   one of them the ground now hands it a working ground rather than a vanishing one.
