## 2 · What I built — `knowledge/_jev.py`

Stdlib only (`urllib`, `json`, `re`, `time`, `datetime`). **No dependency on `typesafe-sdk`**,
though lane J measured it installs clean. The wire protocol is one POST of one JSON object;
urllib is enough, and the SDK can be swapped in behind the same `ask()` signature later if its
retry policy earns the pin.

Public API:

| name | contract |
| --- | --- |
| `available() -> bool` | key readable and non-placeholder. **Does not touch the network.** |
| `ask(state, questions, model=, note=) -> dict` | one POST, one attempt, one receipt line |
| `noul(...)` / `choice(...)` / `score(...)` | question builders for the three documented types |
| `html_to_state(path, cap=6000)` | strips an HTML artefact to text, **reports** truncation |
| `models()` | `GET /v1/models`; no receipt (asks nothing about an artefact) |
| `validate_questions(q)` | local schema check, so a malformed question costs no request |
| `redacted(key)` | the only representation of a key allowed in this process's output |
| `JevUnavailable` | **no oracle — never a fail** |
| `JevError` | reached and refused; `.error_type` carries the typed discriminator |

**The oracle rule is enforced in the type system, not in a comment.** No key, no route, or a
timeout raises `JevUnavailable`; only a reached-and-refused API raises `JevError`. Selftest
arm 11 drives that branch. A caller that turns an absence into a red build has invented a
defect, which is the shape of a gate that cannot fail honestly.

**Error handling branches on the body's `error_type`, not the status code** — lane J measured
403 where `api.md` declares 401. Arm 8 asserts both statuses type identically, so a later
tightening to `== 401` breaks a test instead of breaking silently in production.

**No retry.** 429/529 raise with the typed body intact. Backoff is a budget decision and
belongs to a caller that knows its own budget, not to the transport. Stated in the CANNOT
block rather than left to be discovered.

**Secret handling.** The `Authorization` header is constructed inside `_post`/`_get` and
referenced nowhere else, so no message, log line or receipt can reach it. `load_env` reads
`.env.local` directly and deliberately does **not** export into `os.environ` — a secret in the
process environment leaks into every subprocess and crash dump downstream.

### 2.2 — A real bug the selftest caught before the live call

The first env parser stripped inline comments **before** quotes. On
`TYPESAFE_MODEL="jev-latest"   # note`, the quoted branch did not fire (value did not end in a
quote), so the comment branch returned the literal string `"jev-latest"` — **quotes included**.
Status line, verbatim:

```
$ python3 knowledge/_jev.py
jev adapter — oracle AVAILABLE · key apikey_…[redacted] · base https://api.typesafe.ai · model "jev-latest"
```

That would have posted `"jev-latest"` with quote characters as a model id and earned a 422.
Fixed to quote-first, comment-second; `E="quoted"   # and a comment` and `F=has#hash` added to
arm 1 as regression cases. **Caught by printing the resolved config before spending a request,
not by spending one.**

## 3 · The model id — `jev-1.13.0` was wrong, and interestingly wrong

`.env.local` shipped `TYPESAFE_MODEL="jev-1.13.0"`. Verified live:

```
$ python3 knowledge/_jev.py --models
{
  "models": [
    { "name": "jev-latest",
      "description": "The latest iteration of TypeSafe's System One Model: Jev",
      "release_date": "2026-09-10T18:38:01.391457+00:00" },
    { "name": "jev-preview",
      "description": "A preview version of `jev-latest`: should be better in most ways",
      "release_date": "2026-09-10T18:39:06.057655+00:00" }
  ]
}
```

**Measured: only two requestable ids exist — `jev-latest` and `jev-preview`. `jev-1.13.0` is
not among them.** It is the concrete version the API *echoes back* in `response.model` (it is
what `api.md`'s response examples show), not an id you may *send*. The two are easy to confuse
because the docs print `jev-1.13.0` in every sample response and never in a sample request.

Both live calls below confirm it from the other side: request `jev-latest` → response
`"model": "jev-1.13.0"`. So the number in `.env.local` was *true* and *unusable*.

I edited the single `TYPESAFE_MODEL` line of `.env.local` in place and verified by checksum
that the key line was untouched:

```
$ KEYSUM_BEFORE=$(grep '^TYPESAFE_API_KEY=' .env.local | shasum | cut -c1-12)
$ sed -i 's|^TYPESAFE_MODEL=.*|TYPESAFE_MODEL="jev-latest"   # was jev-1.13.0 …|' .env.local
$ KEYSUM_AFTER=$(grep '^TYPESAFE_API_KEY=' .env.local | shasum | cut -c1-12)
key line unchanged: YES
```

`DEFAULT_MODEL` in the adapter is also `jev-latest`, so an absent override lands on a valid id
rather than a stale pin.

### 4.3 — Latency: measured vs declared

| | measured (wall clock, incl. TLS) | declared (`models.md`, lane J) |
| --- | --- | --- |
| Noul | **703.3 ms** | 70–500 ms |
| Score | **683.6 ms** | 70–500 ms |

**Both calls exceeded the top of the declared band, by 1.37× and 1.37×.** Recorded, not
smoothed. Two honest caveats, neither of which closes the gap on its own: (a) these are
whole-request wall-clock times from a Cowork sandbox including DNS, TLS handshake and one
transatlantic round trip on a cold connection — TypeSafe's band is presumably server-side
inference time; (b) n = 2, on one artefact, so this is an observation, not a distribution.
Anyone quoting 70–500 ms inside Apollo should quote **~700 ms measured end-to-end from this
sandbox** instead.

## 7 · What surprised me

1. **The Score came back saturated: 1.0 / 0.0 / 0.0, confidence 1.0.** A model sold on
   calibration put *all* its mass on one level of a three-level rubric it had never seen
   before, on an artefact type (a rendered design document) for which lane J found no published
   number at all. The Noul, on the same state in the same minute, returned a nuanced 0.85.
   I do not know whether the 1.0 means the rubric was well-separated or whether Score saturates
   more readily than Noul — but **n = 1 confidence of exactly 1.0 is the number I would least
   want anyone to build a threshold on**, and it is the first thing a third call should probe.
2. **The docs print the model id you may not send.** `jev-1.13.0` appears in every sample
   *response* in `api.md` and in no sample *request*; `GET /v1/models` lists only the two
   aliases. The `.env.local` value was copied from the right place and was still unusable.
3. **The fetch tool deduplicated `api.md` across lanes.** Lane J fetched it 1386 s earlier;
   lane J2's fetch returned a "re-use the earlier result" notice — content lane J2 never had.
   Within a single lane that is a saving; across lanes it is a silent hole. `curl` into the
   sandbox is the workaround, and probably the default for any lane that needs doc text.
4. **Lane J's 403-not-401 finding was load-bearing within the hour.** It is the reason the
   error path branches on `error_type`. Researching the *error* shape, not just the success
   shape, paid inside one session.
