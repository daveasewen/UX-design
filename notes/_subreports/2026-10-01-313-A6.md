### Call 28: the runbook index date (s313-D47), `knowledge/gen_runbook_index.py`
- The line used to read `last generated <today>`. It now reads `newest runbook change <date>`. `newest_runbook_change()` works it out with read-only git calls only (`git diff --quiet HEAD`, `git ls-files -o`, `git log -1`, never `git status`):
  - a runbook that is edited but not committed, or new and untracked → today
  - otherwise → the committer date of the last commit that touched `knowledge/_RUNBOOK-*.md`
  - in a shallow clone, where that commit is the clone's boundary (CI, cloud lanes) → the true date is unknown, so the stamp already on disk stands; with no stamp on disk it prints the boundary date and says that is what it is
- Fixture repo (scratch), both ways:
  - committed runbook on 2026-08-03, then a later commit that touched no runbook → `2026-08-03 (last commit touching a runbook, f0594736)`
  - runbook edited → `2026-10-01 (uncommitted runbook change)`
  - new untracked runbook → today
  - reverted → back to `2026-08-03`
  - depth-1 clone → `shallow clone boundary …`
- In this cloud worktree, which is shallow: `('2026-09-07', 'shallow clone — the stamp on disk stands')` once the stamp exists. The first run has to happen at the seat, which has full history, so the committed stamp is the true date.
