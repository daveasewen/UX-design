## The deliverable, in one paragraph

The v3 ship list is **generated, not hand-kept**. `knowledge/_release/_gen_v3_manifest.py`
enumerates the cut from a *named commit* via `git ls-tree`/`git archive`, import-probes every gate
by **running** it in an isolated staging directory, and writes
`knowledge/_release/_v3_manifest.json`. `designer-skills-v3/build-designer-pack.sh` reads that
manifest and bakes — from the same commit, never the working tree — into a deterministic zip.
Dave's go/no-go surface, `reviews/RELEASE-V3-MANIFEST-2026-08-26-v1.html`, is generated **from the
manifest**, so the page and the ship list cannot drift and be believed separately.

**Nothing is baked.** `designer-skills-v3/` holds the build script and nothing else. No zip exists
in any `dist/`. v1 and v2 are untouched. Per `s219-D4(2)`, the release is Dave's word: the script
**refuses** `--release` while the manifest's status reads `PROPOSED`.

## The gate verdict table is MEASURED, and here is exactly how

The brief said *driven not guessed*, and reading an import block by eye answers the wrong
question. "What does it import" is not "does it run outside this repo". So:

1. The non-gate shipped set is materialised at the commit into `/var/tmp/<stage>/pack/`.
2. Each `_validate_*.py` / `_gate_*.py` is copied in **with its local import closure** (computed
   by AST, transitively) and **run**, cwd inside the stage, `PYTHONPATH` pointing only at the
   pack's own `knowledge/`.
3. The exit is classified by what the run SAID, never by what the source imports.

**Four discriminator arms, each of which caught a real misclassification during the build:**

- **Courteous refusal.** `_validate_state_contrast.py` catches its own `ImportError` and prints
  `COULD-NOT-ASK: the 'playwright' module is not installed`. Matching only the literal
  `ModuleNotFoundError:` called it RUNNABLE and hid a real dependency. The needle is the phrase
  `No module named 'x'`, not the exception class.
- **The differential.** A clean non-zero exit is a verdict — *unless* the red is caused by the pack
  not carrying the thing being audited. Every FAIL is re-run against a **full-tree `git archive`
  stage of the same commit** (never the repo itself — a validator that writes an audit file must
  not dirty Dave's tree, #158 class). FAIL in pack + PASS in full tree ⇒ REPO-BOUND.
- **The subject test, anchored.** The differential is confounded when the full tree ALSO fails for
  an unrelated reason (`_validate_queue_fresh.py` does). So failure messages are additionally
  scanned for missing-language lines (`does not exist` / `not found` / `cannot read` /
  `UNPARSEABLE` / `nothing to check`) and the paths named *in those lines* are tested against the
  shipped set. ⚠ The first cut of this matched bare path-shapes anywhere in the output and
  therefore called `_validate_token_forks.py` repo-bound off the line
  `glob : knowledge/canon/*.css (2 file(s))` — which is the file it successfully READ. Sentence
  context is part of the needle.
- **The vacuous pass.** `_validate_no_hardcode.py` exits 0 with *"passed (0 tranche file(s))"* — it
  graded nothing and called it green. In the pack that is correct and expected (the tranche dir is
  the designer's own work, which does not exist yet), but a green that graded zero must never be
  presented as a green that graded something. The population is measured from the gate's own
  output and declared beside its verdict. ⚠ The first cut of THAT matched any `0 <word>(s)` and so
  read `135 snippet(s), 0 failure(s)` — a gate that graded 135 files and found nothing wrong — as
  vacuous. Zero *failures* is the good news; only zero *files* is an empty subject.

## Reproducibility — driven, not asserted

`git archive` at a named commit gives byte-stable content. The two things that would still move
are the mtimes and the build-day stamp, so both are pinned to the **commit's** own timestamp
(`%ct` / `%cI`), not to today. The zip is written by `zipfile` with fixed `date_time`, sorted
entry order, fixed external attrs, no extended-timestamp extra fields, and one root folder.

**Proved, this lane:** two `--dry-run` bakes into two different throwaway directories produced
`sha256 5288358d07aa8945c2ea75d8f18cf017c5e1a20d11f10df64b1edeaae187bc07`, identical. Then
`--check` against the commit: GREEN. Then two mutations, each seen RED by name — one byte added to
`knowledge/tokens/colour.json` ⇒ *"1 file(s) differ from the commit's blobs: knowledge/tokens/
colour.json"*; `knowledge/canon/type.css` removed ⇒ *"1 manifest path(s) MISSING from the pack:
knowledge/canon/type.css"*.

⚠ **One real bug caught by running `--check` twice.** The first cut found the pack README by
substring match over a **set** of names, which also matched `knowledge/README.md`; set iteration
order is hash-randomised per process, so the same zip checked twice gave different answers. A
non-deterministic check is worse than no check. Now addressed exactly: `root + "/README.md"`.

## RULING-SHAPED QUESTIONS — Dave's, not mine

All six are on the review page as cards except Q5/Q6, which are noted here for the conductor.

**Q1 — Does the Memento half ship an EMPTY store, or none at all?** *(the brief asked me to check
this; here is the answer)* **memento-package ships NO store of any kind** — not a chain, not a
rulings store, not a task store, not even an empty one. Its machinery list is five `.py` files plus
`_consult-lexicon.json`, and `_MACHINERY-MANIFEST.md` states the reason: *"`_CHAIN.md` /
`GOOD-MORNING.md` / `_LIVE-STATE.md` — Apollo content, not mechanism. The package ships the
generator; each adopting project grows its own chain."* Mirroring that exactly means a designer
unzips v3, says good morning, and Memento has nowhere to write. **Proposed shape if he wants them
productive on day one:** three empty stores — a task store holding an empty item list, a rulings
store holding an empty ruling list, and *no* chain file (its absence is the signal the ratified
boot rule reads to know this is a new project). Empty shape = machinery; filled shape = the record;
the #64 boundary holds either way.

**Q2 — Do the licensed desktop fonts travel in the zip?** TASTE + LICENCE. The `.gitignore`
justifies tracking them because *"repo is private and shared only in-licence"*; a GitHub zip is a
wider audience than the repo. 8.15 MB of 33.8 MB, so it is also the largest lever on download size.
Currently PROPOSED-IN, per the lane brief's exclusion list naming only *fonts beyond `_desktop`*.

**Q3 — Do the canon GENERATORS ship, or only the minted CSS?** TASTE. v2 shipped the stylesheets
only. `s219-D4(1)` says *as close to what I use as possible*, and what Dave uses is the generator.
Currently PROPOSED-IN (all of `knowledge/canon/`, four generators included) because the gates ride
along too.

**Q4 — Which runbooks are design-facing?** TASTE. Eleven proposed IN; seven held OUT as
Memento-internal (capture-ritual, git-commit, context-gauge, parallel-conductor, dream-pass,
decision-audit, densify-adversarial). memento-package ships **no** runbooks at all, so mirroring it
holds all seven out — which is what the manifest currently does. The awkward one is
**capture-ritual**: it is the ritual that makes Memento work, and a designer with the machinery and
no capture ritual has a chain that never grows.

**Q5 — All 100 guidelines, or v2's filtered set?** NOT on the page; flagged here. v2's script

`design-system-processes.md`, the accessibility-management/QA/hub set, `_INGESTION-QUEUE.md`,
`_RECONCILIATION.md`) on the stated grounds that *"this folder is the design reference, not the
workshop"*. `s219-D4(1)` widens the cut, so v3 currently ships **all 100**. If that reads as
smuggling the workshop back in, the v2 exclusion list is one constant away.

**Q6 — Memento's machinery ships TWICE.** `memento-package/machinery/` (the Copilot-side copy) and
`memento-package/claude-plugin/memento/machinery/` (the plugin copy) are byte-identical by design
and delta-audited by `_validate_package_delta.py`. The manifest mirrors memento-package and ships
both, ~120 KB duplicated. Legitimate — they are two delivery surfaces — but if v3 only ever hands
designers the Claude plugin, one copy is dead weight in the zip.
