## CORE REQUESTS — verbatim, for whoever owns `knowledge/canon/dv-render.js`

> **1. Let a type decline the axis furniture.** `dvRender` calls `furniture(ctx, …)` before
> `draw(ctx)` for every type, and there is no switch. An axis-free type (s182-D2) can only get rid
> of it by emptying `ctx.out` as its first statement, which is what `dv-render-sparkline` does.
> Requested: honour an optional `fn.furniture === false` on a registered type function, alongside
> the existing `fn.axis` and `fn.domain`, and skip the furniture pass when it is set.

> **2. Let a type decline the zero floor.** `dvRender` applies `if (lo > 0) { lo = 0; }`
> unconditionally after consulting `fn.domain`, so `fn.domain` cannot express a domain that does not
> touch zero. That is dv-bar-009 and it is right for a bar, whose LENGTH is the value; it is wrong
> for a trend, whose job is SHAPE — an index running 82→111 against a zero floor is a flat smear in
> the top fifth of the box. `dv-render-sparkline` therefore ignores `ctx.min`/`ctx.max`/`ctx.ticks`
> and computes its own scale. Requested: apply the zero floor only when `fn.domain` is absent, or
> gate it on an optional `fn.zero !== false`.

> **3. `data-fx` has no circle branch.** `dv-behaviour`'s x pass handles `rect`, `text`, `line` and
> `g` only, so a `circle` mark cannot carry its own x fraction and must be wrapped in a
> `g[data-fx][data-x0]`. Three of six type partials draw point markers. Requested: a `circle`
> branch that sets `cx` (the `.dv-mk` glyph contract already covers `cy` in `fitY`).

## RULING-SHAPED — Dave's word, not a lane's

1. **The engine's status vocabulary and s182-D3 name DIFFERENT COLOURS for this atom.** s182-D3
   ruled the spark's stroke onto rag/*-**INK** — "the rules for colours should just follow the red
   and green ink colours for all themes", and for the neutral "the default ink near-black colours
   are fine for the neutrals, white on dark". `canon.css` binds `--status-negative/positive/neutral`
   to rag/*-**GRAPHIC** and rag/**INFORMATION**: graphic red is `#F3543E`, not the two-red law's
   `#DA1A00`, and `--status-neutral` is `#6893D3`, **a blue where Dave said near-black**. Left
   alone, the engine would have repainted a ruled atom. **What I did, declared rather than decided:**
   the partial stays on the ruled vocabulary (`var(--status-*)`, the only vocabulary the engine has),
   and the SNIPPET re-points those four names at the ink inside its own `[data-theme]` blocks — which
   `gen_canon_components.py` lands as a `.cn-chart-sparkline`-scoped alias in canon.css, so the
   override cannot leak to another chart. **No value is minted**; every hex is the one `--spark-*`
   already declared. The driven colours above are therefore the RULED ones. **The question for Dave:
   should the s184-D3 status vocabulary carry an ink leg, or should atoms keep aliasing it?**
2. **A spark drawn by the engine now carries an invisible `<table>` spine, and s182-D2 said the atom
   is the graphic and its one tip.** The engine's whole progressive-enhancement contract is that the
   SVG ships EMPTY, so with JS off an engine-drawn spark with no table is *nothing at all* — a
   regression on the baked atom, which at least drew. s182-D2 removed the table **CTA** and the
   `<details>` **disclosure** (Dave's words are about the affordance: "the table cta can be optional
   in the trend card component"); it did not say the data must vanish. So the spine ships **sr-only**:
   no summary, no toggle, no visible surface, and the atom looks exactly as ruled. **Whether an
   engine-drawn atom may carry an invisible spine at all is Dave's, not a lane's.**
3. **The inline scale cannot join the engine while the spine is non-optional.** A decorative,
   `aria-hidden` mark and a mandatory announced data table are incompatible by construction. Either
   the engine learns an explicit `decorative: true` spec flag (no table, no accessible name, the
   composed tile carries the meaning), or the inline scale stays baked forever. Same shape as lane
   A's cb3/cb5 finding: **the engine's one-size contract meets a ruled exception.**
4. **`markers: true` is a spec field the ruled shape does not have.** The brief asked for optional
   min/max markers; s249-D4's spec is `{type, categories, series, format, unit, caption,
   categoryLabel, label}`. The core's `validate()` ignores unknown keys, so it works — but it is an
   undeclared extension of a ruled contract, used by one type. Declare it or drop it.
5. **`data-fxs`/`data-ys` on a component that never fits.** Because DV-D02-A forbids `dv-fit` here,
   this component authors the library's fit grammar and nothing consumes it. That is either correct
   (one grammar, universally spoken, so a future consumer inside a fitting container just works) or
   it is dead weight in a byte-capped payload. Not a lane's call.
