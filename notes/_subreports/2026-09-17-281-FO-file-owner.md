first. Governance is pass A and the guideline-rule family is pass C, so the file always landed in

## Findings

### 1 · Where the artefact node is minted, and which pass wins — the census was right, and I verified it rather than repeating it

`extract_extra()` mints an artefact node in three places:

- **pass A, governance** — `gov_target(entry)` falls through to `add('artefact:' + entry, …,
  'governance')` for every `governs` entry of every ruling that is not a component or a snippet.
  731 distinct artefact paths are named this way.
- **pass B, guidelines** — the WCAG verification scripts, `add(aid, part, 'guidelines')`.
- **pass C, the rule family** — `_rule_nodes.json` declares 51 artefact nodes of its own, added
  with `RULE_FAM`.

Pass A runs first, and passes C/D/E each open with `if n['id'] in base or n['id'] in nodes:
continue` — "never restate a node another family owns". That line is right and stays; the defect
was that it also **discarded the claim**. The file's fam was therefore decided by source order in
one function, which is exactly what Dave called an accident rather than a decision.

There is no `artefacts` key on a ruling: the artefacts Dave means are the `governs` entries. The
ruling is worded for what is in the file.

### 3 · The fix is a kind map, and a kind it does not know is reported, never guessed

```python
ARTEFACT_KIND = (
    (lambda p: p.startswith('knowledge/guidelines/') and p.endswith('.md'), RULE_FAM, 'guideline file'),
    (lambda p: p.rsplit('.', 1)[-1] in ('py', 'sh', 'js', 'mjs'), 'governance', 'repo tool'),
)
```

Pass F is deliberately the **last** pass, so the claims are complete however the passes are ordered
— re-ordering A–E now changes nothing at all, which is the property the ruling actually asks for.
A tied node of a kind the map does not name keeps the family it has, is marked `UNRESOLVED` in its
own `tie` sentence, and is **printed** by the builder, so the next such file is a question for Dave
rather than a silent decision. Today that count is 0.

Pass F adds no node, removes no node, invents no edge and moves no edge. A base node is never
re-homed: the base graph owns what it owns, which is the 1.11/1.12/1.15 rule, unchanged.

### 4 · The ruling's own line still lands

`s281-D2` requires that a ruling naming the file still draws its artefact line to it. It does, and
nothing had to be done for it: the `governs` edge keeps `fam: 'governance'` and its target id is
unchanged. On the re-homed node the INSPECT record shows both relation groups —
`definedIn ×19` (the guideline-rule family's own line, now drawable) and `governs ×1` (the
Constitution's, marked CHIP OFF at that setting). The Constitution loses nothing.

### 5 · Two artefact nodes under `knowledge/guidelines/` stay in governance, and should

`artefact:knowledge/guidelines/_rules-index.json` and `artefact:knowledge/guidelines/` (the bare
directory, as one ruling wrote it) are named by rulings only — the rule index does not name them,
so they are **not tied** and pass F never touches them. That is the correct scope: `s281-D2` rules
on a file two records both name. Re-homing them on a "everything under guidelines/ is a guideline"
reading would have *created* two new dark dots, because their only edge is a `governs` in the
governance family: show the node without the Constitution and it has nothing to draw. Declared
here so the narrower scope is on the record as a choice, not an oversight.
