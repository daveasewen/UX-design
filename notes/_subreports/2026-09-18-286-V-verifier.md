### D2 — `--quiet=<path>` can be pointed at a tracked path · **carry**
`_git_commit.sh`'s `--quiet` writes its transcript to `outputs/…` by default, which `.gitignore:67`
covers. But `--quiet=<path>` accepts **any** path with no guard, so `--quiet=knowledge/foo.log` would
write a transcript into a tracked directory *during the very run that is about to stage paths*. The
gitignore guarantee holds for the default only. Cheap fix for whoever next touches the script: refuse
a `QUIET_LOG` that `git check-ignore -q` does not cover. **Not blocking** — nobody has to pass the
flag, and I used it only into my own lane dir.

### D3 — `_git_commit.sh`'s quiet keep-filter is anchored, so indented verdicts are dropped · **carry**
`QUIET_KEEP_RE='^(✗|⛔|⚠|✅|✓|— )|REFUS|FAIL|not clean|✗'` anchors the symbol alternatives at
column 0. Several gates indent their verdict lines (`  ✓ …`, `  ⛔ …`). Those are dropped from the
live terminal stream. ⚠ **This is not a silenced refusal** — any refusal exits non-zero and triggers
the full unfiltered replay, which I drove twice — and the unanchored `REFUS|FAIL` alternatives catch
the worded ones. It is a readability loss on a *green* run only. Lane T's "never filtered" phrasing
in the USAGE header is therefore true of refusals and a little strong about `⚠` lines generally.

### D4 — `W-285lm`'s `closes_when` and `body` still disagree · **carry, and ruling-shaped**

accepted the masters by eye at #285) while the row is deliberately `open` because registration is
