## The gate-runner, and the one thing it had to get right

`s219-D4(4)` asks for a skill that *actually runs the packed gates on a designer's work*. The
question that decides whether such a skill is any use is **how a gate finds the designer's file**,
and the answer is not what the gate probe records. R1 measured which gates RUN; nobody had yet
measured which gates can be POINTED AT SOMETHING.

**Measured, by reading every runnable gate's argument surface and then driving them:**

- **Exactly one gate takes a path.** `_validate_screen.py [--render] [path ...]` — everything else
  globs a fixed directory. A skill that told designers to "run the gates on your file" without
  saying that would produce nothing but vacuous greens.
- The rest are reached by **putting the file where the gate looks**, and there are three such
  places, each with a different contract. The skill teaches them as three named routes:

| route | where the file goes | what runs | the contract |
|---|---|---|---|
| **A — a composed screen** | anywhere; hand the path over | `_validate_screen.py <path>` (compose + icon-source + a11y in one pass) | none beyond canon |
| **B — a styling tranche** | `knowledge/_proforma/*.html`, carrying a `#icon-manifest` block (that marker is the discovery signature) | `_validate_no_hardcode.py`, `_validate_css_governed.py`, `_validate_radius.py` | the marker only |
| **C — a component candidate** | `knowledge/snippets/<Name>.reference.html` | the whole snippet set | ⚠ Apollo's FULL authoring contract |

Route C is the honest catch, and the skill says so in bold. A designer's snippet dropped in there
reds immediately — measured: `❌ Filter-chip.reference.html: no #token-manifest block found`, and
after adding one, `missing [data-theme="light"] or [data-theme="dark"] block` ×5. **That red is a
contract they haven't signed, not a defect in their design.** A gate-runner skill that sent every
designer down route C would have taught them that the gates are noise. The skill routes screen
work to A and reserves C for people actually contributing a component.

### The three-verdict paragraph is mechanical, not rhetorical

The brief asked for pass / FAIL / COULD-NOT-ASK taught honestly in one short paragraph. It is
better than that: `knowledge/_could_not_ask.py` ships in the pack and the convention is
**machine-readable** — exit `0` pass, `1` FAIL, `77` COULD-NOT-ASK, `2` bad arguments, plus a
first line beginning `COULD-NOT-ASK:` carrying the reason in the gate's own words. Driven on the
stage: `_validate_state_contrast.py` and `_validate_hit_area.py --all` both exited **77** with
their own refusal lines. So the skill teaches the numbers, not a vibe.

It also carries the fourth reading R1 found and I re-drove: **`0` over an empty population is not
evidence.** `passed (0 tranche file(s))` and `passed (1 tranche file(s))` are the same exit code
and completely different facts. And one small trap, measured this lane: piping a gate into `tail`
gives you `tail`'s exit code, not the gate's — the skill says to run it plainly or use
`${PIPESTATUS[0]}`.
