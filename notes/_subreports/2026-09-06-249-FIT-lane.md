## Findings

1. **The page budget had ZERO headroom before this lane.** `_BEHAVIOUR-GATE.md` (HEAD) reads `page budget: 34816 bytes (34.0 KB …, 100%)` — 14,174 + 15,131 + 5,511 = 34,816 = `PAGE_BYTES` exactly. Any byte added to any dataviz source fails the page gate. The cap was re-dialled 32→34 KB by Dave at #96 for the last `fitOne` extension after it was "shaved twice" (`_validate_behaviour.py` L43–47) — the fork is the same one.
2. **The addition's size.** `dv-behaviour.js` 14,174 → 19,768 (+5,594); the VFIT block is 4,588 bytes, **3,697 code-only**. Comment bytes in the three sources: dv-behaviour 6,649 (5,332 at HEAD), dv-legend 7,317, dv-donut-sweep 1,607 — a shave that keeps VFIT's code needs ≥3.7 KB of existing comments cut from the sources, and the per-source cap needs ≥3.4 KB from dv-behaviour.js alone. That is provenance text, not this lane's to cut.
3. **Physics 19/19 on all 8 svgs.** In the 438px tile at 1440: Chart-line svg0 `1294×340` (viewBox `1294 340`), svg1 `1294×296`; Chart-bar svg0–2 `1318×340`, svg3–4 `1318×296`; template `854×350` — every box == viewBox in both axes, slack 0 at both widths, tick/label font-size one value (12px) across widths, strokes equal, gridline counts unchanged, every mark on its line, every bar keeps its bake fractions (±0.004), glyph sizes unchanged, ticks 3px under their gridline, below-baseline text keeps its offset, live resize returns, 0 page errors. Why 340 vs 296 within one member: the figures' heads/legends differ in height; the engine measures, it does not assume.
4. **Both mutations bite, on DIFFERENT checks.** `no-fity` (y not re-derived, viewBox 1:1): fails 11 (lowest gridline ≠ baseline), 17 (labels no longer baseline+16) and, on bar charts, 14 (bars no longer keep their fraction) — the geometry check catches the missing clause. `scale` (viewBox at data-h, CSS height stretched): fails 01/03/04 (box ≠ viewBox) — the 1:1-pin check catches it. Noted: the computed font-size checks (06/07) do NOT catch `scale` — `getComputedStyle` reports the CSS px, not the rendered glyph — so the pin check is the load-bearing scale detector, as in the DP18 script.
5. **The horizontal bar chart (Chart-bar svg1) rides the same engine.** Axis line 14→230 (vertical), category labels at row centres, ticks at 246: bars re-scale as fractions (rows spread over the taller plot), the axis line spans PT→baseline, ticks keep +16 under the baseline via the engine's below-baseline rule (no `data-dy` needed). 19/19 without a special case.
