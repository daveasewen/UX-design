## Findings

1. **The dashboard's whole `cn-*` vocabulary resolves.** Driven, not assumed: extracted every
   distinct `cn-*` token from `dashboards/international-banking-dashboard.canon.html` and looked
   each one up through the overlay's own exported `slugFromClass` against the generated map —
   **8 classes, 8 map hits, 0 fallbacks** (`cn-chart-line`, `cn-filter-toolbar-bar`,
   `cn-list-items`, `cn-navigations`, `cn-page-header-lockup`, `cn-pagination`,
   `cn-segmented-control`, `cn-stat-card`).

2. **Across all of canon.css the map covers 147 of 165 tokens.** The 18 misses are almost all
   `@keyframes` names my extraction regex swept up, not classes — `cn-x`, `cn-cards-pulse`,
   `cn-tabs-fade`, `cn-skeleton-loader-shimmer`, `cn-confirmation-pop`, `cn-data-grid-dg-shimmer`
   and kin. Checked rather than assumed: `cn-button-s` looked like a genuine class miss until
   grepped — `canon.css:1352` is `@keyframes cn-button-s{…}`. **Every real class in canon.css is
   mapped.** Anything that ever is not still lands on the class-name-only path, which is the
   designed default, not a failure.

3. **The coordinate-based hot corner goes deaf over a cross-origin iframe.** Found by reading, not
   by a test failing. Pointer events landing inside an iframe never reach the host document, so on
   the `file://` readings page the corner watcher — which is deliberately coordinate maths so it
   intercepts nothing — hears nothing over the frame. Answered by arming a real hit zone
   (`.af-sensor`) **only** when a frame was named and turned out unreachable, and saying so in the
   panel. On a normal page the sensor is `display:none` and the shipping mechanism is untouched.
   Proven both ways: check `[1]` asserts `data-sensor="off"` on a normal page, check `[6]` asserts
   `"on"` behind a throwing `contentDocument`.

4. **The tooltip could be drawn outside its own pane.** Found by reading. When the layer is
   container-absolute and the hovered element sits above the container — which is exactly what the
   readings page's practice strip does — the unclamped `top` went negative. Now clamped into the
   layer on both axes.

5. **canon.css carries three leaked bare `body{…}` rules** (canon.css:14103, :16175 — one sets
   `padding: 2.25rem`), absorbed from snippets with a mangled `:where(.cn-…)` prefix that also ate
   the surrounding comments. This is why the readings page does **not** link canon.css. Not mine to
   fix; flagged for whoever owns the absorb prefixer.

6. **The verifier is mutation-sensitive, not decoratively green.** Three mutations, each
   restored byte-identical (`cmp`) afterwards:
   - remove the `-dv` strip → `FAILED 1 of 59` (the chart-family lookup)
   - mount to `body` instead of the container → `FAILED 1 of 59`
   - rename the legacy *value* to `common` → `FAILED 2 of 59`
   The third mutation initially **crashed** the run instead of failing it (indexing an empty
   match); the assertion was hardened to fail loud and named first, then re-run.

7. **`git status` at hand-off:** five untracked files, zero modifications. No dashboard, canon,
   snippet, token, skill, runbook, gate or state file was touched.

   `--border`, `--pri`, `--focus`, `--shadow` and kin are declared in the page's own `:root`, with

   pair) — **nothing invented**. It is done so the overlay's token probe engages and Dave can watch
   the FAB re-theme itself on `file://`, where the real dashboards are unreachable. If wearing

6. **What the inspector shows, and `z-index: 2147483000`.** Four fields per component (name,
   category, purpose-first-sentence, token verdict) is my selection, not a ruled schema; the
