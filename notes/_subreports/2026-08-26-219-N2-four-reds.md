## ② TOKEN FORK-BAN, 3 forks — REAL GATE DEFECT, A FALSE POSITIVE · FIXED

**Reproduction, quoted:**
```
FORK  --dvf1  theme=mono mode=any
   knowledge/canon/canon.css:7199  from      --dvf1: 0   ->  0
   knowledge/canon/canon.css:7199  to        --dvf1: 1   ->  1
GATE RED: 3 fork(s) not in the ledger
```

**The three, found and read.** `canon.css:7202-7204`:
```css
@keyframes cn-chart-bar-dvStackF1{from{--dvf1:0;} to{--dvf1:1;}}
@keyframes cn-chart-bar-dvStackF2{from{--dvf2:0;} to{--dvf2:1;}}
@keyframes cn-chart-bar-dvStackF3{from{--dvf3:0;} to{--dvf3:1;}}
```
These are the **DV-D16 stacked-column growth physics** — registered custom properties interpolated
by a CSS animation.

**Diagnosis — and it is the opposite of a fork.** The parser maintains a brace-depth stack and
tracks at-rules, but never *used* the at-rule context to exclude anything. Inside a `@keyframes`
block the stack reads `[("at","@keyframes …"), ("sel","from")]` — so `from` and `to` are handed to
`context_of()` **as if they were selectors**, and score as two different SCOPES under the same
`(theme=mono, mode=any)`. Two different values in one context is the gate's definition of a FORK.

⇒ **A keyframe's whole purpose is that `from` and `to` disagree.** A keyframe whose frames agreed
would be an animation that does nothing. The gate was measuring the animation and reporting it as
a defect. **Measured scope of the false positive:** exactly three, repo-wide — a brace-matched
sweep of `knowledge/canon/*.css` finds custom-property declarations inside **only** those three
`@keyframes` blocks and no others, so no existing ledger entry is a laundered instance of this
class. **The three forks are new because the DV-D16 physics are new, not because a token forked.**

**Fix at cause** (`knowledge/_validate_token_forks.py`): declarations whose at-rule stack contains
a `@keyframes` (vendor-prefixed forms included; the head is `match`ed, not searched, so a selector
merely *mentioning* the word cannot pull a real rule out of the measurement) are **not returned by
the parser at all**.

⛔ **NOT LEDGERED — deliberately.** The ledger's own header says an entry *"is NOT a sanction and
NOT a fix"* and that *"No script may add to this file automatically"*; filing a **false positive**
there would have been baseline plaster over a gate defect, which is the exact thing `s219-D5(Q5)`
forbids. It would also have handed Dave three fake decisions to make.

**Before → after, and the delta is exactly the three:**
```
parsed: 12009 declarations, 15299 contexts → 12003 declarations, 15293 contexts   (6 = 3 props × from/to)
names : 977 → 974          FORK: 48 → 45          ledger: 50 declared (untouched)
GATE RED: 3 fork(s) not in the ledger  →  GATE GREEN: no undeclared fork
```
No other verdict moved: `UNIFORM 530`, `BENIGN_THEME_AXIS 32`, `BENIGN_MODE_AXIS 53`,
`BENIGN_THEME_AND_MODE_AXIS 314` — all identical either side.

**Selftest widened from 2 bites to 4, BOTH directions:**

| arm | verdict |
|---|---|
| clean sheet → `BENIGN_THEME_AXIS` (four-theme requirement) | OK *(pre-existing)* |
| forked sheet → `FORK` | OK *(pre-existing)* |
| **#219 keyframes:** `@keyframes`+`@-webkit-keyframes` growing `--dvf1` → **no declaration, no verdict** | OK |
| **#219 media CONTROL:** a real same-`(theme,mode)` fork under `@media` → **still `FORK`** | OK |

**Diagnosis.** `canon/type.css:99-102` appends `.search input` to the **`.t-cm-label` composite as


The registry's acknowledged radius is four files. Navigations' `s218-D4` PROPOSED search bar
markup carries `<div class="search" role="search">` wrapping an `<input>`, so canon's global
selector reached a **fifth** file. **A class-name collision — the #202 vocabulary class.**

**Which remedy is at cause — decided by evidence, not by preference.** The brief steered towards
namespacing; the sibling snippets were checked before acting, and they settle it in the opposite
way from the first impression:

| file | uses `.search`? | carries a composite class on its input? |
|---|---|---|
| `Search-field.reference.html` (in radius) | yes, bare | **no** — `/* type: t-cm-label (bound in canon/type.css — T-D9/T-D12) */` |
| `Filter-toolbar-bar.reference.html` (in radius) | yes, bare | **no** — *".search input's font is OMITTED here exactly as it is in Search-field"* |
| `Navigations.reference.html` (the escape) | yes, bare | **YES — `class="t-cm-label"`, explicit** |

⇒ **The two files in the radius CONSUME the binding; Navigations does not.** It declares its own
composite, re-declares all its own geometry under `.nav-searchbar` against its own tokens
(`--field-active`, not `--border-active`), and never links Search-field. `--update`-ing it into the
registry would record a global binding site **that the file does not use** — precisely the
unacknowledged reach the registry exists to stop. **Namespacing is at cause.**

matching the snippet's own `.nav-searchbar`/`nv-*` idiom — three CSS rules and one markup
attribute, with the reason inscribed above the rules so the name is not "tidied" back later.

assertion, no meta, no other snippet.
