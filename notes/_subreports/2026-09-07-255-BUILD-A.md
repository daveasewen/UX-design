## Items 1+2 — `gap: 6px` → `gap: 4px` · GREEN

**WHAT.** One edit, at the SOURCE: `knowledge/snippets/Template-dashboard-bento.reference.html`
rule 10e, `.tpl-na-head .summary__k{ display:flex; flex-direction:column; gap:4px; }`. The
`canon.css` occurrence was never touched by hand — it is the projected copy and it changed only
when `gen_canon_components.py` re-ran (ownership note, `gen_canon_bento.py:704–710`).

**WHY 4px and not 8px** — the design merits of THIS stack, not a default. The key cell holds the
key and its `.t-cm-legal` caption: one thing said twice, not two peers. `.tpl-na-head` already
spends **8px** below the whole head row (`margin-bottom:8px`, unchanged), so an 8px stack inside
the key would set the caption at the same distance as the separation of the head from the body —
it would read as a peer row rather than as the key's second line. 4px is the tightest step the
grid offers and is the one that keeps the pair reading as a pair. The alternative is named in the
RULING-SHAPED section below.

## Item 3 — the `--bento-cols-now` fork · GREEN

**WHAT.** Two declarations left the template. Rule 10a became
`.tpl-page .c-bento.tpl-group-lead > .c-bento__grid{ grid-template-columns:repeat(4,minmax(0,1fr)); }`
and rule 6b(ii) became
`.tpl-page .c-bento.tpl-group-context > .c-bento__grid{ grid-template-columns:repeat(var(--bento-columns),minmax(0,1fr)); }`.
Both write the property canon's own base rule writes (`canon.css:1088`,
`grid-template-columns:repeat(var(--bento-cols-now),minmax(0,1fr))`) and both out-specify it
(0,4,0) vs (0,1,0), exactly as the literal did before. **Rendered geometry is unchanged**: the only
reader of `--bento-cols-now` anywhere in the tree is that one `grid-template-columns` declaration
(receipt below), and the `[data-c]` span clamps the bands also carry are separate rules that were
not touched.

**WHY this shape and not the briefed one.** Read from the gate's own measure, not from a hint.
`_validate_token_forks.py` keys a declaration by `(theme, mode, scope)` where `scope` is the LAST
`.cn-*` class in the selector (`context_of`, L210–224) and `build_index` keeps **last-wins** per
key (L230–248). Every rule the projector prefixes with `:where(.cn-template-dashboard-bento)`
therefore collapses into ONE scope that can hold ONE value per property name — so any second value
of `--bento-cols-now` in template scope is a fork by construction, whatever selector carries it.
The briefed alternative (express the count on the `--bento-columns` instance dial) was built and
measured against the gate's own parser: it does not repair the fork, it **moves** it.

Rule 6b(ii) is inside the five items, not outside them: it is a second declaration of the same

## RULING-SHAPED — two choices this lane made

**R1 · The fork repair shape: the count moves to `grid-template-columns`, not to `--bento-columns`.**
CHOSEN because the gate's scope model gives the whole template projection ONE slot per property
name, so the dial route relocates the fork rather than removing it — measured both ways above
(VAR-A: two forks; VAR-C: none). It also says something true that the literal did not:
`--bento-cols-now` is canon's band machinery, and rule 10a **opts out** of the bands rather than
acting as one. ALTERNATIVE, rejected: ledger the fork under `_TOKEN-FORK-LEDGER.json` — that is
baseline plaster over a live disagreement and is the opposite of the `s253-D2` form. SECOND
ALTERNATIVE, rejected as dishonest: reorder rule 10a above the projected band block so last-wins
picks `1` — identical rendering (10a wins on specificity either way), but it makes the gate green
by arranging the index rather than by fixing the artefact. ⚠ What a future lane should know: under
this gate NO per-instance column count can be expressed on `--bento-cols-now` or `--bento-columns`
inside a `.cn-*` projection. If Dave wants the dial route, the gate's scope key — not the artefact
— is what has to change, and that is his ruling, not a lane's.

**R2 · 4px, not 8px, for the Needs-attention key stack.** CHOSEN on the relation: key + legal
caption is one unit, and 8px is already the head's OWN separation from the body below it
(`margin-bottom:8px`), so 8px inside the key would flatten the hierarchy — caption as peer row.
ALTERNATIVE, rejected: 8px, which would have matched the card's inter-row rhythm and is the safer
"round" step; it loses the distinction between *this key's second line* and *the next row*.
Neither value was ruled by Dave; both are on the 4px grid, so this is a design call, not a gate
call, and it is strikeable.
