## F1 — the menu opens but PAINTS NOTHING (`opacity: 0`). This is the ARM's defect, not the pack's

Assertion 7 is a **soft green** and is named as one. After the click, `#ddEntityM` computes
`display:block`, `visibility:visible`, `position:absolute`, `z-index:20`, rect 918, 325, 95 × 374,
six children — and **`opacity: 0`**. Playwright's `is_visible()` ignores opacity, so the assertion
passed on a menu the eye cannot see; the screenshot shows the toolbar with no menu under it.

Cause, read off the shipped CSS: `:where(.cn-filter-toolbar-bar) .menu` sets `opacity:0` and
`:where(.cn-filter-toolbar-bar) .menu[data-open="true"]` sets `opacity:1`. The pack's own
`Dropdown.reference.html:239` sets **both** attributes (`menu.setAttribute('data-open', …)` and
`trig.setAttribute('aria-expanded', …)`). C6's arm was authored blind against a `canon.css` that
carried **no `.menu` rule at all**, so its script sets `aria-expanded` only. The fix is in the arm's
JS, and the pack already documents the convention it missed.

⚠ **This is the price of the fix being real**: a rule that did not exist before now governs, and a
page that never had to satisfy it does not. Worth one line in the demo prep — any page built
against the v1.0.9 zip may carry the same omission.

## F2 — ⛔ THE SIDEBAR LABELS CLIP THEIR DESCENDERS IN THE RELEASED ZIP. Cascade-dead override

The nav renders, and it renders **"Pavments", "Liauiditv", "Settinas", "Group treasurv"**. Visible
at 3× in `…-nav-zoom.png`; measured, not inferred.

    .nv-label — font-size 16px, line-height 16px, overflow:hidden
      box height  11.6px          (a 16px font trimmed to the alphabetic baseline)
      text-box-edge computes      cap alphabetic       ← NOT the authored value

`canon.css:15442` authors `:where(.cn-sidebar-nav) .nv-label{… text-box-trim:trim-both;
text-box-edge:text text;}` — specificity **(0,1,0)**. The base default at `canon.css:960` is
`:where(.canon) :is(button,a,span,…,input[type=text],…):not(:has(svg))`, whose `:is()` takes its
weight from its heaviest branch and lands at **(0,1,2)**. The default outranks the override, the
override is **cascade-dead**, every nav label computes `cap alphabetic`, and `overflow:hidden`
cuts the descender off.

**Mutation test — the clause, driven both ways** (`…-nav-mutation-control.png`):

| | box height | computed `text-box-edge` |
|---|---|---|
| as shipped | 11.6px | `cap alphabetic` |
| `text-box-trim:none` forced | 16px | — |
| authored value re-asserted at (0,2,0) | **21px** | **`text`** |

This is the SAME failure class the two files already carry ⛔ comments about — `canon.css:955-959`
("48 render-measured descender repairs were cascade-dead … ⛔ Do not unwrap it") and
`Sidebar-nav.reference.html:46` ("`{text-box-edge:text text}` was cascade-dead and every label
computed `cap alphabetic`: the box ended at the baseline and overflow:hidden cut the descender
off"). **The snippet fixed it; canon.css did not.** The snippet's local copy of the default list is
`:where(button,a,span,…)` — fully wrapped, (0,0,0) — so `.nv-label` wins there. canon.css's copy is
`:where(.canon) :is(…)` — the `:where()` is on the SCOPE, not on the list, so the list keeps its
weight. A consumer who obeys rule 2 and links `canon.css` gets clipped labels; one who pastes the
snippet's `<style>` does not.

⬛ **DAVE'S.** This is the label-crop pattern recurring, in the release, on the component the cut
was made for. Whether v1.0.11 ships with it or the cut moves is his word (s219-D4(2)).
