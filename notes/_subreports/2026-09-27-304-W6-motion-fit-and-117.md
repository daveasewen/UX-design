## 2 · JOB 2 — the reduced-motion fit bug (W5a Q3)

**Reproduced, deterministically enough to count** (F5's stage, engine = HEAD, 1440, fresh page per load, W5a's `probe/fitrate.py`): overview c2r1 **18/20**, c2r3 **16/20** unfitted under reduced motion; the other nine chart pages **38/54**.

**Cause, caught in the act** (`tools/mech2.py`: transition events on `svg.dv-fit` + a MutationObserver on `viewBox`): in the failing loads the fit writes `viewBox 0 0 580 …` at ~92–128 ms, the `width` transition runs at ~113–141 ms and ends at ~133–157 ms, and no fit runs after the end. In the one passing load a fit happened to land after the end frame. The transition exists only because of canon.css:1033–1034:

```
@media (prefers-reduced-motion: reduce){ .canon *,.canon *::before,.canon *::after{ transition-duration:.01ms !important; animation-duration:.01ms !important; …
```

With `transition-property` at its default `all`, this turns every computed-value change inside `.canon` into a one-frame transition, including the `.dv-fit-on` release (`figure.dv-fit-on .dv-svg{width:100%}` and `.dv-chart-area{width:100%}`). The fit (`fitOne`: `W = Math.round(svg.getBoundingClientRect().width)`) reads the start value. W4a's ring race (a `CSSTransition` on `width` in flight at `dvRender`) is the same mechanism; W4a removed it for rings by making them not read layout.

**Fix** (`knowledge/canon/dv-behaviour.js`, the only hand edit; `notes/_lanes/304/W6/w6.patch.txt`):

```js
  var dvRAF;   /* the ONE resize listener, rAF-debounced (ADR-0015) */
  function refit() { cancelAnimationFrame(dvRAF); dvRAF = requestAnimationFrame(function () { fitCharts(); placeSegs(); }); }
  window.addEventListener('resize', refit);
  /* #304 W6 — RE-FIT WHEN A CHART'S BOX FINISHES MOVING. … */
  document.addEventListener('transitionend', function (e) { if (e.target.matches('svg.dv-fit,:has(svg.dv-fit)')) { refit(); } });
```

- Why here and not in the CSS: the reset is right for reduced motion and is not the engine's, and any width transition (a sidebar collapsing with motion on, a tile's flex change) strands the fit the same way. `transitionend` on the canvas or on anything that holds one means the box is final, so the fit runs once more on the same rAF-debounced path. Marks inside the svg never match (they hold no canvas), so a fit's own attribute writes cannot loop. Measured: one extra fit pass under reduced motion, none with motion, all quiet by ~160 ms (`measure/fitrate.txt`, settle).
- Still ONE resize listener (the gate counts `addEventListener('resize'`); events delegated at document level; no polling. `_validate_behaviour` OK, `--selftest` OK.
- `:has()` is declared: canon.css already depends on it (F5's chart-only trim restore uses `:not(:has(svg))`).
- **Budget, the saving first:** `fitCharts` and `placeSegs` walk their `querySelectorAll` NodeList with `forEach(fitOne)` / `forEach(moveSeg)`. Same static list, same order, one call per element; the extra (index, list) arguments are ignored by both. `thinLabels` already relied on `NodeList.forEach`, so no platform assumption is new. dv-behaviour 13,581 → **13,590** code-only bytes; **Chart-combo 34,768 → 34,777 / 34,816** (39 left).
