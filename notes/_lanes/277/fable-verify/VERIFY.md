## Method

### #1 · `chart-line` → `dv-line-001`
**As proposed:** *The zero y-axis is OPTIONAL for a line and MANDATORY for a bar, and this meta is the line side of that deliberate asymmetry - it carries no data-domain-min antiPattern, where chart-bar carries one.*
**Why RED:** the absence is real, but the inference "this meta IS the line side of the asymmetry" is contradicted by the meta's own behaviour chain. `behaviour.script` = `knowledge/canon/dv-render.js` (L249), and that engine floors every registered type at zero: `if (draw.zeroBaseline !== false && lo > 0) { lo = 0; }` with "no type in the tree opts out today" (dv-render.js L290–297). `dv-render-line.js` L44–48 says so in the rule's own name: *"CORE REQUEST (reported, NOT worked around): dv-render.js clamps … for every type. That is dv-bar-009's zero baseline, and dv-line-001's asymmetry says it MUST NOT fire on lines … Left alone."* A line drawn from zero every time is not "the line side"; silence in antiPatterns is not obedience.
**Corrected:** *The zero y-axis is OPTIONAL for a line and MANDATORY for a bar, and this meta records only the mandatory side's absence - no data-domain-min antiPattern where chart-bar carries one. The engine it names in `behaviour.script` (dv-render.js) still floors every registered type at zero by default (a `zeroBaseline` opt-out exists; no type takes it today), and dv-render-line.js reports that clamp as a CORE REQUEST against this very rule - so the edge records a rule the line is built to honour and does not yet enact.*
Anchors: `"script": "knowledge/canon/dv-render.js"` — L249 · ABSENT `data-domain-min` — 0 hits.
