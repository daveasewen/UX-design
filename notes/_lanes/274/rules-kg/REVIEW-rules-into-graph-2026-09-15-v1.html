Decisions

Six decisions. The recommendation is first in each.

Nothing here is ruled. Every option stays open; the marked option is the lane's recommendation and carries no weight beyond that.

RK-1

THE NODE KIND

A tagged guideline rule becomes one node: rule:<id>, e.g. rule:aca-001, carrying id · file · destiny · destinyFull · the rule text. 470 nodes. The prefix is MEASURED as free: the live graph carries pattern / context / component / snippet / role / intent / shape / ruling / artefact / evidence / session / sc / guideline / principle / standard / policy / axe — and principle: and guideline: are WCAG's (s269-D2).

Why (a): the ids are already global (aca-001, nam-002) and nothing else in the graph wants the word. (b) buys a spare word we have no use for; (c) leaves the largest measured family at zero, which is what s269-D1 put second in the order.

RK-2

WHAT LANDS IN WAVE 1

Four edge types are measured and strong. Together: 634 edges, 521 nodes. Nothing is invented — an unresolvable target is null plus the evidence.

Why (a): three of the four are read from a FIELD or a generated index, not guessed — definedIn from file, enforcedBy from a gate that NAMES the rule id, flaggedBy from the signals file. Only cites parses prose, and it declares its misses.

RK-3

DESTINY: ATTRIBUTE OR EDGE

Every rule carries one of four enforcement destinies — ADVISORY 321, BLOCKING 59, REVIEW 34, TASTE 56. It can sit on the node or hang off it.

Why (a): four hubs with 470 spokes is a hairball that says nothing the attribute does not. The generator can produce (b) on a flag if you want to see it: --destiny-edges.

RK-4

THE 19 SC CITATIONS WE CANNOT RESOLVE

51 success-criterion citations parse out of the rule text. 32 resolve against the 38 sc: nodes we hold; 19 name criteria the compliance corpus does not carry (1.2.3, 1.4.5, 2.5.1, 3.3.7…).

Why (a): a null with its prose is a to-do the gate can count; a dropped citation is a fact we quietly lost. (c) makes this lane wait on an unrelated corpus.

RK-5

WHERE THE NODES LIVE, AND WHO READS THEM

Rules are not components, so these nodes cannot live in components/*.meta.json. The generator writes knowledge/_rule_nodes.json — the shape of _ruling_edges.json (s267-D3). Nothing reads that file yet.

Why (a): a landed file with no consumer is the named failure — an instrument without a consumer. (c) is defensible and simpler to keep fresh, but it hides the proposal inside a builder where no gate can diff it.

RK-6

RULE → COMPONENT: THE WEAK ONE

appliesTo ALREADY EXISTS in the graph (826 edges, sc: → component). Reusing it for rules needs a rule that NAMES a component. Matching component names in the rule text gives 27 pairs across 24 rules and 14 components — and the sample carries visible false positives (va25-013 matched “Avatar” in an aspect-ratio rule).

Why (a): an edge type that already means something precise should not be widened by a regex with known false positives. (d) is the durable answer and is a separate lane.
