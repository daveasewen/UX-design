Three long stories, no shared sentence

The handoff (25,000 characters), the wrap report (11,000) and the dossier (6,600) each tell the session again in new words. None of their sentences over 60 characters appears in either of the others. The same facts told three ways is where drift comes from.

The memory note, written three times

The memory body appears whole in its payload file, inside the full memory file, and again inside the memory hook. That's about 20,000 characters every wrap.

The carried list, copied whole

Every wrap copies the whole carried-items list into a new section with every age raised by one. That was 370,000 to 800,000 characters a wrap. The file is now 37 MB with 82 sections.

The same scripts, rewritten

Each wrap writes 8 to 11 small scripts again, “modelled on” the last wrap's. They cover the move file, the carried items, the state rows, the shared names, the CI read-back and the commit shells. #305's were 394 lines.

The design

One story, three seats

Today one seat does everything in a line. It writes nine views of the session by hand, then runs the mechanics, then commits, then waits on CI twice. The design splits this into two source files, each with one writer. Every view becomes a generated page, and three seats run side by side until the commit.

a · The one source, in two files

STORY.md is written only by the story seat. It is plain markdown with tagged sections: the headline, your words verbatim with their times, what was found, what landed, decisions, problems and what's owed, strikes with receipts, new carried items, questions for you, what's unproven, and the why-and-how paragraph. Figures appear as placeholders, such as {rulings.total}.

FACTS.json is written only by the mechanics seat, and every value in it is measured. It holds the dates and date split, the commit ids, the rulings count and newest id, the CI runs and verdicts, the window fills, the spend on helpers, the carried count and the banner size.

Why markdown for the story: it is prose, and you and the next seat read it by eye. Why JSON for the figures: the generators and the gate read exact numbers from it, so nothing is ever retyped. Why two files: each has one writer, so the two seats can't collide.

b · What becomes generated

  • The handoff, the dossier, the wrap report, the banner, the delta, the summary for you, the memory note, the commit message and the state-row titles all come from one new tool, _wrap_views.py.
  • The banner generator reports each bullet's size before anything is drafted. The six-drafts-to-fit loop is gone.
  • The scripts each wrap rewrites become permanent tools: _wrap_facts.py measures, _wrap_ops.py builds the one move file, _wrap_carries.py handles carried items, _wrap_rows.py the state rows, and _ci_readback.py reads CI back.
  • These are kept as they are: _gm_move.py, _roll_state.py, _gen_chain.py, _gen_size_stamp.py, _gen_titles.py, _state.py, _render_rulings.py, _git_commit.sh. The index is rebuilt once, last.

c · The three seats and their hand-offs

  • Story seat: reads the brief and the transcript, writes STORY.md, then drops a done marker.
  • Mechanics seat: runs the open gate, measures FACTS.json, runs the archive moves, the carried items and the state rows, renders the rulings page, then drops a done marker. It needs no judgement.
  • Commit seat: waits for both markers. It generates the views, rebuilds the index once, runs the gate inside the commit, pushes, and gives you the summary. Then it reads CI back and writes the generated follow-up. Scratch clean-up runs last.
  • What must stay in order: the views after both sources, the index after every edit, the gate before the commit, and clean-up last.

d · What the gate must change

  • New, and blocking: a “views are fresh” check. It regenerates every view in memory and compares it with what's on disk, the same way the index and rulings-page checks already work. A hand edit to a generated view goes red.
  • The filed-report rule stays whole. The generated wrap report carries the three machine-read lines, gets a state row and is cited by path. The generator is its one writer. The rule asks that figures be copied off one file and never retyped, and generation is the strictest copy.
  • STORY.md and FACTS.json get state rows like any brief.
  • The carried-items count reads the generated list once the carried items are written as changes.

Build order

Six phases, each proven on a real wrap

Sizes are estimates. Each phase is proven the same way: one real wrap runs on it, and the numbers on this page are measured again, before and after.

  1. The mechanics become permanent tools

    The 8 to 11 scripts each wrap writes again become one tool with self-tests: the figures, one move file, the carried items, the state rows, the CI read-back, and the index rebuilt once. About one build lane.

    Proof Scripts the seat writes go from 11 to 0, move files from 9 to 1 and rebuilds from 5 to 1. Minutes to the first push are measured.

  2. Your summary at the push; no second CI wait

    The summary goes to you when the wrap is pushed. The follow-up commit's CI is read by the next session's opener. This is a runbook change and one opener line, with no new code.

    Proof Minutes from launch to your summary (about 59 today), and to done.

  3. One story, every view generated

    This adds the story and figures files, the view generator and the freshness check in the gate. The handoff layout, the report skeleton and the banner shape are copied from today's files, not redrawn. One to two lanes.

    Proof This page's duplicate map is run again, and every fact should have one hand-written home. Hand-written characters are counted before and after, and the gate must be green.

  4. Three seats

    The brief templates for the three seats, and the runbook's step order rewritten to match. Small once phases 1 and 3 exist.

    Proof A timeline drawn from file times, like the one above.

  5. Carried items written as changes

    Each wrap writes only what's new, what's struck and the aging. The full list is generated when it's read, and the gate's count reads that list. About one lane.

    Proof The carried count reproduces (401 today), and the file grows by thousands of characters a wrap, not hundreds of thousands.

  6. Wrap as you go

    At each seam check during the session, your words and the running tally go into the story draft. Small once phase 3 exists.
