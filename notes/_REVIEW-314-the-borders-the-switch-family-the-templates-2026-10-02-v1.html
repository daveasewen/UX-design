07–18 · The templates · twelve calls · Fable

Eleven of the twelve page templates, rebuilt from the library's own parts. The bento dashboard waits for its own lane.

"We need to regenerate the templates too BTW, everything in the library should be a valid 'element' of the design system"Your comment on call 16, Thursday 1 October, 23:18

"A valid element" was your phrase, not a defined term, so the lane settled what it means before building (call 7). The old templates were mostly copies: about four in five of their style rules repeated other parts, and canon.css carried every copy a second time. Rebuilt, each page links the shared stylesheet and only places parts. It never restyles them. canon.css shrinks by about 307 KB. Every before-and-after pair below is a cloud render in a fallback face. The seat renders come when it lands.

What changedEach page is now its parts, by their current names (Metric, not the KPI tile), placed by a few layout rules of its own.
What it shows upA page can't patch a part any more, so a part that is wrong now shows on the page. The lane listed fourteen of these as library findings (call 28).
What is not doneThe bento dashboard: three gates and two generators read it by its old class names. It needs its own lane (call 27).

Call 7

The lane read your phrase as: a template is a page, and a page is made only of parts. It places them, never sizes or restyles them, and carries a meta like any other component. The other reading was to keep each template a self-contained component that copies the rules it needs. Is the first reading yours?

Recommended: Yes: a template is a page made only of parts. Your own words say it three times: "the page never sizes a part", "rebuild the shared stylesheet rather than carrying the rules on the page", and the twelve are "whole composed pages". Under the other reading a template could only ever be a copy.

19–27 · Choices the rebuild made without your word · nine calls

Where the old page and the current rules disagreed, the lane picked one and asked. Each is a choice it made without your word.

Call 19

The error page now uses the empty-state part (a quiet dashed box, smaller heading, faint glyph) with two buttons under it. The old page was half that and half the confirmation part (no box, a bigger title, a success roundel). Which is the error page's column?

Recommended: The empty-state part. The confirmation part only knows success, and its roundel would be wrong on an error.

Call 20

The old templates put page sections on a borrowed card. Since your container rulings, a card is one of a set of like records, and sections are landmarks. The rebuilt pages draw sections on a rule above each. The settings rule still says "sections are grouped on card surfaces". Which wins?

Recommended: Sections sit on rules; the settings wording is amended. It follows your later word, and a page of one-off cards is what the lone-card rule warns about.

Call 21

The bento dashboard carries the top nav and the footer. The plain dashboard and the report now end with the footer but have no nav. The other nine show the page body only. Should every page template carry the app frame?

Recommended: Yes, every page template carries the frame. You called them whole composed pages, and the standing rule is that every app page ends with the app footer.

Call 22

The list index still draws both forms: the data grid for bulk approval, and the plain list as the default. For a payments index, is one of them the template, or do both stay as the drawn choice?

Recommended: Both stay, each chosen by its job. Your list rule already decides between them: the grid when rows are selected in bulk, the list otherwise.

Call 23

The largest logo master you ruled is 40px. The old sign-in page showed the wordmark at 85px. Is a hero-size master wanted, or is 40 right for sign-in?

Recommended: 40 stands. Only ruled masters are drawn, and a new size is a new drawing for you to rule by eye.

Call 24

No part draws a password reveal inside the field, and the icon library has no eye. The sign-in page shows a quiet "Show password" button under the box instead. Should the library gain a reveal: an eye in the text field's end slot?

Recommended: Yes, the library gains a reveal in the field. It is the expected pattern on a banking sign-in, and a reveal under the box costs a line of space on every password field.

Call 25

The old list index drew each payment with a download at the end of the row. The plain list's transaction row has no slot for a row action. Does the row gain one, or does the advice download live on the detail page, where the document row already carries it?

Recommended: The download lives on the detail page. A list is for finding the payment; the document belongs with the payment.

Call 26

The old page drew a pending outcome with a clipboard glyph. The confirmation part has one kind, success. Should it gain a pending kind, or does the status chip carry pending, as it does now?

Recommended: No pending kind; the chip carries it. One more glyph for one state the chip already says in words.

Call 27

The bento dashboard was left as it is: three gates and two generators read it by its old class names (KPI tile), and the move to Metric has to happen in all of them in one go. Give it its own lane, rebuilt the same way?

Recommended: Yes, its own lane, rebuilt the same way. Doing half of it would leave a red build that nobody can review.

28 · What the rebuilt pages show up in the library · one call

A page can't patch a part any more, so where a part is wrong, the page now shows it. Fourteen of these were found.

  1. The empty-state part leaks a demo rule: any heading placed inside it greys.
  2. The form layout's pair row runs wider than its own column. You can see it in the part's own snippet too.
  3. The segmented control shows its pressed label white on white until its script has run, in every place it is used.
  4. The stepper's default width is its own collapse point, so on its own it never shows its dots.
  5. An engine-drawn chart cannot carry the static hover hook the chart rules asked for, so the hook moved to each chart that draws baked.
  6. No part draws a password reveal, and the icon library has no eye (call 24).
  7. Confirmation and empty state each carry their own button styles instead of using the button part, so a button placed inside them is restyled.
  8. Summary is fixed at 420px wide, a dropdown wraps a long value at its own width, and the document row truncates titles in a narrow rail.
  9. The line chart's "target line" and "last year" toggles are author controls, so the report dropped them rather than show dead controls.
  10. Metric caps its row at 1040px, so four figures stop 80px short in a full-width page. The pages place them on the layout grid instead.
  11. The anchor nav has no slot for a glyph and truncates long links.
  12. The text field has no reveal slot (as finding 6).
  13. The action bar knows only three button weights; a quiet fourth sits inside it as a nested button. It draws correctly.
  14. Confirmation has only a success kind; pending rides the status chip (call 26).

Call 28

Should one lane fix these at the part (not on any page), and bring you the ones that change a look as pictures?

Recommended: Yes, one lane fixes them at the part. Each fix lands once and every page that uses the part gets it.
