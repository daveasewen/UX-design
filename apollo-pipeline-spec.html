Overview

The double diamond, as a harness.

Two layers. A discipline-agnostic harness — orchestrator, state stores, gate model, error taxonomy — abstracted from the HDS editorial pipeline. And pluggable discipline pipelines that share it: CX research, CX design, UX research, UX design, UI design, UX copy, with BA and PO as cross-cutting inputs.

The first working pipeline is UX/UI build & review: a brief becomes a prototype built only from the component library, passes a scored craft gate, then parallel expert, accessibility and brand review, then a human taste gate, then developer handoff.

The invariant is the contracts, stores and gates — portable across Claude, GPT‑5.5 and Apollo. The execution engine is replaceable. We own orchestration.

Architecture

Two layers. One invariant.

Harness — reusable
Orchestrator, state stores, gate model, error taxonomy, HITL framework. Discipline-agnostic. Abstracted from HDS. This is what every discipline shares.
Pipelines — per discipline
Spokes, typed contracts and gates specific to CX/UX research, UX/UI design, UX copy. Plug into the harness. The taxonomy will flex without touching the harness.

The invariant — contracts, stores, gates — is portable across Claude, GPT‑5.5 and Apollo. The execution engine is replaceable. We own orchestration.

Spokes — the working pipeline

01
Generator
Renders an approved flow into a prototype using only the component library. Never invents components or variants.

Reads the brief and flow spec, queries canon for just the components each screen needs, composes from defined instances, binds tokens by intent, and covers every state. Missing patterns are raised as open_gaps — never improvised. Inventing variants is the documented primary failure of agentic design; this spoke makes it impossible by construction.

{ "component": "Button", "variant": "primary", "states": ["default","hover","disabled"], "tokens": { "background": "color.action.primary" }, "provenance": "figma:1024:88" }
Output: design_candidate → the craft gate.
02
Critic — craft gate
Scores design-system conformance. A trusted logic gate: the orchestrator routes on its pass field.

Checks every instance against canon: invented components or variants, hard-coded values instead of tokens, anti-pattern and adjacency violations, missing states, contract integrity. Emits a pass plus specific, actionable recommendations. A blocker violation fails the gate; failures route back to the Generator. This is the design analogue of HDS's Critic — craft is scored.

The Critic catches craft failures. The taste gate catches judgment failures. Distinct failure modes, distinct recovery.
03
Parallel review
Heuristic, accessibility and brand reviewers run simultaneously, each in a clean context, joined for the taste gate.

Heuristic — Nielsen's 10 usability heuristics, each issue severity-rated 0–4. Accessibility — WCAG 2.2 AA, each finding citing the success criterion and EN 301 549 clause; any non-waived AA failure blocks handoff. Brand — the GTB Swiss system and experience principles.

Mirrors HDS's parallel Editor∥Essayist dispatch — independent work, joined once before the next gate.

{ "sc": "1.4.3 Contrast (Minimum)", "en301549_clause": "9.1.4.3", "component": "Button.secondary", "severity": "serious" }
04
Handoff
Assembles the approved design into a developer-ready spec with Code Connect mapping and a working prototype.

Produces layout in tokens, component props and states, responsive behaviour, interaction notes and edge cases — plus the Figma-to-code mapping and the prototype (production React preferred; standards-compliant Figma Make as fallback). Rolls up gate results for audit. Gate B is the final human approval before ship.

Persistent State

Three stores that survive across runs

The model layer reads them. The orchestration layer writes them. The design lead audits periodically.

01
Canon (knowledge)
Authoritative facts: the component graph, compliance graph, tokens, and guidelines. Read-only to spokes; built by ingestion on the agency machine. Representation chosen per type — graph, RAG or live MCP.
02
Memory (learning)
Evolving preferences and refinements, proposed by reviews. Committed only via a gated policy — never silently. Periodic audit guards against drift. taste.md is the human-owned north star it must not contradict.
03
Checkpoints
Output of each completed step, written before advancing. Enables partial resumption. Invalidation: transient → retry only; malformed input → invalidate upstream; empty → re-run from the first spoke.

Error Handling

Four failure types.
One routing decision each.

01 — Transient
Environmental: timeout, outage, rate limit. Input valid, spoke capable.
Recovery: retry same spoke, same input. Cap at N, then escalate.
02 — Input Validation
Malformed or incomplete input. Most dangerous if misclassified as transient — retrying broken input fails expensively.
Recovery: do not retry. Go upstream to find the missing field.
03 — Semantic / Business Logic
Spoke ran fine but the content is the problem — off-brief, design-system-violating. Retry won't help.
Recovery: route upstream for new input. Often triggers HITL.
04 — Policy Violation
Crossed a safety/compliance/brand boundary. Pre-flight hooks should catch it first — a hook fires deterministically, a prompt may not.
Recovery: reframe, single retry, then escalate. Never loop.

Knowledge Layer

The right representation per stage.

A knowledge graph earns its curation cost only where relationships and traceability pay off. Elsewhere, retrieval or live access wins.

KnowledgeRepresentationWhy
Component libraryComponent graph (metadata: props, relationships, tokens, anti-patterns)Relationships and anti-patterns are what agents can't infer — a lightweight KG
Compliance rulesKnowledge graph (rule → component → check → SC → clause)Audit-grade, multi-hop reasoning for a regulated context
Design tokensDTCG JSON + intent descriptionsLoad-bearing primitives; reasoned about by intent
Guidelines / voiceRAG over MarkdownUnstructured semantic; a graph is overkill
Live Figma / codeMCP at runtime (Dev Mode MCP + Code Connect)Freshness; don't snapshot what changes hourly

Build to WCAG 2.2 AA; EN 301 549 / WCAG 2.1 AA is the legal floor. The version is a config parameter. EAA is enforceable since June 2025 and covers banking.
