# Digital Experience transformation — package index

*Built 2026-06-29 to seed a separate strategy project. Drawn from the UX-design (Smart Design System / Promenaut) work.*

---

## What this package is
A self-contained set of files to start, and make the case for, transforming a **Design Delivery** team into a **Digital Experience** team — using the Smart Design System as both the enabling tool and the proof. You can move this whole folder into your separate project.

## Two kinds of file (important)
- **Commit-safe context** — factual, use as-is.
- **Strategy drafts (for your review before committing)** — opinionated, kept separate on purpose in `strategy/`. React to them, edit them, make them yours.

## How to use it
1. **Read** `project-context-summary.md` (the Smart Design System in one page) and `strategy/01_transformation-thesis.md` (the core argument).
2. **Start the new project:** open a fresh chat/project, attach `kickoff-prompt.md` (and at least the context summary), and paste the prompt. That seeds the work with clean, full context.
3. **Work the strategy section by section** in that project, firming up the drafts.
4. **For leadership:** use the polished documents in `polished/`.

## The argument in three lines
1. AI has collapsed the cost of design *execution*; a team valued for producing artifacts by hand is losing its basis.
2. Value has moved to **judgment, criteria and governance** — so the team must move from *making artifacts* to *owning experience and the system that guarantees its quality*.
3. We can argue this from strength: the **Smart Design System** is a working instance of that exact model — the tool and the proof.

## A note on what's settled vs not
The context files are factual. The strategy files are a strong **v0.1** to react to — deliberately separate so nothing is "committed" until you've reviewed it. Soft spots I'd pressure-test are listed in `strategy/00_READ-FIRST_strategy-status.md`.
