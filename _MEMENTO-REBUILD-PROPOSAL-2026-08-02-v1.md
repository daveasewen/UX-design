# Memento — the fundamental fault, and a proposal

**2026-08-02 · #85 · PROBE + PLAN, no fixes made · every figure measured in-window**

---

## The fault, in one sentence

**Memento stores work as prose, and prose has no close operation.**

That is the whole thing. Everything you are frustrated by — the token counting, the accounting,
the hand-off, the tail-chasing — is a consequence of that one design decision, and none of it is
fixable by discipline, because you cannot close a paragraph.

---

## How it actually works today

The canonical list of open work is a **regular expression run over a Markdown blockquote**:

```python
DOFIRST_ITEM_RE = re.compile(r"^>\s*\*\*(\d+[a-z]?)\.\s*(.+)$")
```

It scrapes bold-numbered lines out of `GOOD-MORNING.md`, truncates each to 46 characters, and
renders them into the chain. That is the task system.

So an open item has: a number that is **its position in a document**, and a sentence. It has no
identity, no state, no age, no owner, no link to the decision that spawned it, and — the decisive
omission — **no stated condition under which it would be finished.**

An item with no close condition cannot be closed. It can only be *deleted*, and deletion is
correctly forbidden by your own rule ([[home-by-addition-then-cut]]) until a probe proves the fact
lives somewhere else. So items are **structurally immortal: cheap to create, expensive and
prohibited to remove.**

That is why *headroom* has survived ten sessions. Not neglect. There is no mechanism by which it
could ever end.

---

## The four consequences, in order

**1. The list only grows.** Immortal items accrete. 95 item-slots over 12 sessions, 84 distinct.

**2. So the record only grows.** The items live in the record, so the record inherits their
immortality. `GOOD-MORNING.md` is 107KB. The read chain was *cut* at #33 and has grown 47% since.

**3. So token counting becomes existential — and then becomes the work.** Once the record grows on
its own, every session must measure it, attribute its own growth in it, and roll parts of it out.
Those measurements are **written into the prose by hand**, in several files, historically in two
different units. Each written figure is a claim that can rot, so each needs a gate; each gate is
prose that can rot, so it needs a gate.

The result is measurable and it is the number I would put in front of everything else:

> **66.3% of the read chain — the payload every cold session pays for at boot — is arithmetic
> about its own size. 0.0% is about Apollo.**

**4. So the hand-off carries no work.** A new session inherits a full account of the bookkeeping
and nothing about the product. That is why the broad context feels lost. It isn't lost; **it was
never in the payload.**

## The proposal

One principle: **separate STATE from NARRATIVE, and never let a human or an agent hand-write
either the state or a number into the hand-off.**

Today `GOOD-MORNING.md` is simultaneously the state store, the narrative, and the hand-off. Those
three want opposite properties — state wants to be small and mutable, narrative wants to be
append-only and never re-read, the hand-off wants to be generated and bounded. Fusing them is why
every session pays for all three.

### The five parts

**1 · A real task store — `_state.json`.** Every open item becomes a record:

```
id            stable, never reused          W-041
title         one line
state         open | blocked | ruled | done | dropped
opened        session number
owner         dave | claude
closes_when   an explicit, checkable condition          ← the missing field
links         decision-graph node ids
```

**`closes_when` is the fix.** One gate enforces it: *you cannot open an item without stating what
would end it.* Items become mortal. `headroom`, entered eleven sessions ago, would have carried
*"closes when group 78 B is under its cap"* — and would have closed or been dropped by #77.

**2 · One decision store.** Extend `_decision-graph.json` with a `process` node type — same shape
it already has, it simply lacks the type — and fold `_rulings.json` into it. Backfill the nine
rulings. **This also discharges the six-edge-types item that has been open for eight sessions**,
because it becomes the same job.

**3 · The hand-off becomes 100% generated.** `_CHAIN.md` is rendered from `_state.json` + the
graph + a **five-line free-text note** from the last session. Nothing else. Today the chain is
generated *from hand-authored prose*, which is why generation bounds nothing. Generate it from
bounded data and it cannot grow — the bound moves onto the data, where it can be enforced.

**4 · No token figure is ever written into a Markdown file again.** One command prints the number.
The chain shows one generated line. **This deletes 66% of the read chain outright**, and with it
the entire practice of growth-attribution, unit-correction and roll arithmetic — because when the
record is generated from state, its size is a function of the state, and there is nothing left to
attribute.

**5 · Narrative goes append-only and is never re-read.** Dossiers and the ledger are written once,
retrieved on demand, never rolled, never priced. The 2c/2d/2f rolls retire entirely — they exist
only to stop hand-authored files growing, and there will be no hand-authored files.

### Cost, and what you get back

| | now | after |
|---|---|---|
| boot payload | ~13,000 real | ~2,000 real (generated, capped) |
| PM surface a session must handle | ~144,000 tokens | under 20,000 |
| session work that is bookkeeping | ~80% | the wrap becomes a state write |
| items that can close | none | all of them, by construction |

Build cost: **one session.** The state store and the generator are small — the hard thinking is
already done and sitting in `_capture_gate.py`. The 24,000 lines of gates are not touched; they
simply stop having anything to police, and get retired one at a time as they prove moot.
