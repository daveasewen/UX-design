Apollo's top-level product framing (Dave 2026-07-17, "I don't think I've expressed it this way before — a great framing"). Early articulation; labels provisional but the shape is the vision.

**Why "Apollo" — it's the MOONSHOT** (Dave 2026-07-17). Named after the Apollo programme: the name carries the moonshot ambition of the project. Renamed from Promenaut 2026-07-14 ([[apollo-rename-and-red-rule-2026-07-14]]).

**Tagline / subtitle: "lovable on rails"** — generative freedom (à la Lovable-style AI building) but bound to brand / accessibility / governance **rails**. The whole product in three words.

**Four phases — the final harness rolls all our features into these:**

1. **Apollo Discover** — ingest, research, analyse. (KB intake side; the [[chat-to-kb-bot]] likely lives here. Feeds on the ingestion work.)
2. **Apollo Create** — generation; foundations being built now. Four modes:
   1. **Strict mode** — the assembly line / **"Factory mode"** from the sponsor presentation.
   2. **Creative mode**.
   3. **Component Dev mode**.
   4. **Explore mode** — free noodling.
3. **Apollo Craft** — review, edit, craft. (The review doc + comment overlay is this phase — [[review-layer-product-feature]].)
4. **Apollo Dispatch** — hand a package over to engineering. May not be needed in the final version — hopefully integrated rather than a discrete handoff. (Ties to Sutherland build target / [[output-modes-portability]], [[code-binding-hub-spoke]].)

**The Create modes = TIERED LEVELS OF ADHERENCE** (Dave 2026-07-17, refinement). The four modes are
not four flavours — they are **tiers of how tightly generation is held to the rails** (a11y · standards ·
canon components · all KB guidance), with **guardrails progressively removed along the tiers**, and
**sub-settings within each tier** (finer dials — which gates on, how hard). So "lovable on rails" is a
**dial**, not a fixed track. Reading of the ramp: **Strict** = max adherence (all gates blocking, canon
components only, full guidance) → **Creative** = some rails relaxed (invent composition/expression) →
**Component Dev** = *different* rails not just fewer (canon-only off by design since you're extending the
library, but token/structure/a11y rules still bind) → **Explore** = most guardrails off, free noodling.
This is the [[fixed-flex-charter]] (fixed vs may-flex) and the [[register-inference-ramp]] (retrieve →
extend → invent) made into an explicit **per-mode governance control**.
**RESOLVED (Dave 2026-07-17): YES — a11y (WCAG 2.2 AA) is the single non-removable floor**, holding across
every Create mode including Explore; no tier dial can drop it (per the FOUNDATIONAL [[accessibility-aspiration]]).
Likely joined by a few **other locked foundations (e.g. colour palette)** — exact set TBD when we build it.
**Crucial nuance: "non-removable" = LOCKED, not HARDCODED.** The floor is locked against the tier/mode dials,
but an **ADMIN access layer can tune every setting, including the floor itself** — so the whole system stays
flexible/future-proof and nothing is truly hardcoded (consistent with the tokenised-everything, modes-govern
ruling). ⇒ NEW product concept: an **admin settings surface** exposing all guardrails/foundations as tunable,
above the per-mode tier dials. Relates to [[derivation-governance]] (promotion = Dave/admin only).
