Strategy decisions locked 2026-06-20 (framework comparison session). See `_STRATEGY-framework-comparison.md`.

- **Spine: spec/eval-first** (spec-kit / eval-driven dev). Criteria-as-executable-checks = the gates, moved upstream. Truest extension of "verification = enforcement". Spine governs the OBJECTIVE half (states, a11y, tokens, copy); the SUBJECTIVE half stays a human taste-call (LLM-as-judge is unreliable for aesthetics — filter/annotate, never pick).
- **Intake = adaptive maturity router**, not one fixed flow: seed idea → brainstorm; half-formed → guided JTBD/assumption mapping; well-specced → ingestion + short quiz. All lanes converge on the same criteria/spec contract. Several tools eventually; do NOT boil the ocean.
- **Prototype scope: build ONE lane = entry-level/guided JTBD.** Router + other lanes designed-but-deferred. Hard user constraint: teams are NON-EXPERT (some agile + six-sigma; POs DT-aware; designers tactical, short sprints) — tool must GUIDE, not assume skill.
- **Adopt spec-kit's "constitution" pattern** = root file of non-negotiable principles every phase references; ~1:1 with the gated canon.
- **Editor: do not build.** Generation/editing is commodity (v0, Google Stitch, Figma Make, Lovable). Moat is upstream discovery→criteria→enforcement loop. Wrap an existing canvas.
