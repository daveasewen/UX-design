**RULED 2026-07-03 (Dave, blue/400 render session):** the engine never derives a value AND
promotes it — promotion into tokens/canon is **human, never automatic/derived**. When something
fails our gates and is essentially **an error in the design system itself** (published
palette/standard gap), the default is: **log a recommendation in
`knowledge/_DS-IMPROVEMENTS.md` with supporting artifacts, and move on** — no token or component
change. Derived candidates recorded in the log are evidence, not canon.

**AMENDED 2026-07-05 (decision audit, Tier A batch 1 — Dave).** The *core* (human-only, never
auto-promoted) is vouched. The refined detail: promotion is **not a single-person say-so into
general canon** but a **staged, multi-human path**. Inference-born ideas that are worth
following up aren't promoted on Dave's word alone — they land in a **holding pen / sandbox** for
further work, are reviewed **with colleagues**, and can be promoted into an **"extension library"
(a separate-but-connected canon)** where emerging innovation matures, with the prospect of
promotion into the *general* canon only if it proves broadly useful. Not yet fully worked out —
OPEN thread: define the holding-pen / extension-library promotion process (connects to the
[[gap-pattern-build]] promote loop and ADR-0006 compounding-canon). *This amended text re-enters
as `unaudited` per the audit runbook and is re-audited later.*

**RE-AUDITED 2026-07-05 (Tier A batch 2 — Dave): core VOUCHED, staged-path DIRECTION vouched,
specific mechanism DEFERRED as a future feature.** The principle — promotion is multi-human and
staged, never a solo say-so — is sound and stands. The concrete machinery is named-not-built, so
its correctness-as-written can't be graded yet; **deferred** against the OPEN thread, not banked as
vouched (avoids blessing an unbuilt process). **Future-feature shape (Dave's forward vision,
capture-only — build once the goal is set):** *tiered access to canon commits* — roles
**design-system admin → domain admin → standard**. The **sandbox is open to everyone** (all can
work there); **commits are tiered**. **Extension libraries are readable by all**, but **edit
privileges are gated by domain + commit right**. Promotion into general canon still needs the
multi-human bar. Horizon feature, not a current rule — set the goal first, then the process falls
out of it.

**Why:** the engine's authority is enforcement and evidence, not design judgment; the design
system is HSBC's, and "fixing" it locally creates unpublished values — the exact illustration-
leak failure mode this project keeps catching ([[dark-rag-token-gaps]]).

**How to apply:** gate fail traced to the standard → prepare evidence (receipts, ladder,
blast radius, render artifact) → ds-NNN entry in `_DS-IMPROVEMENTS.md` → close the register
item to it → move on. First two entries: ds-001 (dark UI blue / blue/400 leak, col25-018)
and ds-002 (dark error text #DB0011 4.02:1 at rest). A logged entry's residual gate fails are
its "signature" (noted in the entry), not regressions. Fits [[fixed-flex-charter]] (curbs,
retrieval-not-recall) and [[procedural-debt-and-method]] (write the method down).
