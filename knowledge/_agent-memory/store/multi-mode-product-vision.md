**⚠️ HORIZON / DIRECTION — vision, not a build order (Dave, 2026-07-13, confirmed for capture).**
Hold provisionally; the near-term plan is unchanged (mine real projects → build tiers → then test modes).

**1. The KB as the design-system SOURCE OF TRUTH (north star).** A complete, well-crafted KB is not a
reference the engine queries — it's the **system-of-record**: docs, specs, all components, patterns,
principles, AND the **provenance of outputs** (outputs traced back to what they drew from → the library
learns from its own use; generalises the trace tool). Consequence: the **edges ARE the value** — this
is the same thread as Dave's earlier "missing edges" worry. **Discipline (non-negotiable):** grow it by
**accretion/compounding** — each component/pattern/output adds its nodes + edges as made — **NOT a
big-bang "ingest the whole corpus"** project (that is exactly the ingestion that got attempted and
abandoned, see [[ds-knowledge-graph-revisit]]).

**2. MULTIPLE MODES + a settings UI (direction).** The engine fulfils **multiple modes of creation**,
not one. Working set:
- **Strict / factory** — retrieve + assemble + compliance gates. Deliberately **boring = correct**;
  Dave does NOT want strict to be creative (the "flatness" is expected: thin reference, not a defect).
  Floor/churn.
- **Creative / inspiration** — inject inspiration / invent, then normalise onto canon. **This is where
  the two-pass / generate-then-normalise lives** — and its OUTPUT is **new canon (components/patterns),
  not shipped screens.** Ceiling/novel.
- **Component-development** — a focused creative mode whose job is to grow the KB (designer + machine
  invent a pattern → review → promote → canon). = "use the tool to build the tool," compounding loop.
- **Explore / noodle** — open divergent play (the §9a mode A).
All modes share the **compliance gates as the common floor** (the moat; a bank-grade differentiator no
commercial tool has). **Likely a settings UI with TWO faces:** an **admin** mode (tuning, tests, the
dials) and a **simple user** mode. Relates to [[harness-two-modes]], [[product-shape-flexing-engine]].

**3. The library build has TWO engines** (Dave: "much of designers' work is creating new patterns"):
(a) **external research** gap-fill from other libraries + (b) **in-project net-new patterns** created
in the creative mode. Both feed canon. See [[component-library-buildout-plan]].

**⏱️ OPERATIVE CONSTRAINT (2026-07-13): Dave must PRESENT progress that "doesn't disappoint."** Details
(audience/timing/format) being clarified — near-term priorities must yield **demonstrable, non-
disappointing progress**, floor-first. Key risk to manage: a design audience judging the *expected-boring
strict output* instead of the *system + vision*. (Presentation-specific plan to be captured once scoped.)

**"Simpler method" open question (Dave):** may succeed with **rich library + inference + gates as the
floor**, trimming the heavy §9 register machinery ("less infra" instinct) — but the **gates stay**.
Hold as the hypothesis to test once the library can support the modes.
