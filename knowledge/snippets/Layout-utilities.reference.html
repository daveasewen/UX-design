A stack owns the vertical rhythm and its children are told not to add to it. Every value on this row is a step of the spacing ramp in tokens/spacing.json — written literally, because that store is outside the snippet gate's resolver. The comment beside each step names its token path so a human can audit what a machine currently cannot.

Nothing here reconciles them — that is a ruling, and it is yours. The floor is a variable so a consumer sets it once, and the min() wrapper stops a wide floor overflowing a narrow container, which several of the hand-rolled copies do not do.

Twelve tracks, the count held in layout/web/columns; the column gap is layout/app/gutter. Below breakpoint/ms every span goes full width. That collapse is a viewport query rather than a container query, and the reason is honest rather than clever: an explicit column grid is a page-level frame, and a page-level frame answers to the page.

The same markup twice. The second one sits in a 420px frame and has already collapsed, on a screen that is nowhere near narrow. A viewport query cannot see that; a container query can. This is the case that decides which kind of query a primitive should use, and it is why the split uses one and the twelve-column grid does not.

Measure — the reading-width primitive

Sixty-four characters is the measure this primitive sets, and nothing else in the system owns that number. It appears by hand in several snippets as a max-width on a paragraph, which is the same class of duplication the grid recipe shows: a value that is really a decision, written out again each time it is needed. The number itself is not ruled and is not ruled here.

64ch is a specimen choice, not a ruled measure.
