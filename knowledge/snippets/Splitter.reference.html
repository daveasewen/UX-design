Horizontal split — a vertical divider

Two panes side by side. Drag the divider, or focus it and use the left and right arrows. The percentage below is the same number the divider publishes as aria-valuenow, so what a screen reader hears and what the page shows cannot drift apart. Neither pane may go below 160px; try to push past it and the divider simply stops.

Accounts

The primary pane. Its size is the value the separator publishes.

Because the pane scrolls independently, a splitter is only useful when both sides have something worth keeping on screen at once — a list and the thing it opens.

Detail

The secondary pane takes whatever is left. It has its own 160px fence, so the primary cannot swallow it either.

Published aria-valuenow: 50% Primary pane: —px

Vertical split — a horizontal divider

The same component with data-orientation="vertical". The keys change with the axis: up and down arrows instead of left and right. Everything else — the fences, the published value, the collapse toggle — is identical, because it is the same code.

⚠ Look at the published figure below this one: the markup asks for aria-valuenow="40" and the page reports 46%. That is not a bug and it is not rounding. 40% of a 360px box is 141px, which is below the 160px fence, so the fence wins on load and the separator REPUBLISHES the number that is actually true rather than leaving the authored one standing. A control that keeps announcing a value it is not at is worse than one that argues with its own markup.

Filters

The primary pane is the top one when the split is vertical.

Results

Enter on the divider collapses the primary pane to zero and restores it to the size it had. A collapsed pane keeps its separator, so there is always a way back.

Published aria-valuenow: 40% Primary pane: —px
