    4 · New on the desk — dark error red fails at rest

    Found while verifying the sweep’s Selection-controls catch: the reported “light hover 4.02:1” was the gate clicking each snippet’s own theme toggle mid-pass (pressed = a real click; the toggle is the first button in document order), so each pass measured the other theme. Fixed — demo chrome is no longer driven, theme re-asserted per element; the 38-snippet re-sweep now shows the true picture: light is clean (#A8000B on white = 7.87), but in dark, error text #DB0011 on #000000 = 4.02:1 at rest — label and message, every snippet that shows dark error text. As a graphic (border, mark) 4.02 ≥ 3:1 is fine — only text needs to move. No published red sits above #DB0011, so this is the same charter-§6 derivation call as the blue (ladder at hue 355° / sat 100%):
