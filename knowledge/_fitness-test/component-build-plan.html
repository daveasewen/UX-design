Component library · build plan

An extensive component build

From ~38 gated components today to a comprehensive catalogue of 200–300 — sequenced so the reliable "standard" output comes first, and creativity becomes a mode, not a workaround.

The case

Coverage removes the reason to invent — and more parts mean more valid journeys.

Today, when a screen needs a part we don't have, the engine invents one — a run we tested fabricated account numbers and status chips just to fill a table it needed. That is the source of drift and of "needs a tidy". A comprehensive library is what makes standard-quality output the default, because there is always a real component to retrieve.

It also buys variance for free: more legitimate components mean more valid ways to compose a journey, so the same brief yields genuinely different, on-brand results. Creativity then lives in a separate ideation mode — tuned, not improvised.

Two modes

The library does the grunt work; ideation is a dial on top.

Standard

Retrieve the right part for almost any screen; output reads as house-standard by default. The bulk of the work — reliable, fast, on-brand.

Ideation

The register dial — expressive surfaces, motion, gap-pattern generation — tuned for workshops. Creativity on top of a solid base, never a substitute for one.

Because the base is comprehensive, both modes get the variance dividend: more valid compositions on the same curbs, so journeys vary legitimately rather than by invention.
