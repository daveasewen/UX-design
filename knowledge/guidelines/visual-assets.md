## Scope note — the queue mis-tiered this one

Item 12 was queued as "lower component relevance". The `visual-assets.html` page is
the opposite: it is a **UX application standard** — journey-tier imagery budgets,
pattern-consistency rules for empty states and confirmations, icon semantic-fit, and
placement/ratio taxonomies. It is the imagery-side twin of the neurodiversity calm
ceiling. The other six pages are mostly marketing/channel standards (recorded) with
a handful of receipts the engine wants: the no-genAI rule turns out to be
vintage-stable, the masthead logo has a behaviour contract, and icon/avatar rounding
is officially a code mask on a square asset.

## Visual-asset application (engine-relevant)

- **Inclusion test before any asset**: what's the intent? does it help understanding?
  does it distract, obscure or slow the user? No contextually-irrelevant images "for
  the sake of layout or design" — "sometimes less is more". [TASTE at generation —
  composition-level; imagery-side kin of the neuro-042 calm ceiling] {#va25-001}
- **Attribute taxonomy — every asset is functional (icons, avatars, logos),
  informational (product photos, infographics, diagrams, charts) or complementary
  (photography, illustration)** — defined by content nature, not media type. The
  placement rules below key off this. [ADVISORY — classification the checks consume]
  {#va25-002}
- **Visual-engagement tiers set the imagery budget per page type**: HIGH (home, hub,
  landing, promotion) = complementary allowed throughout · MEDIUM (product, service,
  article) = complementary minimal — header or start-of-section only; informational/
  functional carry the weight · LOW (applications, processes) = ONLY assets
  fundamental to the task; complementary at most at the very start or completion.
  ENGINE-CRITICAL: a page-type parameter that caps complementary imagery — the sober
  register's imagery numbers by another route. [ADVISORY-derivable — asset-budget
  check keyed on page-type contract] {#va25-003}
- **Onboarding: new-to-HSBC users may get more complementary assets (if they enhance,
  never distract); existing customers get focused informational/functional for new
  features.** [TASTE — contract parameter] {#va25-004}
- **Pattern consistency across the journey: same asset type for the same pattern
  everywhere** (an illustration on one confirmation page = illustrations on ALL
  confirmation-class pages); logged-on and logged-off experiences consistent. Named
  surfaces where this is critical: applications · onboarding · coach marks ·
  tutorials · alerts messaging · status codes (eg 404) · **empty states**.
  ENGINE-CRITICAL → confirmation/success gap-pattern + any empty-state pattern get
  an asset-type contract. [ADVISORY-derivable — cross-screen asset-type consistency
  check at journey level] {#va25-005}
- **Hierarchy: assets supporting the primary goal outrank secondary-goal assets;
  avoid conflicts of attention** (order, scale, space, contrast, balance).
  [TASTE — heuristics-judge class] {#va25-006}
- **Re-use rules: an asset re-appears only in the same context/metaphor/purpose.**
  Never the same thumbnail linking to different content; never the same hero for
  different articles/products; **never an icon outside its functional context**
  (source example: a memo icon representing fraud content). ENGINE-CRITICAL: the
  icon SEMANTIC-fit layer on top of the icon-source gate — provenance says which
  icons exist, this says an icon must mean what it shows. [ADVISORY-derivable —
  same-asset-different-target check is exact; semantic fit is judge-class]
  {#va25-007}
- **Type taxonomy** (animation · photography · illustration · infographics · charts ·
  diagrams · avatars · icons · favicons · third-party logos), each pointing to its
  own standard; favicon guidelines exist as a separate page. [RECORDED — taxonomy +
  pointers] {#va25-008}
- **Responsive behaviour: test assets across devices; photography adapts by ratio
  crops; illustrations may need reformatting AND line-weight adjustment per layout/
  size.** Brand-source receipt for the dynamic-weight concept — the brand itself
  says line weight is context-dependent. [ADVISORY — receipt; note for the
  dynamic-weight icon set] {#va25-009}
- **Light/dark modes: assets may need per-mode exports; icons black-in-light get
  value-reversed in dark (can be code-level).** Receipt for the icon-contrast-delta
  work and mode-aware asset handling. [ADVISORY — receipt; already practiced]
  {#va25-010}
- **Quality bar: sharp, high-quality, tested on low- and high-DPI — or NO asset at
  all** ("better not to use any visual assets" than bad ones). [TASTE with an
  advisory edge — resolution floor is checkable at render] {#va25-011}
- **Placement taxonomy: hero · display · spot · thumbnail · interface**, with
  attribute legality per placement (hero = complementary/informational · interface =
  NEVER complementary · thumbnail = any) + the placements-by-type matrix (verbatim
  in `_sources`: video/animation top out at spot; photography/illustration reach
  thumbnail; avatars/icons/logos live spot→interface; favicons interface-only).
  [ADVISORY-derivable — placement-type legality lookup] {#va25-012}
- **Aspect ratios: video/animation 16:9 standard (21:9, 4:3, 1:1 alternates);
  photography/illustration/infographics 21:9, 16:9, 4:3, 1:1 (reversible for
  portrait); icons/avatars 1:1 square — "icons and avatars that appear rounded are
  likely to have masked the square asset using code"; third-party logos 16:9/4:3.**
  The rounding-is-a-code-mask line is the official mechanics behind the Badge+Avatar
  round exemption: the ASSET stays square, the mask rounds. [ADVISORY-derivable —
  fixture ratio check; ratio vocabulary for generated media slots] {#va25-013}

## Photography (2025)

- **No Generative AI, mixed media or CGI-rendered elements in imagery — ALSO the
  2025 rule.** photo26-002 is therefore vintage-STABLE, not a refresh novelty: the
  ban has held across both standards. Second receipt for the pipeline-critical rule
  (engine generates experiences, never photographic assets; library retrieval only).
  [ADVISORY — second-source receipt for photo26-002] {#va25-018}
- **D&I imagery rules: diverse representation across markets; no stereotypes or
  clichés; represent LGBTQ+ people; portray people with disabilities living their
  lives — never make the perceived difference the focus; localisation sensitivity
  per market.** Imagery-side kin of tov-025's fixture diversity. [ADVISORY —
  judge-class; governs fixture-image selection if the engine ever picks photos]
  {#va25-019}
- **Creative considerations (explicitly optional): natural hints of red; hexagon-
  geometry angles, never a forced 45°; wide 'opening up' frames + intimate close
  crops.** [TASTE — register material for expressive imagery] {#va25-020}
- **Sourcing governance: Global Image Library FIRST → contracted partners (EyeEm,
  Getty; +Shutterstock/Offset for video) → NEVER free or Creative-Commons libraries
  (licensing/reputation risk); purchased assets are uploaded back to the shared
  library; hero exclusivity via metadata with an end date.** [RECORDED + PROCESS —
  asset governance; the retrieval-not-synthesis pipeline's supply side] {#va25-021}
- **Photography textures always use the red/white/grey palette.** [ADVISORY —

  Univers Next for HSBC"); Photography references the "four new photography themes".
  The supercharge rollout is editing the old pages in place — vintage labels on

  the 2026 pages don't restate (va25-014/015/017).

  standards ban generative AI/CGI/mixed-media imagery outright. For the
  transformation strand: this is not a transient policy, it's held across a rebrand.
- **F3 — visual-assets.html is the imagery calm-ceiling.** va25-003's engagement
  tiers give generation a page-type imagery budget: applications/processes get NO
  complementary imagery except start/completion. Direct input to the fixed/flex
  page-type contract; pairs with neuro-042.
- **F4 — Component contracts harvested**: masthead logo behaviour (va25-015 →

  gap-patterns), icon semantic-fit (va25-007 → icon gate's semantic layer),
