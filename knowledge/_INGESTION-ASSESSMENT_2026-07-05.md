## TL;DR (read this, the rest is evidence)

**There is not one ingestion — there are three, in very different states, and no graph links them.**

1. **create.hsbc guidelines** — *healthy and resumable.* 462 indexed rules, good provenance
   discipline. Tier 1 complete, Tier 2 mostly done. Remaining: a defined Tier-2 queue, Tier 3
   on-demand, and 21 legacy files needing upgrade.
2. **Component metas + compliance KG** — *consistent but narrow.* 38 metas = 38 in the compliance
   graph, but that graph models **only WCAG** (31 rules ↔ 31 success-criteria ↔ 38 components). It is
   the **only cross-entity graph in the repo.**
3. **Tokens (Common Toolkit → DTCG store)** — *half-migrated, and mis-tracked.* The Sutherland
   export **has arrived** (2026-06-17) but the gaps manifest still says it's "parked, blocked on an
   export that doesn't exist." 147 deprecated tokens still awaiting retirement; P1–P5 gaps open.

**Why the process was wrong:** completeness was measured as *pages/components processed*, never as
*entities linked*. Cross-references are hand-written prose notes (`[REVIEW]`, `F1`), not graph edges.
So even the "done" strands never built the interlink — they deferred it to human cross-reading. Plus
the tracking is **stale** (the Sutherland block above), which is how a resumed workstream still reads
as "blocked."

**The fix is two problems, not one:** (a) *finish the capture* (guidelines tail + the now-unblocked
token migration); (b) *build the overlay/index graph* that links guideline-rule ↔ token ↔ component
↔ snippet ↔ success-criterion (the ADR-0003 "done right"). Do not conflate them again.

## 2. Why the process was wrong (structural, not incidental)

1. **Three siloed stores, one narrow graph.** Guidelines rules-index, component metas/compliance KG,
   and the token store are separate, each with its own generator. The only graph (compliance) covers
   WCAG↔component. Nothing joins *guideline-rule → token it constrains → component that binds it →
   canon snippet that renders it*. Example that should be one edge-path but is four prose notes: the
   `col25-018` blue/400 leak → the `blue/*` token → the components binding it → the snippet.
2. **Completeness was the wrong metric.** It was counted as "pages/components processed," never as
   "entities linked." A tier can read "✅ complete" while the interlink — the actual value — was
   never built; it was deferred to human cross-reading via `[REVIEW]`/`F1` prose.
3. **Token capture was fragile.** `get_variable_defs`/`get_metadata` repeatedly failed on the Figma
   branch (API reads the desktop selection, not the URL node; `net::ERR_HTTP2_PROTOCOL_ERROR`);
   many values came via OCR/screenshots; doc-vs-variable conflicts were logged, not resolved. The
   Sutherland native export is the intended fix (supersedes OCR) — and it has arrived.
4. **Tracking rots silently.** The Sutherland block is the proof: state changed (export arrived
   2026-06-17) but the manifest still says "blocked." Nothing forces a tracking doc to update when
   the world changes — which is exactly the gap the state machine (§5) must close.

## 5. Target state + phased resumable worklist

**"Done right" (the target):** every ingested entity — guideline rule, token, component, snippet,
success-criterion — addressable in **one interlinked graph** (or an **overlay/index layer** across
the existing specialised stores; overlay is the leading hypothesis, extends `_blast-radius.json` /
`compliance/graph-index.json`), with **completeness measured as coverage of edges**, not pages. The
token store is Sutherland-canonical with the depricate set retired.

Phased, each phase independently shippable:

- **Phase 0 — reconcile the tracking (cheap, do first).** Fix the stale "parked on Sutherland"
  block in `_DESIGN-SYSTEM-GAPS.md`; make this assessment the single ingestion-state entry point.
- **Phase 1 — execute the Sutherland token migration (now unblocked).** Import modes → rebind the
  147 depricates by context (`depricate-replacement-map.json`) → re-verify zero references → delete;
  close P1 (subtle-surface family) + P4 (`rag/neutral-tint`); fix P3 (Tabs dark-mode binding);
  resolve the doc-vs-variable `$review` conflicts. Tabs is a good first rebind.
- **Phase 2 — finish guidelines capture.** Tier-2 queue + Common Toolkit tranche 2+ + 21 legacy
  upgrades; Tier 3 on-demand only.
- **Phase 3 — build the overlay/index graph (the ADR-0003 "done right").** Model the entity/edge set
  across the full corpus; decide keep-hybrid vs overlay vs unify (overlay leading); wire
  guideline-rule ↔ token ↔ component ↔ snippet ↔ SC. This is a separate, audit-grade thread with its
  own method (memory `ds-knowledge-graph-revisit`).
- **Phase 4 — wire ingestion coverage into the state machine (§6)** as a tracked state with a
  target, so "resumed but incomplete" can never again hide as "blocked."

## 6. How this feeds the state machine (Dave's ruling, 2026-07-05)

The state machine (`_LIVE-STATE.md`, ADR-0007) currently records **current truth + change history**
(LIVE / DEAD / OPEN). **Ruling: it must also record *future / target* states for planning** — where
we intend to be, not only where we are and what changed. This is a first-class extension to
ADR-0007's temporal model (a target node is a future validity interval / intended state).

- Implemented as a new **`## PLANNED / TARGET STATES`** section in `_LIVE-STATE.md` (each target =
  what · why · blockers · source doc). The ingestion target (§5) is the first entry.
- When `_build_live_state.py` (the PM-KG MVP) is built, it should **emit target states too**, and the
  staleness gate should flag a target whose blockers have cleared but whose status still reads
  "blocked" (exactly the Sutherland failure). Reports coverage-toward-target; never self-promotes.
- This ruling itself is a **decision node** — seeds as `unaudited`, to be correctness-audited later
  (it extends ADR-0007, which was vouched).
