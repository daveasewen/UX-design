Priority — a PROPOSAL, not a ruling

My proposed order, and the weights it came from

You ruled that I generate the priorities and you overrule them. This is the generated half. It is computed at build time from the store, never written back into it, so it cannot rot and it cannot quietly become a decision. Six criteria, each scored 0–1, combined with the declared weights below into a score out of 100. The weights themselves are a proposal too — change any number in the table and the order changes; nothing about them is ratified.

CriterionWeightWhat it measuresWhere the input comes from
Unlock0.30how much other work this item is blockingthe item's links array, plus inbound links from other items
Rot risk0.20cost of delay — how long it has been open, and whether it can even be closedopened (session number) and condition
Effort (inverse)0.15a small job scores higher than a big one, all else equalthe item's OPTIONAL effort (S/M/L) where present — otherwise PROXY ONLY: the length of the item's body.
Deadline0.15proximity to the Friday 2026-08-14 setthe item's OPTIONAL deadline (ISO date) where present — otherwise PROXY ONLY: a prose scan of title/body/closes_when.
Risk reduction0.10does closing this close a gate-coverage holePROXY ONLY — prose signal (gate / selftest / ratchet / coverage)
Decision relief0.10does finishing this take a decision OFF Dave's plateowner plus a prose scan for a pending decision
TOTAL1.00Score = 100 × Σ(weight × criterion). Deadline set: Friday 2026-08-14.

Some inputs are proxies, and the table says which. opened, condition and owner are real fields. effort and deadline are OPTIONAL real fields that replace their proxy when present — today they are present on 0 and 0 of 37 items respectively, so the proxy is what runs everywhere else. links is empty on 37 of 37 items. Where an input was missing, the score carries a LOW-CONFIDENCE flag naming it. A clean-looking number from thin data is the one thing this page must never print.

How much this ranking actually separates the work: not much, and here is the number. That is what a ranking looks like when its heaviest criterion has no data: the order below is a tie-break, not a verdict. It gets sharper the moment links exists.

What the missing-input words in the last column mean. unlock — no item in the store carries any links, so the dependency graph cannot be read. age — opened is 0 — the item's birth session is unknown, so cost-of-delay cannot be measured. effort — the item has no `effort` field — the score reads the byte-length of its body as a PROXY, which measures the prose, not the work. deadline — the item has no `deadline` field — the score reads a prose scan of the item's own words as a PROXY, so an item scores higher by SAYING 'friday'.
