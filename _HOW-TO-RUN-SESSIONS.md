# How to run sessions — the short version

Two ways to work. Pick one. When in doubt, pick the first.

## 1 · One at a time (the default)
1. Open a chat → say **"read good morning."**
2. Do the work.
3. It writes **GOOD-MORNING.md** at the end for next time.

That's the whole loop. No receipts, no conductor, nothing else to hold in your head.

## 2 · Several at once (only if you want them running in parallel)
1. Open each chat → say **"read good morning."**
2. It asks each one: **Worker · Conductor · Solo.**
3. Make **ONE** the **Conductor** — it writes GOOD-MORNING and commits for everyone.
4. The rest are **Workers** — they just do work and drop a note in `notes/_receipts/`.
5. You hit **Push** in GitHub Desktop at the end.

## The one rule under both
**GOOD-MORNING has exactly one author per round.** Solo writes its own; the Conductor writes it for the
whole group. That's the thing that stops sessions clashing — everything else is enforced automatically by
where files go and how they're named.
