Proposal for ruling

What the knowledge graph is missing

Three research lanes scoured everything collected under knowledge/ and compared it with what the graph actually holds; a fourth lane tried to break their numbers. Every count below was re-measured by the verifier; where a lane was wrong, the corrected figure is shown. Your words that set the brief: "the assets aren't represented either, no font, no icons, no photography, what else might we be missing that is important for the super-designer we are making?"

Verdict

The graph holds the components and their governance, and almost nothing the components are made of. Tokens, icons, fonts, logos, photography, the 470 tagged create.hsbc rules, the 145 graded UX principles and the 12 roles are all collected, mostly structured, and all at zero in the graph. The four "principle" and twelve "guideline" nodes that exist are WCAG groupings — not ours.

Recommendation: land the families whose node payload already exists and already has a ruling, in this order — roles, tagged rules, principles, icons, logos — before any new entity kind is invented. Tokens go in as files or tiers first, never 932 leaves. Photography and fonts each wait on one decision of yours.

01What the graph holds today

Base graph: 890 nodes — 380 patterns, 222 contexts, 137 components, 137 snippets, 14 rulings — joined by 1,267 edges of 16 types. The big four are commonPattern (421), usedInContext (367), renderedBy (137) and containedBy (88).

Two extra families ride on top: governance (733 evidence, 553 artefacts, 439 rulings, 92 sessions; 3,605 edges) and guidelines — which is WCAG only: 64 axe rules, 38 success criteria, 12 WCAG guideline groups, 4 WCAG principles.

Two premises corrected by measurement. The consumes edge is component→component, not component→token: there are no token nodes of any kind. And knowledge/guidelines/*.md and brain/principles.json contribute zero nodes — the guideline and principle names in the graph are WCAG's, which also means the prefixes guideline: and principle: are already taken.

04What mature systems carry that we don't

Thirty-one external sources, thirteen fetched in full (DTCG, Figma modes and Code Connect, Supernova, zeroheight, Knapsack, Storybook, GOV.UK, Carbon, Atlassian, USWDS, Polaris); the rest are snippet-level and marked so. Eight entity kinds a super-designer needs that we do not have, ranked:

  1. Content standard as a typed node — tone dimensions, reading level, error-copy rule, with an edge to a component. Polaris, Carbon, Atlassian and GOV.UK all carry content as a first-class track; ours is prose, so no gate can test a sentence.
  2. End-user persona / job-to-be-done, distinct from our slot roles. GOV.UK organises its whole pattern library by user task. Nothing of the kind exists here; it would be created, not mapped — and the caution is real: persona sets are the classic ontology that rots, so bind each to an evidence node.
  3. Mode axis (theme / density / contrast / locale / size) with defaults and inheritance — Figma's variable modes. We fan out four themes plus light/dark as parallel token sets.
  4. Lifecycle status and owner per node — zeroheight, Carbon, GOV.UK. One field; it tells the agent what it may reach for.
  5. Evidence chain for the user side — finding → evidence → recommendation, and per-component accessibility test results as nodes (USWDS publishes them). Our chain covers our decisions, not the user.
  6. Prop- and variant-level code binding — Figma Code Connect's granularity. We bind at component level.
  7. Locale / script / direction with font fallback — Spectrum, Fluent. Our six font script families are exactly this capability, invisible.
  8. WCAG technique / failure layer under the success criterion — the negative knowledge the agent needs most. Ours is flat against the SC.

Two cautions from the sources themselves. DTCG says tools should not infer meaning from token groups — a folder path must not become a semantic edge. And six of these domains (research, WCAG, axe, content, tone, rights) share one shape: a claim with a typed link to what justifies it. Build one evidence shape, not six.

Recommended order

Ready-made and already ruled first; new entity kinds last.

  1. Roles + the DESK address fields — providesRole, answersIntent, hasDataShape, yieldsTo. Closed stores, live resolvers, your ruling on record. A day's lane.
  2. The 470 tagged rules as rule: nodes, with citesGuidelineRule from the 38 metas that cite them and the 131 advisory-signal edges riding free.
  3. The 145 principles + 22 polarity edges — under a new prefix, because principle: is WCAG's.
  4. Icons then logos — manifests exist; usesIcon (19), the active pair edge, fillMode→token, and s230-D2's logo→theme default.
  5. setIn, behaviourFrom, capturedFrom, acceptsCapability — component-side edges to targets that exist today.
  6. Tokens as files or tiers, then bindsToken; leaves only if the layout pass survives a measured trial.
  7. Photography and fonts — each after its decision below.
  8. New entity kinds from 04 — content standard first, then lifecycle status, then persona bound to evidence.
Today
A component graph with governance on top. The agent can find a component and its ruling; it cannot find the token, icon, font, rule, principle or role the component is made of or judged by.
Proposed
The same graph with its atoms and its house rules as nodes, joined by edges that answer a designer's questions: what is this set in, which rule binds it, which icon does it use, which sibling beats it, and what breaks if I change this.

"Evidence grade is a field on every principle node." — s237-D1. The word node was yours a fortnight ago; the node does not exist yet.

Yours — six decisions, one word each

  1. Go on 1–5 of the recommended order? All are ready-made payloads to existing or ruled targets; nothing new is invented. I'd say yes.
  2. Prefix for our UX principles — ux: is my pick, since principle: is WCAG's.
  3. Tokens: file, tier, or leaf? Tier (semantic vs primitive) is my pick — it answers the blast-radius question without 932 nodes.
  4. Photography node identity — the manifest row, with original and derivative as attributes, which is the shape the note itself favours.
  5. Should component metas cite principles? Zero do today; this is authored work, not derived. I'd start with the six A-grade laws only.
  6. Which of the new entity kinds enter scope now — content standard and lifecycle status are cheap and unrisky; persona is the one that rots.
