00
The short version

Anthropic now offers server-side compaction: when a conversation nears a token threshold, the API automatically writes a summary and drops everything before it. It is, in effect, an automated version of our wrap ritual — except the summary is unverified, the ritual is skipped, and the loss is silent. Our whole token-management strategy exists because a confident false inscription is the failure mode. So the recommendation is: adopt compaction as vocabulary and as a parachute, never as a substitute for the wrap. Three concrete wiring points are proposed below; none is built.

Your next action: read the five questions in section 06 and rule, defer, or park each. Everything else in this document is receipt.

01
What compaction is

The API summarises the past and throws it away

Server-side compaction (beta compact-2026-01-12) watches input tokens. When they cross a configured trigger, the API has the model write a summary of the conversation so far, wraps it in a compaction block, and continues. On every later request, everything before that block is dropped — the summary is the past from then on.

Adjacent machinery, same family: context editing clears old tool results and thinking blocks selectively rather than summarising (finer-grained, no narrative loss); the memory tool lets the model write facts to files before they are cleared — which is architecturally what Memento already does by hand. Anthropic's own engineering guidance for long-running agents recommends exactly our pattern: compaction plus git checkpoints plus progress files, tuned first for recall, because "overly aggressive compaction can result in the loss of subtle but critical context."

02
Where it touches us

We already run a compaction protocol — by hand, with receipts

Map the vocabulary and the overlap is almost total. Their trigger is our amber line. Their summary is our wrap. Their compaction block is our read chain. Their instructions parameter is our capture ritual. The difference is not mechanism — it is trust.

API conceptMemento equivalentThe gap

A compaction block is a Polaroid that the system is instructed to treat as a tattoo. Memento's entire design premise is that this substitution is the failure mode — the risk is never forgetting, it is confidently remembering something false.

Verdict

Adopt the vocabulary. Refuse the substitution.

Compaction is real, well-designed, and solves the problem our stop line exists for — for systems that have no inscription discipline. We have one. So the question is not "compaction or wrap" but "what does compaction do underneath the wrap."

Compaction alone

Automatic, cheap to operate, no ritual. One lossy summary, written by the model mid-task, never verified against the repo. No registers, no do-not-rule fence, no subject read-back. A silent gap — and a declared gap passes while a silent one fails.

Wrap + compaction as parachute

The wrap stays mandatory and stays first. Compaction becomes the declared emergency floor beneath it: if a session ever blows past the stop line un-wrapped, the harness's compaction fires rather than the window dying mid-thought. The parachute is priced, named at check-in, and its summary is treated as UNPROVEN until reconciled against the repo.

04
Wiring options

Three wiring points, smallest first

  • W1 — Vocabulary & runbook (words only, ~zero build). Add a compaction section to _RUNBOOK-context-gauge.md: define the harness's compaction as the layer below the stop line, state that a fired compaction is a declared event to surface at the next check-in, and state the rule that a compaction summary is UNPROVEN inscription — never trusted, always reconciled against _CHAIN.md and git. This is the "read the runbook, not the hook" home for the whole topic.
  • W2 — Gauge compatibility (small, priced build). Teach _gauge_tokens.py / _checkin.py to read usage.iterations when present, so a compaction pass can never silently corrupt FILL. This is the same class of defect as FILL-vs-THROUGHPUT (#59→#90): a new usage shape that an old gauge mis-sums. Cheap to gate now, expensive to re-discover later.
  • W3 — Sub-agent compaction with Memento instructions (larger, only if a need appears). For long-running subs, enable compaction with custom instructions drafted from the capture ritual: preserve rulings verbatim, preserve the DO-NOT-RULE list, mark everything else as summary. Note the doc's own warning — with tools defined, the summariser sometimes calls a tool instead of summarising and returns a null block, so the instructions must forbid tool calls. This option is speculative until a sub actually exceeds a window mid-task, which the divvy-plan discipline currently prevents.

Recommended sequence: W1 now (it is a paragraph), W2 when the gauge is next open for edits, W3 parked until observed need. No new instrument in the same breath as the finding — W2 and W3 each get their own priced brief if ruled.

05
Consequences, replayed

What goes wrong if this is done carelessly

The summary supplants the wrap

If compaction is allowed to stand in for the wrap even once, the session it "saved" has no inscribed record — the next session inherits a model-written Polaroid as its only past. Wrap is not optional (#86), and no automation changes that.

The gauge mis-reads the new usage shape

With compaction enabled, top-level input_tokens excludes the compaction pass. A gauge that sums the old way under-reports real spend and over-reports room to the stop line — the exact FILL/THROUGHPUT confusion class, in a new coat.

Registers flatten

A default summary has no concept of floated vs standing vs canon. A ruling and a passing thought compress to the same sentence weight. Anything that survives a compaction must be re-graded before it is trusted — conclusions are debt, and a compacted conclusion is debt with the receipt burned.

Quota bleed

The summarisation pass runs on the same model as the conversation — no cheap-model option server-side. On a Fable or Opus lane, every compaction is a full-model generation charged against the weekly quota. Which budget binds must be named before enabling it anywhere.

Cache invalidation cost

Each compaction rewrites the cache. Without a separate cache breakpoint on the system prompt, the whole prefix re-caches every time — a recurring, invisible tax. The docs' own mitigation (breakpoint at end of system prompt) must travel with any adoption.

The premise may not even be ours to control

This session runs inside Cowork's harness; whether and how it compacts is not configured from inside a conversation. W1's runbook text must state plainly which layers we control (subs we launch, API builds) and which we merely observe — an instruction that cannot be enacted where it is written is the #173 class of gate.
